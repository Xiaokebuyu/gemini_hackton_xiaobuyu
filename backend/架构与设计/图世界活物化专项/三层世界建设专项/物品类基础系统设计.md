## 一、系统总览

物品系统是一组**独立但协作的子系统链**，构成游戏经济和角色装配的底层基础设施。

### 生产者 / 消费者链

```
┌──────────────────────────────────────────────────────────────────┐
│ 上层消费方                                                        │
│   商店系统 · 战斗掉落 · 任务奖励 · GM 工具 · 制作系统(未来)          │
├──────────────────────────────────────────────────────────────────┤
│ D. 物品效果引擎     使用消耗品 → 状态变化（HP/状态/增益）            │
│      ↑ 消费 B（移除已用物品）                                      │
├──────────────────────────────────────────────────────────────────┤
│ C. 装备系统         穿戴/卸下 → 属性重算（AC/攻击/伤害）            │
│      ↑↓ 与 B 双向（装备从背包取出，卸下放回背包）                    │
├──────────────────────────────────────────────────────────────────┤
│ B. 背包系统         持有层 — 增删查改玩家持有的物品                   │
│      ↑ 消费 A（物品定义 + 堆叠规则）                                │
├──────────────────────────────────────────────────────────────────┤
│ A. 物品注册表       定义层 — 世界中存在哪些物品，只读                 │
│      数据源: items.json（Schema 对齐 BG3/D&D 5e）                  │
└──────────────────────────────────────────────────────────────────┘
```

### 三层架构对齐

| 子系统 | 底层引擎（纯机械） | 中层（SessionRuntime） | 顶层（REST API / 工具） |
|--------|-------------------|----------------------|----------------------|
| A. 物品注册表 | ItemRegistry | — | GET .../items/* |
| B. 背包 | PlayerCharacter.inventory | session.add_item/remove_item | GET/POST .../inventory/* |
| C. 装备 | operations.equip/unequip + AC 重算 | session.equip/unequip | GET/POST .../equipment/* |
| D. 物品效果 | ItemEffectEngine | session.use_item | POST .../inventory/use |

## 二、子系统概要与现状

### A. 物品注册表 (ItemRegistry)

**职责**：世界物品定义的只读数据源

**位置**：`app/world/player/item_registry.py`（81 行）

**数据格式**：→ [物品数据 Schema 规格](物品数据Schema规格.md)（BG3 / D&D 5e 对齐）

**现状**（2026-02-25）：
- get_item / list_items / search_items ✅
- 路径 bug（`structured/` → 应为 `structured_new/`）❌
- 缺 subtype 过滤、parse_price ❌
- 物品数据需按新 Schema 重构（旧 ac_bonus → 新 base_ac 等）

### B. 背包系统 (Inventory)

**职责**：管理玩家持有的物品

**现状**（2026-02-25）：
- 底层 add_item/remove_item/has_item ✅（PlayerCharacter + PlayerNodeView）
- 中层 StatOps 包装 ✅
- 顶层 MCP 工具 ✅，REST API ❌，drop_item ❌

### C. 装备系统 (Equipment)

**职责**：管理装备槽位，装备变更触发属性重算

**装备槽位**：→ [Schema 规格 §三](物品数据Schema规格.md#三装备槽位13-槽)（13 槽，BG3 对齐）

**现状**（2026-02-25）：
- 底层 equip/unequip/recalculate_ac ✅（operations.py）
- 中层 StatOps ❌，顶层 REST API ❌，Immersive tools ❌
- AC 重算需适配新 Schema（base_ac + max_dex_bonus 模型）

### D. 物品效果引擎 (Item Effects)

**职责**：执行消耗品使用的效果

**效果系统**：→ [Schema 规格 §八](物品数据Schema规格.md#八special_effects-系统)（完全机械化，13 种 effect_type）

**现状**（2026-02-25）：
- 仅 2 个硬编码效果（healing_potion, greater_healing_potion）
- 效果定义需迁移到 Schema 的 special_effects 结构

### E. 金币系统

**现状**（2026-02-25）：
- 底层 add_gold/remove_gold ✅
- 中层 StatOps.remove_gold ❌，顶层 Immersive tools ❌

## 六、实施路线

### 原则

- 按**单个子系统纵向打通**（底层→中层→顶层），每步可独立验证
- 新 Schema 引入后，AC 重算、效果执行等底层引擎需适配
- 物品数据迁移通过提取管线（worldbook_graphizer）统一完成

### 总览

```
Step 0: 物品数据迁移（items.json 旧格式 → BG3 Schema）
    ↓
Step 1: 子系统 A — 物品注册表适配新 Schema
    ↓
Step 2: 金币补全（StatOps.remove_gold + Immersive tools）
    ↓
Step 3: 子系统 B — 背包打通（REST API + drop_item）
    ↓
Step 4: 子系统 C — 装备打通（AC 重算适配 base_ac + 中层 + 顶层）
    ↓
Step 5: 子系统 D — 物品效果（读 special_effects + use_item 全链路）
    ↓ 基础层完成
Step 6: 桥接 E — 状态系统（conditions CRUD）
Step 7: 桥接 F — 战斗掉落（roll_loot）
Step 8: 桥接 G — 装备熟练度
    ↓ 桥接层完成
后续: 丰富层按需
```

### 依赖图

```
Step 0（数据迁移）
    └──→ Step 1（注册表）
            ├──→ Step 2（金币）──→ Step 3（背包）──→ Step 4（装备）──→ Step 5（效果）──→ Step 6（状态）
            ├──→ Step 7（战斗掉落，可与 2-6 并行）
            └──→ Step 4 ──→ Step 8（熟练度，可与 5-6 并行）
```

> 关键路径：0 → 1 → 2 → 3 → 4 → 5 → 6

## 七、Schema 变更对现有组件的影响

新 Schema 的引入会波及以下组件，需在对应 Step 中同步更新：

| 受影响组件 | 影响点 | 对应 Step |
|-----------|--------|----------|
| `item_registry.py` | 解析新字段（weapon_data/armor_data/etc） | Step 1 |
| `operations.py: recalculate_ac()` | ac_bonus → base_ac + max_dex_bonus 模型 | Step 4 |
| `operations.py: equip_item()` | 新增 slot 自动推断（subtype → slot 映射） | Step 4 |
| `player_character.py: equipment` | 槽位从 ~6 扩展到 13 | Step 4 |
| `player_character.py: to_combat_player_state()` | 读取 weapon_data 取伤害/属性 | Step 4 |
| `rules.py: ITEM_EFFECTS` | 硬编码效果表 → 读 special_effects | Step 5 |
| `combat_engine.py` | proficiency 检查、damage_type 适配 | Step 7-8 |
| worldbook_graphizer 提取 prompt | 按新 Schema 模板输出 | Step 0 |
