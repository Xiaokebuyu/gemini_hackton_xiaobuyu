## 一、目标架构

> **核心理念**：把玩家和 Agent 放入一个真正的游戏世界。抽象层隔开上层与底层，底层对所有上层实体透明，无非权限高低。

```
┌─────────────────────────────────────────┐
│  上层：居民（Players / Agents）          │
│  GM Agent / NPC Agent / 队友 Agent / 玩家 │
│  只看到"我能做什么"，通过统一接口行动      │
├─────────────────────────────────────────┤
│  中层：世界规则接口（World API）          │
│  权限控制 / 动作验证 / 结果包装           │
│  对上层暴露统一工具，对下层转发操作         │
├─────────────────────────────────────────┤
│  底层：游戏世界引擎（World Engine MCP）    │
│  WorldGraph + BehaviorEngine + 导航 +     │
│  经济 + 时间 + 事件 + 战斗 + 物品 + ...  │
│  机械真理源，零 AI，纯规则/状态/计算       │
└─────────────────────────────────────────┘
```

**原则**：
- 底层 = Strandbeest 的机械结构（纯规则，零 AI）
- 中层 = 机械结构暴露给外界的操作面板（统一接口 + 权限）
- 上层 = 风（玩家操作 + Agent AI 决策）

## 三、发现的核心问题

### 3.1 状态散落（同一数据多处读写）

**玩家金币/XP/HP**：
```
写入路径 1: v4_agentic_tools.add_xp()         → session.player.xp += N
写入路径 2: _sync_combat_to_graph()            → session.player.xp = ... + N
写入路径 3: _apply_on_complete_from_graph()    → session.player.xp = ... + N
写入路径 4: flash_cpu._sync_combat_results()   → session.player.xp = ... + N
写入路径 5: session._apply_tick_side_effects() → session.player.xp = ... + N
```

5 条写入路径，每条都直接操作 `player.xp`，没有统一校验，没有升级检查。Gold 同理有 4 条。

**NPC 位置**：IntentExecutor 直接改 WorldGraph HOSTS 边
**事件状态**：BehaviorEngine + V4AgenticTools + SessionRuntime 三处可改

### 3.2 Agent 层和世界层混合

- `V4AgenticToolRegistry`：既是 LLM 工具定义，又是状态修改入口
- `IntentExecutor`：主要是机械执行，但 TALK 意图会触发 FlashCPU 的 NPC 对话
- `SessionRuntime`：主要是状态管理，但内嵌了 BehaviorEngine tick 和副作用分发逻辑
- `NpcReactor`：放在 `app/world/` 但含 LLM 调用，层级错位

### 3.3 三套接口不统一

### 3.5 依赖注入与单例问题（补充审计发现）

**StateManager 三实例分叉**：
```
AdminCoordinator._state_manager     → StateManager A（几乎不使用）
AdminWorldRuntime._state_manager    → StateManager B（实际使用，start_session & persist）
FlashCPUService._state_manager      → StateManager C（已弃用但仍存在）
```
三份独立的 `_states` 字典，同一会话状态在三处可能不同步。

**后期注入空指针风险**（`admin_coordinator.py:121-137`）：
```python
self.flash_cpu.party_service = self.party_service        # 后期注入
self.flash_cpu.character_service = None                  # placeholder → 竞态风险
```

**双重单例冗余**：`AdminCoordinator.get_instance()` 返回类单例 + `@lru_cache()` 包裹，重置时可能不同步。

### 3.6 持久化链路脆弱性（补充审计发现）

**Player 唯一持久化路径是 WorldGraph 快照**：
```python
# session_runtime.py persist() 步骤 3:
if self._dirty_player:
    self._dirty_player = False        # 标记清除
    persisted.append("player")        # ← 实际不写任何东西！
# 真正写入在步骤 7:
await self._persist_world_graph_snapshot()  # ← 若失败，player 数据永久丢失
```

- `_world_graph_failed=True` 时**静默降级**：事件工具被禁、BehaviorEngine 不跑、Player 更改不保存，但会话继续运行无报错
- `metadata.player_character` 已停用写入，但恢复时仍作为回退读取（幽灵路径）

**副作用去重不持久化**：
```python
self._applied_side_effect_events: Set[str] = set()  # 纯内存，crash 恢复后清空
```
场景：XP +100 → 快照保存 → 崩溃 → 恢复 → 去重集为空 → XP 再发一遍。

**双倍 BehaviorEngine tick**：
- pre-tick（A 阶段）+ post-tick（C 阶段）各跑一次
- 去重仅限本轮内存，工具路径产生的同一事件可能重复

**persist() 7 步无事务保证**：
```
步骤 1: GameState    → 成功
步骤 2: Narrative    → 成功
步骤 3: Player       → 仅标记（依赖步骤 7）
步骤 4: Party        → 已实时写入
步骤 5: Companions   → ⚠️ 未实现
步骤 6: AreaRuntime  → 成功
步骤 7: WorldGraph   → 若失败 → Player 数据丢失，其他步骤已提交无法回滚
```

### 3.7 私聊系统脱离主管线（补充审计发现）

`process_private_chat_stream()`（`admin_coordinator.py`）完全绕过 PipelineOrchestrator：
- 不记录 SessionHistory
- 不执行 BehaviorEngine
- 不触发事件副作用
- NPC 记忆与主线剧情脱离

### 3.8 Firestore 数据模型问题（补充审计发现）

**GameState 多副本无同步**：
```
副本 1: StateManager._states（内存缓存）
副本 2: sessions/{sid} → metadata.admin_state（Firestore）
副本 3: game_state.narrative_progress（嵌入式，与 metadata.narrative 可能分叉）
```

**完整 Firestore 路径结构**（文档原缺）：
```
worlds/{world_id}/
  sessions/{session_id}/
    (document)                    ← 主会话文档（metadata.admin_state / narrative / player_character）
    world_snapshot/current        ← WorldGraph 快照（Player 唯一持久化路径）
    messages/{message_id}         ← 会话历史
    companions/{char_id}/
      data/state                  ← 同伴状态
      shared_events/{event_id}    ← 共享事件（上限 100 条）
      area_summaries/{area_id}    ← 区域摘要
    areas/{area_id}/
      state/current               ← 区域状态
      npc_contexts/{npc_id}       ← NPC 快照
      visits/{visit_id}           ← 访问记录
  parties/{session_id}/
    (document)                    ← Party 元数据
    members/{char_id}             ← 队伍成员（实时写入，非事务）
  characters/{char_id}/
    nodes/, edges/                ← 角色知识图
    dispositions/{target_id}      ← 好感度（含 history 最近 50 条）
  graphs/world/nodes/, edges/     ← 世界级知识图
  chapters/{cid}/graph/data/...   ← 章节级
  chapters/{cid}/areas/{aid}/graph/data/...  ← 区域级
  camp/graph/...                  ← 营地级
  choices/{choice_id}             ← 玩家选择记录
```

**无 schema 版本管理**：GameState、NarrativeProgress 等模型无 `schema_version` 字段，跨版本升级靠运气。

## 四、重构方向

### 4.1 底层：World Engine MCP

将所有"世界机械"收编为一个统一的服务（内部模块化，对外统一 MCP 接口）：

```
World Engine MCP
├── graph/          WorldGraph + GraphBuilder + Snapshot
├── behavior/       BehaviorEngine + EventPropagation + SceneBus
├── navigation/     AreaNavigator + 位置管理 + 子地点
├── economy/        StatsManager（金币/XP/物品统一入口）+ ShopService
├── combat/         CombatEngine + Dice + Effects + Rules
├── time/           TimeManager + 时段 + 营业时间
├── character/      CharacterService + D&D 规则 + 升级
├── narrative/      NarrativeService + 章节 + 事件状态机
├── party/          PartyService + 位置同步
├── persistence/    GraphStore + StateManager + Snapshot + CharacterStore
└── query/          ContextAssembler + IntentResolver + SpreadingActivation
```

**关键变化**：
- `StatsManager` 成为金币/XP/物品的**唯一写入入口**，任何路径想改玩家数值都必须经过它
- 升级检查内嵌在 `StatsManager.add_xp()` 中（不再需要外部调用方记住检查）
- 商店是子地点上的机械实体，ShopService 管理货架/价格/库存

### 4.2 中层：World API（抽象服务层）

统一接口层，对上层暴露操作，对下层转发：

```
World API
├── 动作接口       move(target) / talk(npc_id, message) / examine(target) / use_item(item_id) / rest()
├── 交易接口       buy(item_id, shop_location) / sell(item_id) / haggle(item_id, offer_price)
├── 查询接口       get_location() / get_inventory() / get_stats() / get_shop_stock(location)
├── 战斗接口       trigger_combat() / combat_action() / resolve_combat()
├── 社交接口       update_disposition() / start_dialogue() / end_dialogue()
└── 权限层         根据调用者身份（player/gm/npc/teammate）过滤可用操作和可见信息
```

**权限示例**：
- **玩家**：能 move/talk/examine/buy/sell/use_item，不能直接 activate_event
- **GM Agent**：能 activate_event/complete_event/advance_chapter，不能直接改金币（由系统结算）
- **NPC Agent（商人）**：能 adjust_price/show_inventory，不能改玩家位置
- **NPC Agent（普通）**：能 update_disposition/recall_memory，不能交易

### 4.3 上层：居民（Agent 层）

每个 Agent 通过 World API 与世界交互，看到的是"我能做什么"：

```
上层居民
├── 玩家          通过前端 UI → REST → World API 与世界交互
├── GM Agent      消费 SceneBus → 叙述 + 创意裁决（不操作世界数值）
├── NPC Agent     被唤醒时读 SceneBus → 用自己的人格交互 → 通过 World API 执行
├── 队友 Agent    始终读 SceneBus → 自主决策 → 通过 World API 表达
└── 系统结算      战斗/事件完成后自动通过 World API 发放奖励（非 Agent）
```

## 九、数据流全景（补充审计）

### PipelineOrchestrator.process() 完整调用链

```
玩家输入
  ↓
A 阶段: 上下文组装
  ├── SessionRuntime.restore()
  │     └── Wave1 并行: GameState, Player, Party, Narrative
  │     └── Wave2 串行: History, Area, Companions, WorldGraph, Snapshot
  ├── session.run_behavior_tick("pre")        ← 第一次 BehaviorEngine tick
  │     └── 产生副作用事件 → _applied_side_effect_events 去重
  ├── IntentResolver.resolve(input)           ← 机械意图识别
  │     └── IntentExecutor.dispatch(intent)   ← 可直接修改位置/时间/物品
  │           └── 设置 context["engine_executed"]
  └── NPCReactor.collect_reactions()          ← ⚠️ 含 LLM，基于旧状态快照
  ↓
B 阶段: Agentic 会话
  └── FlashCPUService.agentic_process_v4()
        └── V4AgenticToolRegistry.get_tools()
              └── 工具过滤: 若 engine_executed → 排除对应工具
              └── LLM 工具调用可修改 WorldGraph/Player/Party/Events
  ↓
C 阶段: 后处理
  ├── session.run_behavior_tick("post")       ← 第二次 BehaviorEngine tick
  │     └── 同一事件可能再评估一遍（去重仅限本轮内存）
  ├── CompanionInstance 事件分发
  ├── TeammateResponseService.process_round() ← LLM 决策
  └── SessionRuntime.persist()                ← 7 步（见 3.6）
```

### 三个并发的状态存储

```
Firestore（持久层）
  ├── metadata.admin_state  → GameState
  ├── metadata.narrative    → NarrativeProgress
  ├── world_snapshot/current → WorldGraph 快照（含 Player 节点）
  └── parties/{sid}/members → Party 成员（实时写入）

StateManager._states（内存层）
  ├── A: AdminCoordinator._state_manager   [几乎不用]
  ├── B: AdminWorldRuntime._state_manager  [实际使用]
  └── C: FlashCPUService._state_manager    [已弃用]

WorldGraph（会话期间）
  ├── 节点 state（XP, HP, 位置, 物品）
  ├── 快照保存到 Firestore → 恢复时加载
  └── _world_graph_failed 时全部降级
```
