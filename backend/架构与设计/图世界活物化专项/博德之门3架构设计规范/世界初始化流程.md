# 世界初始化流程

创建时间：2026-02-26
状态：设计中
前置文档：所有层设计规范（❶❷❸⊕❺ + 编排层）+ 子系统接入手册

> 从"世界书 JSON → 提取 → 加载 → 新会话 → 角色创建 → 第一个时间格"的完整链路。
>
> 本文档是操作流程手册，不是架构原理说明。每一步都能对应到具体的代码执行路径。

## 一、完整链路概览

```
世界书 JSON（SillyTavern-v2 角色卡格式）
    │
    │  Phase 1: 世界数据提取（离线，一次性）
    ▼
结构化数据文件（10 个 Registry 对齐的 JSON）
    │
    │  Phase 2: WorldInstance 加载（服务启动时 or 首次访问时）
    ▼
WorldInstance（❶ 内容层，世界级单例，只读）
    │
    │  Phase 3: 新会话创建
    ▼
StateContainer（❸ 状态层，会话级单例，可变）
    │
    │  Phase 4: 角色创建
    ▼
PlayerSlice 填充 + 起始装备/金币
    │
    │  Phase 5: 第一个时间格
    ▼
TickCoordinator 启动 → GM 开场叙述 → 等待玩家第一次操作
```

**时间线**：

| Phase | 触发时机 | 频率 | 耗时预期 |
|-------|---------|------|---------|
| Phase 1 提取 | 手动 CLI 命令 | 每个世界书一次 | 数分钟（Batch API） |
| Phase 2 加载 | 服务启动 or 首次访问 | 每个世界一次（进程级缓存） | < 2 秒 |
| Phase 3 会话 | `POST /sessions` | 每次新游戏 | < 500ms |
| Phase 4 角色 | `POST /character` | 每次新游戏 | < 200ms |
| Phase 5 开场 | 角色创建完成后自动 | 每次新游戏 | < 3 秒（含 LLM 调用） |

## 二、Phase 1: 世界数据提取

### §2.1 提取管线入口

```bash
python -m app.tools.init_world_cli extract \
    --input "worldbook.json" \
    --output data/{world_name}/structured/ \
    --model gemini-3-pro-preview \
    --thinking-level none \
    --relabel-edges --enrich-entities
```

输入：SillyTavern-v2 世界书 JSON（可含数百条 lorebook 条目，数十万 tokens）

输出：一组结构化 JSON 文件，与 ❶ 内容层的 10 个 Registry schema 对齐。

### §2.2 输出文件与 Registry 对齐

提取管线为每个 Registry 生成一个对应文件：

```
data/{world_name}/structured/
    ├─ tags.json              ← TagRegistry
    ├─ map.json               ← MapRegistry（区域 + 子地点 + 连接 + 地形）
    ├─ characters.json        ← CharacterRegistry（NPC 模板）
    ├─ items.json             ← ItemRegistry（物品模板）
    ├─ monsters.json          ← MonsterRegistry（怪物模板）
    ├─ skills.json            ← SkillRegistry（技能/法术/状态效果）
    ├─ classes.json           ← ClassRegistry（职业/种族/背景）
    ├─ quests.json            ← QuestRegistry（任务模板）
    ├─ factions.json          ← FactionRegistry（阵营定义 + 行为规则）
    ├─ lore.json              ← LoreRegistry（世界规则文本）
    │
    ├─ knowledge_graph.json   ← 世界知识图谱（本地 NetworkX 加载 + 可选云端同步）
    └─ mainlines.json         ← 主线剧情大纲（编排层使用）
```

### §2.3 自动提取 vs 手动补充

世界书能提取的内容有限，部分 Registry 需要手动补充。

| Registry | 自动提取 | 需要手动补充 |
|----------|---------|-------------|
| TagRegistry | ✅ 提取时生成实体标签 | 标签类别维度定义 |
| MapRegistry | ✅ 世界书中的地点 + 连接关系 | 精确旅行时间、遭遇表、地形 |
| CharacterRegistry | ✅ NPC 性格/背景/说话风格 | 精确数值属性（STR/DEX/...） |
| ItemRegistry | ✅ 名称/描述/标签 | 精确数值（伤害/AC/价格） |
| MonsterRegistry | ✅ 名称/描述/类型 | 精确属性/技能/掉落表 |
| SkillRegistry | ⚠️ 有限（世界书很少包含） | **大部分手写**（D&D SRD 对齐） |
| ClassRegistry | ❌ 非世界书内容 | **全部手写** |
| QuestRegistry | ⚠️ 世界书剧情线索 | 精确目标/奖励/前置条件 |
| FactionRegistry | ✅ 世界书阵营关系 | 行为规则需要结构化 |
| LoreRegistry | ✅ 世界书设定文本 | 结构化规则提取 |

**分层交付策略**：

```
第一批（提取管线直接输出，可快速上线）：
  tags.json, map.json, characters.json, factions.json, lore.json

第二批（需要人工审核 + 补充数值）：
  items.json, monsters.json, quests.json

第三批（需要完全手写或 D&D SRD 翻译）：
  skills.json, classes.json
```

### §2.4 提取质量校验

提取完成后运行校验脚本，检查输出是否符合 Registry schema：

```bash
python -m app.tools.init_world_cli validate \
    --input data/{world_name}/structured/ \
    --schema schemas/registry_schemas/
```

校验项：

| 检查项 | 说明 |
|--------|------|
| Schema 合规 | 每个 JSON 符合对应 Registry 的 Pydantic schema |
| 引用完整性 | NPC 引用的 faction_id 存在于 factions.json |
| Tag 一致性 | 实体使用的标签都在 tags.json 的维度中定义 |
| 地图连通性 | MapRegistry 中所有区域形成连通图（无孤岛） |
| ID 唯一性 | 所有实体 ID 全局唯一（跨 Registry） |
| 必填字段 | 无缺失的必填字段 |

## 三、Phase 2: WorldInstance 加载

### §3.1 加载入口

```python
# GameRuntime（全局单例）
class GameRuntime:
    _world_cache: dict[str, WorldInstance]

    async def get_world(self, world_id: str) -> WorldInstance:
        if world_id not in self._world_cache:
            instance = await WorldInstance.load(world_id)
            self._world_cache[world_id] = instance
        return self._world_cache[world_id]
```

触发时机：
- **服务启动时**：预加载已知世界（可选，减少首次请求延迟）
- **首次访问时**：懒加载，加载后缓存为进程级单例

### §3.2 加载顺序

TagRegistry 是所有 Registry 的依赖（其他 Registry 的实体都引用 Tag），必须最先加载。

```
WorldInstance.load(world_id)
    │
    ├─ Step 1: TagRegistry 加载（最先）
    │     data/{world_id}/structured/tags.json
    │     构建 Tag 维度索引 + 标签查询 API
    │
    ├─ Step 2: 基础 Registry 并行加载
    │     ├─ MapRegistry      ← map.json
    │     ├─ ClassRegistry    ← classes.json
    │     ├─ SkillRegistry    ← skills.json
    │     └─ LoreRegistry     ← lore.json
    │     （这些 Registry 不依赖其他 Registry，可并行）
    │
    ├─ Step 3: 实体 Registry 并行加载（依赖 TagRegistry + 基础 Registry）
    │     ├─ CharacterRegistry ← characters.json（引用 Tag + Faction）
    │     ├─ ItemRegistry      ← items.json（引用 Tag + Skill 效果）
    │     ├─ MonsterRegistry   ← monsters.json（引用 Tag + Skill）
    │     ├─ FactionRegistry   ← factions.json（引用 Tag）
    │     └─ QuestRegistry     ← quests.json（引用 Character + Location）
    │
    ├─ Step 4: 交叉引用校验
    │     验证所有跨 Registry 引用的完整性
    │     例：quest.target_npc 必须在 CharacterRegistry 中存在
    │
    └─ Step 5: 标记为只读
          冻结所有 Registry（运行时不可变）
          返回 WorldInstance
```

### §3.3 缓存策略

| 策略 | 说明 |
|------|------|
| **进程级缓存** | WorldInstance 在 `GameRuntime._world_cache` 中缓存，整个进程生命周期内只加载一次 |
| **只读保证** | 加载完成后冻结，运行时不可变，无并发写冲突 |
| **多世界共存** | 缓存是 dict[world_id → WorldInstance]，支持同时加载多个世界 |
| **刷新机制** | 世界数据更新后，需要重启服务或调用 `GameRuntime.reload(world_id)` |

### §3.4 知识图谱加载

知识图谱与存档一样采用本地优先策略：

```
knowledge_graph.json → 本地 NetworkX 图加载（进程内存）
                     → 同时写入本地图谱存储 graphs/{world_id}/world/
                     → 可选异步同步到 Firestore（跨设备/备份）
```

**静态世界图谱**（GraphScope.world()）：提取管线产出的 knowledge_graph.json 在 WorldInstance 加载时直接读入 NetworkX，常驻内存。供 MemoryGraph 扩散激活检索使用。

**动态记忆图谱**（GraphScope.character() 等）：NPC 对话产生的记忆节点/边写入本地图谱文件，异步同步到云端。

```
本地图谱存储：
graphs/{world_id}/
    ├─ world/                  ← 静态世界图谱（只读，提取管线产出）
    │   ├─ nodes.json
    │   └─ edges.json
    ├─ characters/{char_id}/   ← 角色个人记忆图谱（可写）
    │   ├─ nodes.json
    │   └─ edges.json
    ├─ chapters/{cid}/         ← 章节图谱
    └─ camp/                   ← 队伍营地图谱
```

只在**首次部署**或**数据更新**时从 knowledge_graph.json 初始化（幂等写入，已存在则跳过）。

## 四、Phase 3: 新会话创建

### §4.1 触发

### §4.2 StateContainer 初始化

从 ❶ WorldInstance 模板实例化 ❸ 初始状态。核心思想：**❶ 模板 + 空 Diff = 初始 ❸**。

```python
StateContainer.create_new(world: WorldInstance) -> StateContainer:
    container = StateContainer()

    # TimeSlice：固定初始值
    container.register("time", TimeSlice(
        day=1,
        slot=8,               # 08:00 开始（白天）
        period="day",
        action_count=0,
        accumulated=0.0,
    ))

    # PlayerSlice：空壳，等 Phase 4 角色创建填充
    container.register("player", PlayerSlice.empty())

    # RelationSlice：从 ❶ CharacterRegistry 初始化 NPC 基础好感度
    relations = RelationSlice()
    for npc in world.character_registry.all():
        relations.init_npc(npc.id, Disposition(
            approval=npc.base_disposition.approval,   # 来自 ❶ 模板
            trust=npc.base_disposition.trust,
            fear=0,
            romance=0,
        ))
    for faction in world.faction_registry.all():
        relations.init_faction(faction.id, faction.initial_standing)
    container.register("relations", relations)

    # QuestSlice：主线任务标记为 unknown，章节完成度 0%
    quests = QuestSlice()
    for quest in world.quest_registry.all():
        quests.init_quest(quest.id, state="unknown")
    for chapter in world.quest_registry.chapters():
        quests.init_chapter(chapter.id, completion=0.0)
    container.register("quests", quests)

    # FlagSlice：空（无世界标记）
    container.register("flags", FlagSlice())

    # AreaSlice：从 ❶ MapRegistry 初始化区域状态
    areas = AreaSlice()
    for area in world.map_registry.all_areas():
        areas.init_area(area.id, AreaState(
            exploration="undiscovered",    # 起始区域在 Phase 5 标记为 discovered
            danger_level=area.base_danger,
            properties={},
            tags=area.tags,
        ))
    container.register("areas", areas)

    # EventSlice：从 ❶ 加载初始事件定义
    events = EventSlice()
    for event_def in world.quest_registry.initial_events():
        events.register_event(event_def.id, state="locked", conditions=event_def.preconditions)
    container.register("events", events)

    # PartySlice：空队伍
    container.register("party", PartySlice())

    # SceneSlice：空（格级生命周期）
    container.register("scene", SceneSlice())

    return container
```

### §4.3 ❶ → ❸ 模板实例化对照表

| ❶ Registry | ❸ Slice | 初始化内容 |
|------------|---------|-----------|
| MapRegistry | AreaSlice | base_danger → danger_level，所有区域 exploration="undiscovered" |
| CharacterRegistry | RelationSlice | base_disposition → 各 NPC 初始好感度 |
| FactionRegistry | RelationSlice | initial_standing → 各阵营初始声望 |
| QuestRegistry | QuestSlice | 所有任务 state="unknown"，章节 completion=0.0 |
| QuestRegistry | EventSlice | 初始事件注册（state="locked"） |
| — | TimeSlice | 固定值：day=1, slot=8, period="day" |
| — | PlayerSlice | 空壳（等角色创建） |
| — | FlagSlice | 空 |
| — | PartySlice | 空 |
| — | SceneSlice | 空 |

### §4.4 持久化

StateContainer 创建后立即写入本地存档：

```
saves/{session_id}/
  ├─ state/time.json        ← TimeSlice
  ├─ state/player.json      ← PlayerSlice (empty)
  ├─ state/relations.json   ← RelationSlice (initialized)
  ├─ state/quests.json      ← QuestSlice (all unknown)
  ├─ state/flags.json       ← FlagSlice (empty)
  ├─ state/areas.json       ← AreaSlice (initialized)
  ├─ state/events.json      ← EventSlice (initial events)
  ├─ state/party.json       ← PartySlice (empty)
  └─ meta.json              ← 存档元数据（世界ID、创建时间）

同时异步上传到 Firestore 云端备份。
```

## 五、Phase 4: 角色创建

### §5.1 前端交互流程

```
GET .../character-creation/options
    → 返回可选的种族/职业/背景列表（来自 ❶ ClassRegistry）

前端 UI（纯面板选择，3-5 分钟）：
    1. 选择种族（6 选 1） → 属性加成 + 种族特性
    2. 选择职业（8 选 1） → 起始技能 + 装备类型
    3. 选择背景（7 选 1） → 额外技能 + 起始金币
    4. 分配属性点（27 点购买制，D&D 标准）
    5. 填写背景故事（可选，纯风味文本）
    6. 确认

POST .../character
    → 提交角色数据
```

### §5.2 引擎执行

角色创建通过 ❷ RulesEngine 执行，确保所有数值计算走统一路径。

```python
# 1. 构造角色创建 Command
cmd = Command(
    type="create_character",
    source="engine",
    params={
        "race": "human",
        "class": "fighter",
        "background": "soldier",
        "attributes": {"str": 16, "dex": 14, "con": 14, "int": 10, "wis": 12, "cha": 8},
        "name": "阿尔文",
        "backstory": "...",    # 可选
    },
)

# 2. GrowthHandler 计算
result = rules_engine.execute(cmd, state, world)
#   → 计算 HP: hit_die + CON_mod
#   → 计算 AC: 基于装备（默认 10 + DEX_mod）
#   → 计算 proficiency_bonus: +2 (1 级)
#   → 计算 initiative: DEX_mod
#   → 确定起始技能/特性（种族 + 职业 + 背景）
#   → 返回 delta

# 3. 应用到 PlayerSlice
state.apply(result.delta)
```

## 六、Phase 5: 第一个时间格

### §6.1 TickCoordinator 构建

```python
# 角色创建完成后，构建 TickCoordinator
tc = TickCoordinator(
    world=world_instance,
    state=state_container,
    rules_engine=RulesEngine(handlers=ALL_HANDLERS),
    ai_osiris=AIOsiris(world=world_instance),

# 注册 9 个内置 SettlementHook
tc.register_settlement_hook(ScheduledEventHook())    # P10
tc.register_settlement_hook(StatusEffectHook())       # P20
tc.register_settlement_hook(AIOsirisHook())           # P30
tc.register_settlement_hook(EncounterHook())          # P40
tc.register_settlement_hook(EventConditionHook())     # P50
tc.register_settlement_hook(NpcScheduleHook())        # P60
tc.register_settlement_hook(TimeAdvanceHook())        # P70
tc.register_settlement_hook(GmNarrationHook())        # P80
tc.register_settlement_hook(SceneBusResetHook())      # P90

# 初始化 SceneBus（空）
tc.scene_bus = SceneBus()

# 缓存到 AdminCoordinator
admin_coordinator.register_tick_coordinator(session_id, tc)
```

### §6.2 GM 开场叙述

```python
# 组装开场上下文
opening_context = ContextAssembler.assemble_opening(
    world=world_instance,
    state=state_container,
    player=state_container.player_slice,
)
# 包含：
#   - 起始区域描述（❶ MapRegistry）
#   - 当前时段氛围（day, 08:00）
#   - 角色背景摘要
#   - 世界基调（❶ LoreRegistry）

# GM Agent 生成开场叙述
gm_result = await AgenticExecutor.run(
    role="gm",
    system_prompt=opening_narration_prompt,
    context=opening_context,
    tools=[],   # 开场无工具，纯叙述
)

# 写入 SceneBus
tc.scene_bus.add(SceneEntry(
    source="GM",
    content=gm_result.text,
    visibility="public",
))

# 推送给前端
# → SSE gm_narration 事件
# → SSE scene_change 事件（起始地点背景 + 氛围）
```

### §6.3 开场叙述原则

来自玩法导向文档——**不做教程**：

| 原则 | 说明 |
|------|------|
| 无强制教程 | AI GM 本身就是最好的引导 |
| 无固定脚本 | GM 基于位置 + 世界书 + 角色背景即兴生成 |
| 自然开场 | 玩家发现自己在某个地方（冒险者公会？边境小镇街头？），周围有可交互的 NPC 和可去的地点 |
| 第一任务自然涌现 | 去公会看看任务板 → NPC 主动搭话 → 发现线索 |

### §6.4 等待玩家操作

开场叙述推送后，系统进入等待状态。玩家可以：

- 点击 NPC 交互（→ `/interact/stream`）
- 选择导航到其他地点（→ `/navigate`）
- 输入自由文字（→ `/input/stream`）
- 查看地图/背包/角色面板（0 成本，不消耗时间）

从玩家第一次操作开始，时间经济系统正式启动。

## 七、会话恢复

### §7.1 触发

```
POST /{world_id}/sessions/{session_id}/resume
    → AdminCoordinator.resume_session(world_id, session_id)
```

### §7.2 恢复流程

```
Resume
    │
    ├─ 1. 加载世界数据
    │     GameRuntime.get_world(world_id)
    │     → WorldInstance（进程级缓存，可能已加载）
    │
    ├─ 2. 恢复状态（本地优先 → 云端回退）
    │     SaveStore.load(session_id)
    │     → 优先读取本地存档 saves/{session_id}/state/
    │     → 本地不存在时回退到 Firestore 云端存档（跨设备场景）
    │     → StateContainer.restore(data)
    │
    │     state/time      → TimeSlice（恢复 day/slot/period/accumulated）
    │     state/player    → PlayerSlice（恢复角色全部属性）
    │     state/relations → RelationSlice（恢复所有好感度）
    │     state/quests    → QuestSlice（恢复任务进度）
    │     state/flags     → FlagSlice（恢复世界标记）
    │     state/areas     → AreaSlice（恢复区域状态）
    │     state/events    → EventSlice（恢复事件 + 延时事件）
    │     state/party     → PartySlice（恢复队伍）
    │
    │     ※ SceneSlice 不恢复（格级生命周期），重新创建空实例
    │
    ├─ 3. 重建 TickCoordinator
    │     注入恢复的 StateContainer + WorldInstance
    │     注册 SettlementHook 链
    │     SceneBus 重新初始化（空）
    │     恢复 TimeSlice.accumulated（未完成的格内累积时间）
    │
    ├─ 4. NPC 实例恢复
    │     InstanceManager 按需懒加载（不在恢复时全量加载）
    │     当玩家与 NPC 交互时，才加载该 NPC 的工作记忆 + 图谱记忆
    │
    └─ 5. GM 恢复叙述
          读取当前位置 + 时段 + 最近事件摘要
          GM 生成简短的恢复描述
          "你在{location}，{time_description}。{recent_context_hint}..."
          → SSE gm_narration
```

### §7.3 恢复一致性保证

| 检查项 | 处理方式 |
|--------|---------|
| WorldInstance 版本变化 | 比对 world_version 字段，不匹配则提示用户（可能影响平衡） |
| 引用完整性 | NPC/区域 ID 仍存在于 ❶ 中（数据更新可能删除了某些实体） |
| 时间一致性 | TimeSlice 恢复后，重新计算 period（确保 slot ↔ period 一致） |
| 队伍一致性 | PartySlice 中的队友仍在 CharacterRegistry 中 |

### §7.4 跨设备恢复

玩家在设备 A 游玩后，想在设备 B 继续：

```
设备 A：游玩 → 本地存档 → 云端同步（自动/手动上传）
设备 B：启动 → 本地无存档 → 从 Firestore 下载 → 本地恢复 → 继续游玩
```

冲突处理：两台设备都有本地存档时，比对 `meta.json` 中的 `save_timestamp`，以时间戳较新者为准，提示用户确认。

## 八、数据目录结构

> 注意：当前代码库中的 `data/{world_name}/structured/` 路径为旧目录，新目录结构待迁移确定。
> 以下是目标结构设计。

```
data/
  └─ {world_id}/
       │
       ├─ raw/                          # 原始世界书（不进 git）
       │   └─ worldbook.json
       │
       ├─ structured/                   # 提取管线输出（进 git，版本控制）
       │   ├─ tags.json
       │   ├─ map.json
       │   ├─ characters.json
       │   ├─ items.json
       │   ├─ monsters.json
       │   ├─ skills.json
       │   ├─ classes.json
       │   ├─ quests.json
       │   ├─ factions.json
       │   ├─ lore.json
       │   ├─ knowledge_graph.json
       │   └─ mainlines.json
       │
       ├─ manual/                       # 手动补充数据（进 git）
       │   ├─ skills_srd.json           # D&D SRD 技能数据
       │   ├─ classes_full.json         # 完整职业/子职业数据
       │   └─ balance_overrides.json    # 数值平衡覆盖
       │
       └─ merged/                       # 合并后的最终数据（构建产物，可不进 git）
            ├─ tags.json                # structured + manual 合并
            ├─ ...
            └─ world_manifest.json      # 世界元数据（版本、创建时间、数据完整度）
```

**合并策略**：

```
structured/{registry}.json  ← 提取管线自动生成
    +
manual/{registry}_override.json  ← 手动补充/覆盖
    =
merged/{registry}.json  ← WorldInstance 实际加载的文件
```

手动覆盖优先级高于自动提取。合并脚本：

```bash
python -m app.tools.init_world_cli merge \
    --structured data/{world_id}/structured/ \
    --manual data/{world_id}/manual/ \
    --output data/{world_id}/merged/
```

## 九、完整时序图

### §9.1 从服务启动到玩家第一次操作

```
服务启动
    │
    ├─ FastAPI app 初始化
    ├─ 依赖注入：GameRuntime（全局单例）、SaveStore、GraphStore、MCPClientPool
    ├─ GameRuntime: 空缓存（懒加载 WorldInstance）
    │
    ... 等待请求 ...
    │
玩家请求：GET /worlds
    │
    ├─ 返回可用世界列表（扫描 data/ 目录 + saves/ 本地存档）
    │
玩家请求：POST /{world_id}/sessions
    │
    ├─ Phase 2: GameRuntime.get_world(world_id)
    │     → 首次加载 WorldInstance（~2 秒）
    │     → 缓存
    │
    ├─ Phase 3: StateContainer.create_new(world)
    │     → 9 个 Slice 初始化
    │     → 本地存档写入 + 云端异步同步
    │
    ├─ 返回 session_id
    │
玩家请求：GET .../character-creation/options
    │
    ├─ 从 ❶ ClassRegistry 返回种族/职业/背景选项
    │
玩家请求：POST .../character
    │
    ├─ Phase 4: 角色创建
    │     → ❷ GrowthHandler 计算属性
    │     → ❷ InventoryHandler 分配装备
    │     → PlayerSlice 填充
    │     → 起始位置设置
    │     → 本地存档写入
    │
    ├─ Phase 5: TickCoordinator 构建
    │     → 9 个 SettlementHook 注册
    │     → SceneBus 初始化
    │
    ├─ Phase 5: GM 开场叙述
    │     → ContextAssembler 组装开场上下文
    │     → AgenticExecutor.run(role="gm") → 叙述文本
    │     → 写入 SceneBus
    │     → SSE gm_narration + scene_change
    │
    ... 等待玩家操作 ...
    │
玩家第一次操作（例：点击 NPC）
    │
    ├─ POST .../interact/stream
    │     → AdminCoordinator.process_interact()
    │     → NpcInteractionCoordinator.process()
    │     → NPC Agent 响应 → GM 观察 → 队友旁观 → 对话选项
    │     → TickCoordinator.accumulate(1/6)
    │     → 持久化
    │
    │  ※ 时间经济系统正式启动
    │  ※ 此后每个动作消耗时间，累积到 1.0 格后触发结算
```

### §9.2 会话恢复到继续游戏

```
玩家请求：POST /{world_id}/sessions/{session_id}/resume
    │
    ├─ GameRuntime.get_world(world_id)（可能已缓存）
    │
    ├─ SaveStore.load(session_id)
    │     → 本地存档优先 → 云端回退
    │     → StateContainer.restore(data)
    │     → SceneSlice 重新创建
    │
    ├─ TickCoordinator 重建
    │     → 注入恢复的 StateContainer
    │     → SettlementHook 注册
    │     → accumulated 恢复
    │
    ├─ GM 恢复叙述
    │     → SSE gm_narration
    │
    ... 继续正常游戏循环 ...
```
