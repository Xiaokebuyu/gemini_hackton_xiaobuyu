## P0：角色链路止血（character_store=None → 运行时 500） ✅ 已完成

### 问题本质

`CharacterStore`（Firestore 独立持久化）已废弃，角色数据现在住在 **WorldGraph 快照**里（`session.player` → `PlayerNodeView`）。但路由层和协调器层仍有 9 处直接调用旧 `character_store.get_character()` / `get_creation_config()`，全部 AttributeError 炸。

### 设计决策（2025-02-25 确认）

**方向：将角色操作变为 WorldGraph 原生功能，在 player 子系统内闭环。**

对比 `PlayerNodeView` 与旧 `CharacterService`：
- `PlayerNodeView` 已实现完整的 PlayerCharacter 兼容 API（读写属性、ability_modifier、add_item、model_dump 等），且自带脏标记
- `CharacterService` 的核心价值是**业务规则**（创建校验、升级计算、装备 AC 重算、点数购买校验），不是数据访问
- 两者功能互补，但 CharacterService 的 store 依赖是唯一痛点

**结论：新建 `app/world/player/operations.py` 作为独立执行模块**，将 CharacterService 的业务规则迁入，操作对象改为 WorldGraph 原生接口（PlayerNodeView），与 node_view.py 解耦。

### 修复策略

#### 新模块：`app/world/player/operations.py`

独立的角色业务操作模块，**无 store 依赖，无 SessionRuntime 耦合**：

```python
# 所有函数接受明确的数据对象，不依赖外部服务
def create_player_node(wg, config, request, location) -> PlayerNodeView
    """校验 + 种族加成 + 衍生计算 → 构建 WorldNode → wg.add_node() → 返回 PlayerNodeView"""

def level_up(player: PlayerNodeView, config) -> dict
    """add_xp + 多级跳 + HP/法术位/熟练加值更新"""

def equip_item(player: PlayerNodeView, item_id, slot) -> dict
    """装备管理 + AC 重算"""

def unequip_item(player: PlayerNodeView, slot) -> dict

def validate_point_buy(scores, config) -> bool
    """纯函数，点数购买校验"""
```

关键设计：
- **函数式 API**（非类），接受明确参数，无隐式依赖
- `create_player_node()` 直接操作 WorldGraph（`wg.add_node()`），创建完即可通过 `session.player` 读取
- 升级/装备操作通过 `PlayerNodeView` 的 setter 自动触发脏标记 → 快照持久化自动处理
- `config`（创建配置）从 WorldInstance 传入，operations 本身不关心来源

#### 删除旧 CharacterService

`app/world/player/character.py` 删除，业务逻辑全部迁入 `operations.py`。

#### 创建配置来源

WorldInstance 新增 `character_creation_config` 注册表：
- `initialize()` 时从 Firestore `worlds/{wid}/meta/character_creation` 加载
- 路由层通过 `world_instance.character_creation_config` 直接读取

#### AbilityCheckService 改造

`ability_check.py` 的 `perform_check()` 改为直接接受 player 对象（PlayerNodeView / PlayerCharacter 均可，接口兼容），不再需要 store。

- **`CATCHABLE_EXCEPTIONS`**：11 种域/操作异常元组，定义在 `app/exceptions.py`，路由层和内部服务统一使用
