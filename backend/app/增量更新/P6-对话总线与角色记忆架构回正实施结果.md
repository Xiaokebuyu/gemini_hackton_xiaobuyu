## 二、关键设计决定

### 1. 主流程 agent 协作挂在 `TickCoordinator`，不直接挂在 `PipelineOrchestrator.after_engine`

最终实现没有把主流程 agent round 做成 `PipelineOrchestrator` 内部 hook，而是做成
`TickCoordinator` 的 post-action hook 链。

原因：

1. agent 必须观察到已经 apply 到 `StateContainer` / `SceneBus` 的最新结果
2. 当前 `PipelineOrchestrator.process()` 的 hook 点发生在 delta apply 之前
3. 如果强行放进 `PipelineOrchestrator`，Agent 会在旧状态上决策，语义不对

因此，本轮收口点是：

`RulesEngine -> apply delta -> 写 ENGINE 语义标签 -> post-action agent hooks -> settlement`

这比“形式上更像 pipeline hook”更符合运行时语义。

### 2. 主流程 agent hooks 现在是可注册、可排序、可容错的

`TickCoordinator` 现在支持注册多个 post-action agent hooks。

特性：

1. 按 `priority` 排序执行
2. 单个 hook 失败不会中断玩家动作主流程
3. 失败会发出 `agent_hook_error`
