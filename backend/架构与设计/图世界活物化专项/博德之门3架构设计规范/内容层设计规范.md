# ❶ 内容/数据层设计规范

创建时间：2026-02-26
状态：设计中
前置文档：`博德之门3架构深度分析.md` §二.❶ + §二.Tag系统，`状态层设计规范.md`，`玩法导向的架构设计.md`

> ❶ 内容层 = 世界的 DNA。静态只读，启动时加载，运行时不可变。
> 采用 **Content Registry 注册制**：每个数据域拥有自己的注册表，WorldInstance 是容器 + 注册表。
> **Tag 系统是 ❶ 层最重要的基础设施**——所有实体在数据层就携带语义标签，上层系统统一消费。

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **静态只读** | 启动时从世界数据加载，运行时不可变。运行时状态在 ❸ 状态层 |
| **模板 vs 实例** | ❶ 存模板（出厂参数），❸ 存实例（当前值）。实例从模板初始化 |
| **Registry 自治** | 每个数据域一个 Registry，定义 schema + 查询 API |
| **持续可扩展** | 新数据域 = 新 Registry + 注册到 WorldInstance，零侵入 |
| **Tag 贯穿** | 所有实体携带 Tag，Tag 是跨层通用语言 |
| **双面数据** | 每个实体同时有结构化数值（给 ❷ 规则引擎）和语义描述（给 ❺ AI 叙事层） |

## 二、整体架构：WorldInstance + Registry 注册表

```
WorldInstance（内容容器，世界级单例，启动时加载）
    │
    │  职责：
    │  - 持有所有已注册 Registry 的引用
    │  - 统一加载生命周期（load_all / reload）
    │  - 跨 Registry 查询（by ID / by Tag）
    │  - 为 ContextAssembler 和 AI Osiris 提供静态数据
    │
    │  接口：
    │  - register(registry) → 注册新 Registry
    │  - get_registry(name) → Registry
    │  - load_all(world_data) → 加载全部 Registry
    │  - query_by_tags(tags, registry_name?) → 跨 Registry Tag 查询
    │
    ├─ TagRegistry          Tag 分类体系（基础设施，其他 Registry 依赖它）
    ├─ MapRegistry          区域 / 子地点 / 连接 / 地形
    ├─ CharacterRegistry    NPC 模板（运行时实例管理：`NPC与队友子系统设计规范.md`）
    ├─ ItemRegistry         物品模板
    ├─ MonsterRegistry      怪物模板
    ├─ SkillRegistry        技能 / 法术 / 状态效果
    ├─ ClassRegistry        职业 / 种族 / 背景
    ├─ QuestRegistry        任务模板
    ├─ FactionRegistry      势力定义
    ├─ LoreRegistry         世界规则文本
    └─ ... 未来扩展
```

### 2.1 Registry 基类

```python
class ContentRegistry(ABC):
    """内容注册表基类，只读"""

    @property
    @abstractmethod
    def name(self) -> str:
        """注册表名称，用于注册和寻址"""

    @abstractmethod
    def load(self, data: dict) -> None:
        """从世界数据加载（启动时调用一次）"""

    @abstractmethod
    def get(self, id: str) -> Any:
        """按 ID 查询单个实体"""

    def query_by_tags(self, tags: list[str], match_all: bool = True) -> list:
        """按 Tag 组合查询。match_all=True 要求全部匹配，False 任一匹配"""

    def list_all(self) -> list:
        """列出所有实体（调试 / 全量快照用）"""

    def snapshot(self) -> dict:
        """生成只读快照（给 AI Osiris / ContextAssembler）"""
```

### 2.2 WorldInstance

```python
class WorldInstance:
    """世界内容容器——所有 Registry 的注册表和生命周期管理器"""

    def __init__(self):
        self._registries: dict[str, ContentRegistry] = {}

    def register(self, registry: ContentRegistry):
        self._registries[registry.name] = registry

    def get_registry(self, name: str) -> ContentRegistry:
        return self._registries[name]

    # 便捷访问器（高频 Registry 直接暴露）
    @property
    def tags(self) -> TagRegistry: ...
    @property
    def maps(self) -> MapRegistry: ...
    @property
    def characters(self) -> CharacterRegistry: ...
    @property
    def items(self) -> ItemRegistry: ...
    @property
    def skills(self) -> SkillRegistry: ...

    def load_all(self, world_data: dict):
        """按依赖顺序加载：TagRegistry 最先，其他按注册顺序"""
        self._registries["tags"].load(world_data.get("tags", {}))
        for name, reg in self._registries.items():
            if name != "tags":
                reg.load(world_data.get(name, {}))

    def query_by_tags(self, tags: list[str], registry_name: str = None) -> list:
        """跨 Registry 的 Tag 查询。指定 registry_name 则只查该 Registry"""
        if registry_name:
            return self._registries[registry_name].query_by_tags(tags)
        results = []
        for reg in self._registries.values():
            results.extend(reg.query_by_tags(tags))
        return results
```

## 三、TagRegistry — Tag 分类体系（❶ 层最核心基础设施）

Tag 是所有实体的语义标签，是**跨层通用语言**。每一层都消费 Tag：

| 消费者 | 怎么用 Tag |
|--------|-----------|
| ❷ 规则引擎 | `FINESSE → 可用 DEX 攻击`；`UNDEAD → 治疗法术造成伤害` |
| ❸ 状态层 | 实体的 Tag 组合 = 身份描述 + 规则属性 |
| ❹ 战斗 AI | `场景中有 EXPLOSIVE？→ 评估引爆效用` |
| ⊕ AI Osiris | `偷了 SACRED 物品 → 推理宗教后果` |
| ❺ NPC Agent | `对方有 MERCHANT → 可以交易`；`HOSTILE → 拒绝对话`（详见 `叙事层设计规范.md` §四.4 NPC 工具集） |

### 4.2 遭遇概率公式

```
遭遇概率 = base_danger × period_multiplier

period_multiplier:
    DAWN  = 0.8
    DAY   = 0.5
    DUSK  = 1.0
    NIGHT = 1.5

danger_level → base_danger:
    low     = 0.05 (5%)
    medium  = 0.15 (15%)
    high    = 0.30 (30%)
    extreme = 0.50 (50%)
```

```python
CharacterTemplate = {
    id: str,                          # "merchant_tom"

    tags: list[str],                  # [NPC, MERCHANT, CIVILIAN, FRIENDLY]

    # === 语义描述（给 ❺ AI 叙事层） ===

    dialogue_style: str,              # "市侩精明，喜欢讨价还价，偶尔抱怨生意难做"
    background: str,                  # 背景故事
    secrets: list[str],               # 隐藏信息（只有高 trust 才会透露）

    # === 行为参数 ===

    # 记忆系统（自然生长模型——不预设层级，记忆深度随互动频率自然变化）

    # 互动越多的 NPC 积累的记忆越丰富，表现越像"深度角色"。
    # 运行时的资源分配（模型/thinking/上下文窗口）由 InstanceManager 动态管理，
    # 不在 ❶ 模板中硬编码。
    # 详见 `NPC与队友子系统设计规范.md` §三（InstanceManager）和 §四（双层认知）。

    # 日程
    schedule: dict[str, str],         # {period → location_id}
    # 例：{"dawn": "home", "day": "general_store", "dusk": "general_store", "night": "home"}

    # 关系初始值
    base_disposition: dict,           # {approval: 50, trust: 30, fear: 0, romance: 0}

    # 阵营归属
    faction_id: str | None,           # 所属势力 ID（引用 FactionRegistry）
}

Attack = {
    name: str,                        # "短剑攻击"
    hit_bonus: int,                   # 攻击加值
    damage_dice: str,                 # "1d6+2"
    damage_type: str,                 # slashing / piercing / bludgeoning / fire / ...
    range: int,                       # 格数
    tags: list[str],                  # [MELEE, SLASHING, SIMPLE]
}
```

### 5.2 自然生长记忆模型

> **不分层级，自然生长。** 不预设"路人/次要/核心"分类。
> 所有 NPC 都有记忆能力，记忆深度随互动频率自然变化。

| 方面 | 设计 |
|------|------|
| **双层认知** | 所有 NPC 共享同一套架构：层1 工作记忆（ContextWindow）+ 层2 记忆图谱（MemoryGraph） |
| **记忆积累** | 互动越多 → 图谱节点越丰富 → NPC 对玩家的认知越深 |
| **资源动态分配** | InstanceManager 根据互动频率 / 当前场景重要性动态分配模型和上下文窗口，不在模板硬编码 |
| **溢出机制** | 工作记忆达阈值 → 自动图谱化旧对话 → 释放 token |
| **淘汰策略** | 实例池 LRU 淘汰，淘汰前强制图谱化（记忆不丢失） |

**模板中不包含 tier 字段**——NPC 的"重要程度"是玩家用脚投票的结果，不是设计师预设的。

## 十、QuestRegistry — 故事里程碑图

> **设计演化**：QuestRegistry 不再存储详细任务模板（目标、奖励、投递方式），而是存储**故事里程碑**——主线骨架上的关键节点。
> 具体的中间任务由 NarrativePlanner 在运行时根据玩家行为动态生成。
> 隐喻：里程碑 = "价值"（固定），动态任务 = "价格"（随行为波动）。
> 详见 `NarrativePlanner设计规范.md`。

### 10.1 Schema

```python
class QuestRegistry(ContentRegistry):
    """故事里程碑注册表"""
    name = "quests"

    milestones: dict[str, StoryMilestone]
```

```python
StoryMilestone = {
    id: str,                          # "investigate_western_farm"
    name: str,                        # "调查西部牧场"
    tags: list[str],                  # [MAIN_QUEST, GOBLIN, INVESTIGATION, WESTERN_REGION]

    # === 故事定位 ===
    chapter_id: str,                  # 所属章节 "ch1_goblin_crisis"
    completion_value: int,            # 对章节完成度的贡献（5-30）
    sequence: int,                    # 章节内排序（10, 20, 30...）
    prerequisites: list[str],         # 前置里程碑 ID

    # === 叙事上下文（给 NarrativePlanner 的创作素材）===
    narrative_context: str,           # 故事背景描述（NarrativePlanner 据此生成动态任务）
    key_elements: list[str],          # 关键叙事元素（动态任务必须包含的要素）
    involved_npcs: list[str],         # 相关 NPC ID
    involved_locations: list[str],    # 相关地点 ID

    # === 达成判定 ===
    success_conditions: list[MilestoneCondition],
    failure_conditions: list[MilestoneCondition] | None,

    # === 失败后果 ===
    failure_fallback: str | None,     # 失败时的叙事走向描述

MilestoneCondition = {
    type: str,        # location_visited / flag_set / npc_talked / item_obtained / kill_count / time_elapsed
    params: dict,     # 条件参数
    optional: bool,   # 是否为可选条件
}
```

### 10.2 里程碑状态机（❸ QuestSlice 管理）

```
LOCKED → AVAILABLE → ACTIVE → COMPLETED
   │                    ↘ FAILED
   └── 前置里程碑完成时解锁
```

- `LOCKED`：前置里程碑未完成
- `AVAILABLE`：前置满足，NarrativePlanner 可以开始引导
- `ACTIVE`：NarrativePlanner 已生成相关动态任务，玩家正在推进
- `COMPLETED`：success_conditions 全部满足
- `FAILED`：failure_conditions 触发（如超时）

### 10.3 主线完成度阶段

| 阶段 | 触发 |
|------|------|
| 25% | 新区域/NPC 解锁 + 世界状态变化 + GM 叙述 |
| 50% | 重大转折 + 新势力介入 + 奖励 |
| 75% | 最终准备阶段 + 高潮前奏 |
| 100% | 章节完结 + 新章节开放 |

```python
    tags: list[str],                  # [FACTION, MERCHANT, URBAN, LAWFUL]

    # 核心属性
    alignment: str,                   # lawful / neutral / chaotic + good / neutral / evil
    influence_areas: list[str],       # 势力影响区域 ID

    # 行为规则（给 AI Osiris 做推理参考）
    behavioral_rules: list[str],
    # [
    #   "对偷窃行为零容忍，一旦发现会全城通缉",
    #   "重视契约精神，违约者会被列入黑名单",
    #   "对信誉良好的冒险者给予交易优惠",
    # ]

    # 与其他势力的初始关系
    faction_relations: dict[str, str],
    # {
    #   "temple_order": "allied",
    #   "thieves_guild": "hostile",
    #   "adventurer_guild": "neutral",
    # }

    # 关联 NPC
    leader_id: str | None,            # 领导者 NPC ID
    member_ids: list[str],            # 成员 NPC ID 列表
}
```

### 11.2 势力关系类型

| 关系 | 含义 | 好感度范围 |
|------|------|-----------|
| `allied` | 同盟 | 70 ~ 100 |
| `friendly` | 友好 | 30 ~ 69 |
| `neutral` | 中立 | -29 ~ 29 |
| `unfriendly` | 不友好 | -69 ~ -30 |
| `hostile` | 敌对 | -100 ~ -70 |

## 十二、LoreRegistry — 世界规则文本

### 12.1 Schema

```python
class LoreRegistry(ContentRegistry):
    name = "lore"

    entries: dict[str, LoreEntry]
    rules: dict[str, WorldRule]
```

```python
LoreEntry = {
    id: str,                          # "goblin_slayer_world_overview"
    title: str,                       # "世界概况"
    content: str,                     # 世界观描述文本
    tags: list[str],                  # [WORLD, OVERVIEW, LORE]
    scope: str,                       # global / chapter / area
    scope_id: str | None,             # 关联的 chapter_id / area_id
}

WorldRule = {
    id: str,                          # "theft_consequences"
    title: str,                       # "偷窃后果规则"
    description: str,                 # "边境小镇治安松散，小额偷窃可能不被追究..."
    tags: list[str],                  # [CRIME, ECONOMY, SOCIAL]
    scope: str,                       # global / area / faction
    scope_id: str | None,
    priority: int,                    # 优先级（冲突时高优先级覆盖低优先级）
}
```

### 12.2 用途

LoreRegistry 是 AI Osiris 的 `world_rules_context` 的**数据来源**。TickCoordinator 通过 ContextAssembler 从 LoreRegistry 中按当前场景提取相关规则：

```
ContextAssembler 组装 world_rules_context:
    1. 全局规则（scope == "global"）
    2. 当前章节规则（scope == "chapter", scope_id == current_chapter）
    3. 当前区域规则（scope == "area", scope_id == current_area）
    4. 相关势力规则（从 FactionRegistry 的 behavioral_rules）
    → 合并去重，按 priority 排序
```

### 12.3 查询 API

```python
class LoreRegistry(ContentRegistry):
    def get_lore(self, lore_id: str) -> LoreEntry: ...
    def get_rules_for_context(self, chapter_id: str, area_id: str, faction_ids: list[str]) -> list[WorldRule]:
        """按当前上下文获取相关世界规则"""
    def get_by_scope(self, scope: str, scope_id: str = None) -> list: ...
    def get_by_tags(self, tags: list[str]) -> list: ...
```

## 十三、❶ ↔ ❸ 模板-实例映射

| ❶ Registry | ❸ Slice | 关系 |
|-----------|---------|------|
| MapRegistry（区域模板） | AreaSlice（区域当前状态） | 模板提供 base_danger → 实例跟踪 danger_level 变化 |
| CharacterRegistry（NPC 模板） | RelationSlice（NPC 当前好感） | 模板提供 base_disposition → 实例跟踪好感度变化 |
| ItemRegistry（物品模板） | PlayerSlice（背包/装备） | 模板定义属性 → 实例跟踪谁持有、是否被偷 |
| MonsterRegistry（怪物模板） | —（战斗中临时实例化） | 模板定义属性 → 战斗引擎临时创建实例 |
| SkillRegistry（技能定义） | —（纯定义，无运行时状态） | ❷ 规则引擎直接读定义计算 |
| ClassRegistry（职业/种族） | PlayerSlice（玩家角色） | 模板定义成长路线 → 实例跟踪当前等级/特性 |
| QuestRegistry（故事里程碑） | QuestSlice（里程碑进度）+ NarrativePlanSlice（动态任务） | 里程碑定义故事骨架 → QuestSlice 跟踪里程碑状态，NarrativePlanner 动态生成中间任务 |
| FactionRegistry（势力定义） | RelationSlice（势力好感度） | 模板定义初始关系 → 实例跟踪好感度变化 |
| TagRegistry | —（纯定义） | 被所有 Registry 和所有层消费 |
| LoreRegistry | —（纯定义） | 被 AI Osiris 和 GM Agent 消费 |

**实例化流程**（新会话开始时）：

```
1. WorldInstance.load_all(world_data)     ← ❶ 加载完毕
2. StateContainer.init_from(world_instance):
     TimeSlice.init()                    ← day=1, slot=8 (08:00)
     PlayerSlice.init(class_template)    ← 从 ClassRegistry 获取起始值
     RelationSlice.init(char_templates)  ← 从 CharacterRegistry 获取 base_disposition
     QuestSlice.init(milestones)          ← 有前置的 LOCKED，无前置的 AVAILABLE
     FlagSlice.init()                    ← 空
     AreaSlice.init(area_templates)      ← 从 MapRegistry 获取 base_danger
     EventSlice.init()                   ← 空
     PartySlice.init()                   ← 空队伍
     SceneSlice.init()                   ← 空
```

## 十四、数据加载与生命周期

### 14.1 加载时序

```
服务启动
    │
    ▼
GameRuntime.init()
    │
    ├─ 加载世界数据文件（structured/ 目录下的 JSON）
    │
    ├─ WorldInstance.load_all(world_data)
    │     ├─ TagRegistry.load()        ← 最先加载（其他依赖它）
    │     ├─ MapRegistry.load()
    │     ├─ CharacterRegistry.load()
    │     ├─ ItemRegistry.load()
    │     ├─ MonsterRegistry.load()
    │     ├─ SkillRegistry.load()
    │     ├─ ClassRegistry.load()
    │     ├─ QuestRegistry.load()
    │     ├─ FactionRegistry.load()
    │     └─ LoreRegistry.load()
    │
    └─ WorldInstance 缓存为世界级单例（运行时不变）
```

### 14.2 数据来源

```
世界书提取管线
    │
    │  从 SillyTavern 世界书 JSON → 结构化数据
    │
    └─ 输出目录: TBD（新数据目录，待后续确定）
         ├─ tags.json               ← TagRegistry
         ├─ maps.json               ← MapRegistry
         ├─ characters.json         ← CharacterRegistry
         ├─ items.json              ← ItemRegistry
         ├─ monsters.json           ← MonsterRegistry
         ├─ skills.json             ← SkillRegistry
         ├─ classes.json            ← ClassRegistry（可能大部分手工编写）
         ├─ quests.json             ← QuestRegistry
         ├─ factions.json           ← FactionRegistry
         └─ lore.json               ← LoreRegistry
```

**哪些能自动提取，哪些需要手工**（留待管线设计时细化）：

| Registry | 自动提取 | 手工补充 |
|---------|---------|---------|
| TagRegistry | 提取时生成 Tag | 分类维度需要手工定义 |
| MapRegistry | 世界书中的地点和连接 | 精确旅行时间、遭遇表 |
| CharacterRegistry | NPC 性格/背景/对话风格 | 精确数值属性、战斗数据 |
| ItemRegistry | 物品名称/描述/Tag | 精确数值（伤害骰/AC/价格） |
| MonsterRegistry | 怪物名称/描述/类型 | 精确属性/技能/掉落表 |
| SkillRegistry | 有限（世界书中很少） | **大部分需要手工定义**（D&D SRD 对齐） |
| ClassRegistry | 无（非世界书内容） | **完全手工定义** |
| QuestRegistry | 世界书中的剧情钩子 | 精确目标/奖励/前置条件 |
| FactionRegistry | 世界书中的势力关系 | 行为规则需要手工完善 |
| LoreRegistry | 世界书中的设定文本 | 结构化规则需要手工提炼 |
