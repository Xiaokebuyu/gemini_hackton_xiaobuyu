# P26 — 等级墙 + 属性/物品存在感修复

## Phase 3：等级墙 + 日常任务引导（已完成，2026-03-12）

### 改动摘要

任务系统无等级限制导致缺少成长曲线。本次修复引入 `min_level` 等级门槛字段，确保高难度任务需要玩家达到一定等级方可接取，同时引导 Planner 为低等级玩家生成日常任务。

### 3-1：planner_create_quest 支持 min_level

**文件**：`app/game_core/rules/handlers/planner.py` — `_compute_create_quest()`

- 在 `quest_payload` 构建前提取 `min_level`（优先 `cmd.params.get("min_level")`，回退 `metadata.get("min_level")`）
- 用 `max(1, coerce_int(...) or 1)` 确保最小值为 1
- 将 `"min_level": min_level` 写入 `quest_payload` dict

### 3-2：board_accept_quest 加等级检查

**文件**：`app/game_core/rules/handlers/board.py` — `_compute_board_accept_quest()`

- 在 status 检查后读取 `quest_payload.get("min_level", 1)`
- 若 `min_level > 1` 且 `state.player.level < min_level` → 返回
  `ExecuteResult.error(f"player level {state.player.level} below quest minimum {min_level}")`

### 3-3：browse_board 展示等级信息

**文件**：`app/game_core/rules/handlers/board.py` — `_enrich_with_quest_status()`

- 读取 `state.player.level` 一次（`player_level`），fallback=1
- 在每条 enriched entry 中附加：
  - `"min_level"`: 从 `quest_payload.get("min_level", 1)` 提取
  - `"level_locked"`: `min_level > 1 and player_level < min_level`
- 无 quests slice 时两个字段均设保守默认（1 / False）

### 3-4：Planner 上下文 + Prompt 引导

**文件**：`app/game_core/orchestration/hooks/narrative_planner.py` — `_build_planner_context()` 末尾

- 新增两个 key：
  - `"player_level"`: `context.state.player.level`（无 player slice 时 fallback=1）
  - `"player_xp"`: `context.state.player.xp`（无 player slice 时 fallback=0）

**文件**：`app/narrators.py` — `_format_planner_context()`

- 在"Part 3: 玩家行为画像"的时间行之后插入：
  ```
  Player level: {level} (XP: {xp}, need {xp_for_next} for next)
  ```
  `xp_for_next = player_level * 1000`（与 PlayerSlice.add_xp 计算一致）

**文件**：`app/narrators.py` — `AgenticNarrativePlanner._SYSTEM_PROMPT`

- 在"进程引导原则"中追加第 6 条：
  ```
  6. 任务难度与等级匹配：
     - 查看 player_level，为低等级玩家创建日常任务（巡逻、采集、护送）
     - create_quest 时设置 min_level 匹配任务难度（日常=1，中级=2，高级=3+）
     - 任务奖励应包含合理 XP（简单=200, 中等=400, 困难=800）
     - 主线讨伐任务设 min_level=2，引导玩家先做日常升级
  ```

## Phase 2：攻击/伤害属性修正（已完成，2026-03-12）

**文件**：`app/game_core/rules/combat_units.py`

- 在 Stat helpers 区新增公开函数 `compute_attack_ability_mod(stats, attack_tags) -> int`

- 默认（无特殊 tag）→ STR modifier

## Phase 1：武器数据加载修复（已完成，2026-03-12）

### 问题

`combat_units.py:150-163` 从 `equipment["main_hand"]` 直接读 `hit_bonus`/`damage_dice` 等字段，但 `inventory.py` 的 `_compute_equip()` 只存 `{"item_id": "..."}` 到 equipment dict（这些字段根本不存在），导致所有玩家武器攻击默认为 hit_bonus=0, damage_dice="1d6"。

### 1-1：新增 `_build_weapon_attack_from_registry()`

**文件**：`app/game_core/rules/combat_units.py`

- 在 "Public builders" 分区前新增 `_PROPERTY_TO_TAG` 常量和 `_build_weapon_attack_from_registry(item_id, equipment_slot, world)` 函数
- 优先顺序：
  1. `world.items.get(item_id)` → `template.weapon_data` 提取 `damage_dice`, `damage_type`, `range`, `properties`
  2. 从 `properties`（lowercase）映射到 attack tags（uppercase）：finesse→FINESSE, ranged→RANGED 等
  3. range > 2 或有 RANGED property → 去掉 MELEE 改为 RANGED tag
  4. `hit_bonus` 始终设为 0（Phase 2 追加 ability_mod + prof_bonus）
  5. 无 world / registry 无此 item → fallback 到 equipment slot dict 字段

### 1-2：`build_player_unit` 签名变更

**文件**：`app/game_core/rules/combat_units.py`

- `build_player_unit(state, world=None)` 新增可选参数
- 调用 `_build_weapon_attack_from_registry()` 替换原有内联武器构建逻辑

### 1-3：更新 `build_player_unit` 调用方

**文件**：`app/game_core/rules/handlers/combat.py`

- `build_player_unit(state)` → `build_player_unit(state, world)`（world 已在方法参数中）

### 测试

新增 6 个测试，全部通过（`tests/test_combat_units.py` - `TestBuildPlayerUnitRegistry` class）：
- `test_weapon_damage_dice_from_registry` — equipment 只有 item_id → 从 registry 读取正确 damage_dice
- `test_finesse_tag_propagated` — FINESSE property → FINESSE tag 传播
- `test_ranged_weapon_gets_ranged_tag` — range>2 → RANGED tag, 去掉 MELEE
- `test_world_none_fallback_to_slot_fields` — world=None → 读 slot dict 字段（向后兼容）
- `test_item_not_in_registry_fallback_to_slot_fields` — registry 无此 item → 同上
- `test_unarmed_when_no_main_hand` — 无 main_hand → Unarmed Strike

### 注意事项

- `DEFAULT_ACTION_COMMAND_TYPES` 无需改动（`build_player_unit` 是纯工具函数，不是 command handler）
- `build_companion_unit` 无需修改（companion 的攻击从 CharacterTemplate.attacks 列表读，已是类型化数据）
- 现有测试 `test_build_player_unit_weapon`（weapon slot 含 damage_dice 字段）仍然通过，走 fallback 逻辑

## Phase 4：治疗骰子 + 消耗品效果（已完成，2026-03-12）

### 问题

1. `resolve_item_heal_amount()` 只读 `effect.params["amount"]`（int），但 items.json 用 `"dice": "2d4+2"` → 治疗药水始终治疗 0（None fallback）
2. 非治疗消耗品（解毒剂等，`effect.type == "buff"`）被当作 no_effect 丢弃，实际上应该生效

### 4-1：`resolve_item_heal_amount` 支持骰子表达式

**文件**：`app/game_core/rules/handler_utils.py`

- 在检查 `effect.type == "heal"` 后，优先读 `effect.params.get("dice")`
- 有 dice 字符串时调用 `roll_damage_dice(dice_str)` 返回掷骰结果
- fallback 到原来的 `effect.params.get("amount")` 静态值路径
- `roll_damage_dice` 已在同模块定义，调用时已解析，无循环依赖

### 4-2：`_compute_use_item` 支持 buff 效果

**文件**：`app/game_core/rules/handlers/inventory.py`

- 新增私有方法 `_try_buff_effect(item_id, item_template, state) -> ExecuteResult | None`
  - 检查 `consumable_data.effect.type == "buff"` 且 `effect.params.get("remove_status")`
  - 过滤 `player.active_effects`，移除匹配 `effect_id == remove_status` 的效果
  - 构建 StateChange("player", "set", "active_effects", next_effects) + inventory 消耗
  - metadata 含 `effect_type: "buff"`, `remove_status`, `removed_count`, `hp_delta: 0`
- 在 `_compute_use_item` 顶部调用 `_try_buff_effect`，非 None 时直接返回
- 新增顶层 import：`from app.game_core.content.registries.shared_types import Effect`

### 测试

新增 6 个测试，全部通过（`tests/test_inventory_handler.py` - `TestPhase4UseItem` class）：

- `test_dice_heal_minimum_one` — 骰子最小值=1，治疗量受 max_hp 上限约束
- `test_static_amount_fallback` — amount=8 静态值路径仍然正常
- `test_antidote_removes_poisoned_status` — buff/remove_status → 移除 poisoned，保留 bleeding
- `test_antidote_when_not_poisoned_still_consumes` — 玩家无中毒时解毒剂仍消耗（removed_count=0）
- `test_utility_effect_item_is_noop` — utility 类型效果 → no_effect，不消耗物品
