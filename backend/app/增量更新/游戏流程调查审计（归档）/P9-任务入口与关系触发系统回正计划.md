# P9-任务入口与关系触发系统回正计划

## Summary
- 目标是修正当前 live 世界里四条已经被代码审计确认的断链：
  1. 真实布告栏 `quest_board` 无法进入任务交互链
  2. `NarrativePlanner` 的默认投递目标仍停留在 shell world 假设
  3. `PrivateChatTriggerHook` 全局扫关系表，导致跨区域 NPC 乱入私聊
  4. `AIOsiris` 仍是 MVP 骨架，只做轻量 flag 记录，无法承担设计文档里的系统调度职责
- 本轮不做“全面重写任务系统”，而是先把真实世界中玩家能感知到的入口、投递、触发范围和最基本的系统编排拉回到文档约束。

## 当前问题
### 1. 任务入口模型错位
- live 世界中，布告栏是 `adventurer_guild` 里的 interactable，真实 id 是 `quest_board`。
- 前端当前点击可交互物，固定发送 `target_kind='object'` + `intent='examine'`。
- 后端交互策略只支持 `npc` / `board`，并把 `board_id` 当作“当前所在子地点 id”校验。
- 结果：
  - 场景里看得到委托板
  - 但点击不会进入 `board_snapshot`
  - 玩家感觉“任务没有接取入口”

### 2. NarrativePlanner 投递目标仍是 shell world 常量
- 默认 planner 仍硬编码：
  - `board_id='board'`
  - `npc_id='guild_clerk'`
- live 世界里当前真实场景对象是：
  - 子地点 `adventurer_guild`
  - interactable `quest_board`
  - 柜台 NPC `guild_girl`
- 当前会出现：
  - 任务已生成
  - bulletin 已写入
  - 但公告发往不存在/不可达的 `board`
  - directive 发往不在场或不存在的 `guild_clerk`
- 额外问题：`direct_npc` 当前允许空 `directive` 落库，会制造“NPC 好像接到任务，实际什么都没收到”的假象。

### 3. 私聊触发范围错误
- `PrivateChatTriggerHook` 当前按 `relations.npc_dispositions` 全量扫描，只看 romance/trust/stage/cooldown。
- 它不检查：
  - 当前区域
  - 当前子地点
  - NPC 是否在场
  - NPC 是否与当前 SceneBus 有接触上下文
- 结果：
  - 别处 NPC 会突然发起 `npc_wants_to_chat`
  - 关系系统看起来像“没有隔离”

### 4. AIOsiris 仍是骨架实现
- 默认 `BasicAIOsirisEvaluator` 当前只做两件事：
  - 记录最近一次 quest change chapter
  - 确认 `quest_started` flag
- 它还没有承担设计文档里预期的：
  - 社会反馈
  - 动态任务/线索推进
  - 区域级世界状态调度
  - 有意义的可见后果
- 结果：
  - hook 在链上，但用户体感接近“没工作”

## 本轮计划落地
### Phase A：打通真实布告栏入口
- 后端交互模型改成区分：
  - `board` 作为真实 interactable target kind
  - `board_id` 不再等同于 `current_location`
- `InteractionPolicyContext` 增加当前子地点下可见 interactables 快照。
- `validate_presence()` 对 `board` 改为：
  - 验证该 board/interactable 是否在当前 area + current_location 可达
  - 不再要求 `current_location == board_id`
- 前端 `GamePage.onInteractWith()` 识别 `quest_source` / `quest_board`，发送：
  - `target_kind='board'`
  - `intent='browse'`
  - `target_id='quest_board'`
- `board_snapshot`、`accept`、`complete`、`retire` 流程全部基于真实 `quest_board` 走通。

### Phase B：对齐 NarrativePlanner 的真实世界投递
- 去掉默认 planner 中的硬编码：
  - `board`
  - `guild_clerk`
- quest seeding 改成按 live world 数据解析：
  - 优先当前 area / 当前 location 下带 `quest_source` tag 的 interactable 作为 board target
  - 优先 milestone `involved_npcs`
  - 若无 involved NPC，再从当前场景的 guild staff / quest giver 角色里选
- `direct_npc` 增加强校验：
  - `directive` 不能为空 dict
  - 无法归一化时直接丢弃，不写入 `npc_directives`
- `present_quest` directive 要明确落到真实当前世界可见 NPC，例如 `guild_girl`。

### Phase C：收紧私聊触发范围
- `PrivateChatTriggerHook` 改成只评估“当前场景可触达 NPC”：
  - 当前 area
  - 如有 current_location，则优先当前 location
  - 至少要求 NPC 在 `AreaSlice.npc_locations` 中有有效在场位置
- 可选的第二层过滤：
  - 如果 NPC 从未建立过最小互动上下文，则不发起主动私聊
- 保留当前 romance/trust/stage/cooldown 规则，但不再跨场景广播。

### Phase D：把 AIOsiris 从骨架补到最低可用
- 第一轮不追求完整设计文档，只补最小有效行为：
  - quest 新建后，能够根据场景/区域写入合理的 flag 或轻量推进
  - 在 meaningful slices 变化后，产出至少一种对玩家可感知的后果
  - 让 `ai_osiris_applied` 不再长期是纯 flag 记账
- 目标是把它提升到“有最低产品意义”，不是一步做到完整社会模拟。

## 明确延后
- 完整 per-actor 社会图谱和关系隔离重构
- 完整 quest board 内容层 schema 升级
- 多 board / 多 guild / 多城市任务分发系统
- 完整 AI Osiris LLM 版 evaluator
- 前端任务面板全面重做

## 验收标准
### 任务入口
- 玩家在 `adventurer_guild` 点击 `quest_board` 可以打开 `board_snapshot`
- `BoardOverlay` 能看到由 planner 投递的 live 任务
- 点击“接受”会成功触发 `advance_quest`，状态从 `available -> active`

### 任务投递
- planner 生成的 bulletin 不再写到虚构 `board`
- planner 生成的 NPC directive 不再指向缺席 `guild_clerk`
- `npc_directives` 中不再出现空 `directive`

### 私聊范围
- 只有当前场景在场 NPC 才可能发出 `npc_wants_to_chat`
- 不在当前区域的 `cow_girl`、`priestess` 等不会再跨图乱入

### AIOsiris
- settlement 后在 quest/flags/relations/party 等 meaningful change 下，`AIOsiris` 至少能产生可验证的有效后果
- `ai_osiris_applied` 不再只是“记录一个内部 flag”这种近似无感行为

## 建议执行顺序
1. Phase A：任务入口打通
2. Phase B：planner 投递目标对齐
3. Phase C：私聊触发范围收紧
4. Phase D：AIOsiris 最低可用补强

## 备注
- 当前用户体感“任务系统坏了”主要不是因为任务没生成，而是因为：
  - planner 在生成
  - 但入口对象、布告目标、NPC 投递目标都和 live world 不匹配
- 当前用户体感“关系系统没隔离”主要不是因为关系值全局存储，而是因为：
  - `npc_wants_to_chat` 这种关系驱动事件没有做场景过滤
