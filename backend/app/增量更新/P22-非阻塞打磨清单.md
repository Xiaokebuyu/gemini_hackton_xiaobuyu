## 1. 目的

`P21` 收口后，`3.1-3.6` 的运行时主链已经基本打通。  
本清单用于记录后续“非阻塞但值得继续做”的打磨项，避免它们和主链修复、数据扩充混在一起。

这份文档是轻量 backlog，不是新的大执行计划。

---

## 2. 边界约束

后续所有打磨项继续遵守当前架构边界：

- `❶ 内容层` 只放静态模板事实，不放运行时现况
- `❸ 状态层` 是运行时现实的权威来源
- 应用层 / 面板层只做读模型组装，不新建真理源
- `❷ 规则引擎` 继续负责正式状态变更；如需受控例外，必须明确记录
- 不为了表现层便利再并行造一套 state / route / planner 旁路

换句话说：

- 可以打磨“怎么读”
- 可以收口“字段契约”
- 可以提升“planner 怎么选”
- 但不要把静态、动态、展示层职责重新搅混

---

## 3. 当前优先级

建议按下面顺序推进：

1. 读模型打磨
2. 数据契约收口
3. `ItemDesigner` 策略升级
4. 可观测性 / 维护性补强
5. 纯内容扩充

理由：

- 前两项成本低、收益直接，而且不会破坏主链
- 第三项会提高质量，但不影响“能不能玩”
- 第四项偏工程收益
- 第五项最容易无上限扩散，放最后

## 5. 建议的第一批打磨包

如果开始做非阻塞项，建议先用一个很小的工作包起步：

### WP-P22-A：读模型与奖励契约收口

范围：

- 已完成：
  - `C1` 奖励 schema 硬切
  - `C2` legacy alias 退役
  - `quest_history.kind` 统一
  - quest 读路径 normalize helper 收口
  - `R1` `/quests` 稳定排序
  - `R2` 奖励视图补 item 展示字段

不包含：

- `ItemDesigner` 策略升级
- 大规模内容扩充
- 新 route / 新 panel / 新 slice

完成标志：

- 奖励相关前端读模型不再依赖 legacy alias 才能读通
- `/quests` 和 `ask_reward` 的返回契约更稳定
- `WP-P22-A` 已关闭；读模型稳定化已完成，下一步转入 `I1 / I2`

### WP-P22-D：可观测性 / 合同 / 测试收口

范围：

- 已完成：
  - `O1` planner replay trace 子系统级摘要

  - `O5` focused tests 迁移

落地结果：

- 已新增：
  - `tests/test_planner_directive_contracts.py`
