# 本轮修复记录 (2026-03-05)

## 已修复问题

### Fix-1: LoreEntry 序列化崩溃
- **症状**：`TypeError: Object of type LoreEntry is not JSON serializable`
- **根因**：`pipeline.py` 把含有原始 dataclass 的 `assembled_context` 塞进 `PipelineResult.metadata`，
  然后 `gameplay.py:_build_action_result_event()` 把 `result.metadata` 原样放进 SSE payload，
  `json.dumps` 无法序列化 `LoreEntry` / `FactionTemplate` 等 dataclass 对象
- **修复**：从 `PipelineResult.metadata` 移除 `assembled_context`（无下游消费者）
- **文件**：`app/game_core/orchestration/pipeline.py` (line 120, 132)

### Fix-2: LLM 无响应（.env 未加载）
- **症状**：NPC 对话无 LLM 回复，`agent_svc is None`
- **根因**：`.env` 中有 `GEMINI_API_KEY`，但代码未调用 `load_dotenv()`，
  `os.environ.get()` 拿不到 key，`llm_provider = None`
- **修复**：在 `deps.py` 添加 `from dotenv import load_dotenv; load_dotenv()`
- **文件**：`app/deps.py` (line 9-11)

### Fix-3: Gemini thought_signature 丢失
- **症状**：`400 INVALID_ARGUMENT: Function call is missing a thought_signature`
- **根因**：`_parse_response()` 把 `thought_signature` 和 `function_call` 存在同一个 dict 的
  `raw_model_parts` 里，但 `_to_content()` 用 `elif` 链处理——匹配到 `function_call` 后
  跳过了同一 dict 里的 `thought_signature`
- **修复**：`_to_content()` 中提取 `sig = p.get("thought_signature")`，
  当 part 有 `function_call` 时同时设置 `part.thought_signature = sig`
- **文件**：`app/llm_gemini.py` (line 96-116)
