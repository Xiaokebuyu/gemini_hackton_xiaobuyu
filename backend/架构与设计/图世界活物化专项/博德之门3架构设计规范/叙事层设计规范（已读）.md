# ❺ AI 叙事层设计规范

创建时间：2026-02-26
状态：设计中
前置文档：`博德之门3架构深度分析.md` §二.❺ + §四.4，`规则引擎层设计规范.md`（Command 构造器目标），`状态层设计规范.md`（SceneSlice/RelationSlice），`编排层设计规范.md`（A/B/C 管线 + interact/private-chat 管线），`NPC与队友子系统设计规范.md`（InstanceManager + 双层认知）

> ❺ AI 叙事层 = 世界的"声音"。对已确定事实的文学化包装。
> GM/NPC/队友三种 Agent，通过传统工具调用与 ❷ 交互（工具 = Command 构造器）。
> **核心约束：❺ 不决定"发生什么"（那是 ❷ 的事），只决定"怎么说"。**

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **先执行后叙述** | ❷ 算完、❸ 已写入，然后 Agent 才叙述。叙述的是已发生的事实（P2） |
| **Agent 只通过 Command 操作世界** | 工具 = 构造 Command → ❷ 执行。不存在绕过 ❷ 的状态修改 |
| **传统工具调用** | Agent 使用 Gemini 原生 function calling，不走 MCP（核心循环无需跨进程） |
| **声明意图，不算机械** | Agent 说"我要说服守卫"，❷ 算 DC 和结果。Agent 不自己决定检定是否成功 |
| **权限由工具集约束** | 每种 Agent 只能看到自己权限内的工具，LLM 无法调用未暴露的工具 |

## 二、三种 Agent

### 2.1 总览

```
┌───────────────────────────────────────────────────┐
│ ❺ AI 叙事层                                       │
│                                                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐     │
│  │ GM Agent │  │NPC Agent │  │Teammate Agent│     │
│  │          │  │          │  │              │     │
│  │ 零写入   │  │ 角色权限 │  │ 角色权限     │     │
│  │ 纯叙述   │  │ 内操作   │  │ 内操作       │     │
│  └────┬─────┘  └────┬─────┘  └──────┬───────┘     │
│       │             │               │              │
│       │   ┌─────────┴───────────────┘              │
│       │   │                                        │

│   工具 = Command 构造器 → ❷ RulesEngine             │
│                                                    │
└───────────────────────────────────────────────────┘
```

### 2.2 Agent 职责对比

| | GM Agent | NPC Agent | Teammate Agent |
|---|---|---|---|
| **职责** | 环境叙述、场景描写、结算旁白、**玩家行为点评** | 角色对话、个性表达、角色权限内操作 | 队友对话、战术建议、营火互动 |
| **写入 ❸** | **无**（硬约束） | 通过 Command（仅限自身相关） | 通过 Command（仅限自身相关） |
| **输入** | narrative_hints + SceneBus + ❶❸ 快照 | SceneBus + 自身记忆 + ❶❸ 相关数据 | SceneBus + 自身记忆 + ❶❸ 相关数据 |
| **输出** | 叙述文本 + 点评文本 | 对话文本 + 可选 Command | 对话文本 + 可选 Command |
| **触发** | 每次引擎执行后、格结算后 | 玩家对 NPC 说话时 | 每次动作后（自主决定是否发言） |
| **何时 PASS** | 较少 PASS（场景无变化且无可评价内容时） | 不 PASS（被对话时必须回应） | 可以 PASS（不是每次都发言） |

### 2.3 GM Agent 人格——毒舌旁白者

GM 不是冷漠的全知叙述者，而是一个**有态度的旁白**——类似暗黑地牢的旁白、Stanley Parable 的叙述者。

**核心风格**：犀利、幽默、毒舌但不恶毒。对玩家的决策和操作给出有态度的点评。

**点评触发**（LLM 自主判断，非硬编码规则）：

| 触发场景 | 点评示例 |
|---------|---------|
| 明显不明智的决策 | *"好的，看来今天选择了速通路线。"* |
| 长时间犹豫不决 | *"又站在洞口发呆了。哥布林们已经开始猜你是不是迷路的旅行商人了。"* |
| 戏剧性/讽刺性的结果 | *"投资酒精产业，经典的冒险者理财策略。"* |
| 战斗中的糟糕表现 | *"那把剑可能更擅长在地上打滚。"* |
| 做了精彩操作 | *"哦？偶尔也会动脑子的嘛。"* |
| 重大剧情转折 | *"命运的齿轮转动了。至少这次不是向着悬崖的方向。"* |

**度的把握**（写入 GM 系统提示）：

| 原则 | 说明 |
|------|------|
| **毒舌不恶毒** | 朋友间的吐槽，不是恶意嘲讽。玩家应该觉得好笑，不是被冒犯 |
| **频率适度** | 不是每个动作都评价——平凡操作不点评，有趣/关键时刻才出口 |
| **只评不导** | 只评价已发生的事，不说"你应该这样做"（引导是 NarrativePlanner 的事） |
| **傲娇式认可** | 玩家做出精彩操作时，认可要"不情愿"——*"行吧，这次算你聪明。"* |
| **与叙述融合** | 点评和环境叙述穿插进行，不是割裂的两段文字 |

## 三、Agent 上下文——每种 Agent 看到什么

### 3.1 上下文层级模型

所有 Agent 共享一个分层上下文结构，但**每种 Agent 看到的范围不同**：

```
Layer 0: 世界常量       ← ❶ LoreRegistry（世界观、文化设定）
Layer 1: 章节状态       ← ❸ QuestSlice（当前章节进度）
Layer 2: 区域环境       ← ❶ MapRegistry + ❸ AreaSlice（当前区域描述、NPC、危险度）
Layer 3: 地点细节       ← ❶ MapRegistry.SubLocation（当前子地点的描述和互动对象）
Layer 4: 动态状态       ← ❸ 相关切片（角色状态、队伍、好感度、背包）
Layer 5: 场景总线       ← ❸ SceneSlice（格内所有动作的上下文）
Layer 6: 记忆召回       ← MemoryGraph 扩散激活检索（基于当前话题）
Layer 7: 引擎结果       ← ❷ narrative_hints（本次动作的机械结果）
```

### 3.2 各 Agent 可见范围

| Layer | GM Agent | NPC Agent | Teammate Agent |
|-------|----------|-----------|----------------|
| L0 世界常量 | ✅ 完整 | ✅ 完整 | ✅ 完整 |
| L1 章节状态 | ✅ 完整 | ❌ 不可见 | ⚠️ 部分（已知任务） |
| L2 区域环境 | ✅ 完整 | ✅ 当前区域 | ✅ 当前区域 |
| L3 地点细节 | ✅ 完整 | ✅ 当前地点 | ✅ 当前地点 |
| L4 动态状态 | ✅ 全局 | ⚠️ 自身 + 对玩家好感 | ⚠️ 自身 + 队伍 |
| L5 场景总线 | ✅ 全部条目 | ✅ 可见条目（visibility 过滤） | ✅ 可见条目 |
| L6 记忆召回 | ❌ GM 无个人记忆 | ✅ 自身记忆图谱 | ✅ 自身记忆图谱 |
| L7 引擎结果 | ✅ 完整 hints | ⚠️ 仅自身相关 | ⚠️ 仅自身相关 |

**GM 看得最全但不能写，NPC/队友看得有限但能做角色内操作。**

> NPC 的 ContextWindow 和 MemoryGraph 由 InstanceManager 管理，详见 `NPC与队友子系统设计规范.md` §三（实例池）和 §四（双层认知）。
> 四维好感度模型详见 `NPC与队友子系统设计规范.md` §五。

class AgentContextBuilder:

## 四、Agent 工具系统——Command 构造器

### 4.1 设计理念

Agent 的"工具"不是直接操作状态的函数，而是 **Command 构造器**：

```
旧模式：
  tool "heal_player" → 直接修改 ❸ player.hp

新模式：
  tool "heal_player" → 构造 Command(type="modify_hp", ...) → ❷ 执行 → delta → 调用方写 ❸
```

每个工具做三件事：
1. **参数校验**（LLM 输出的参数格式对吗？）
2. **构造 Command**（翻译为 ❷ 能理解的指令）
3. **调用 ❷ 并返回结果**

```python
class AgentTool:
    """Agent 工具基类——Command 构造器"""

    name: str                    # 工具名（LLM 看到的）
    description: str             # 工具描述（LLM 理解用途）
    parameters: dict             # 参数 schema（Gemini function calling 格式）
    allowed_roles: list[str]     # 哪些角色可用：["gm", "npc", "teammate"]

    def execute(self, params: dict, context: AgentContext) -> ToolResult:
        """
        1. 校验 params
        2. 构造 Command
        3. 调用 context.rules_engine.execute(command)
        4. 返回 ToolResult（给 LLM 看的执行反馈）
        """
```

### 4.2 AgentContext——工具执行环境

```python
class AgentContext:
    """传递给每个工具的执行环境"""

    role: str                    # "gm" / "npc" / "teammate"
    character_id: str | None     # NPC/队友的角色 ID（GM 为 None）
    rules_engine: RulesEngine    # ❷ 引擎引用
    state_snapshot: StateSnapshot # ❸ 当前快照
    world: WorldInstance         # ❶ 静态数据
    scene: SceneSlice            # 场景总线
```

### 4.3 GM 工具集

GM 的工具全部是**只读/叙述类**——不构造任何写入 Command。

| 工具 | 描述 | 做什么 |
|------|------|--------|
| `describe_environment` | 描述当前环境 | 读 ❶ 地点描述 + ❸ 状态，返回参考素材 |
| `narrate` | 输出环境/场景叙述 | 纯文本输出，不调 ❷ |
| `comment` | 对玩家行为的点评 | 毒舌旁白输出（见 §2.3 人格定义）。前端可用不同样式渲染 |
| `pass` | 本次不叙述也不点评 | 返回空。仅在场景无变化且无可评价内容时使用 |
| `suggest_options` | 生成玩家选项 | 输出结构化选项（含检定意图，见 §五） |

**GM 没有任何能构造写入 Command 的工具。这是架构硬约束。**

> `comment` 和 `narrate` 的区别：`narrate` 是客观环境叙述（*"壁炉的火光在墙壁上投下摇曳的影子"*），`comment` 是主观态度点评（*"又在酒馆坐了整整一天，哥布林表示感谢。"*）。两者可在同一轮中先后调用，也可只用其一。前端通过不同 SSE 事件类型区分渲染风格。

### 4.4 NPC 工具集

NPC 有叙述工具 + 角色权限内的 Command 构造器。

| 工具 | 描述 | Command | 权限约束 |
|------|------|---------|---------|
| `speak` | 说话（对话文本） | 无（写入 SceneBus） | — |
| `emote` | 表情/动作描述 | 无（叙述辅助） | — |
| `update_feeling` | 表达对玩家的感受变化 | `modify_disposition` | 仅自身好感度 |
| `remember` | 记住某件事 | `add_knowledge` | 仅自身记忆 |
| `offer_quest` | 委托任务 | `advance_quest`（→ DISCOVERED） | 仅自己能委托的任务 |
| `offer_trade` | 展示商品 | 无（只读展示） | 仅商人 NPC |
| `refuse` | 拒绝请求 | 无 | — |
| `reveal_secret` | 透露秘密信息 | `add_knowledge`（给玩家） | trust 阈值检查 |

### 4.5 Teammate 工具集

| 工具 | 描述 | Command | 权限约束 |
|------|------|---------|---------|
| `speak` | 说话 | 无（写入 SceneBus） | — |
| `emote` | 表情/动作 | 无 | — |
| `express_opinion` | 表达对事件的看法 | `modify_approval`（自身） | 仅自身审批值 |
| `suggest_tactic` | 战术建议 | 无（纯叙述） | — |
| `share_memory` | 回忆共同经历 | 无（从记忆图谱检索并叙述） | — |
| `request_action` | 请求玩家做某事 | 无（叙述 + 影响选项生成） | — |

### 4.6 工具注册——RoleToolRegistry

```python
class RoleToolRegistry:
    """按角色注册工具集"""

    def __init__(self):
        self._tools: dict[str, list[AgentTool]] = {
            "gm": [],
            "npc": [],
            "teammate": [],
        }

    def register(self, tool: AgentTool):
        for role in tool.allowed_roles:
            self._tools[role].append(tool)

    def get_tools_for(self, role: str, traits: list[str] = None) -> list[AgentTool]:
        """
        获取某角色可用的工具列表
        traits 用于条件过滤：如 is_merchant=True 才有 offer_trade
        """
        base = self._tools[role]
        if traits:
            return [t for t in base if t.matches_traits(traits)]
        return base

    def get_function_declarations(self, role: str, traits: list[str] = None) -> list[dict]:
        """转为 Gemini function calling 的 declarations 格式"""
```

## 五、对话选项生成

### 5.1 流程

对话选项是 **❺ Agent 声明意图 + ❷ 填充机械参数** 的协作产物：

```
Step 1: Agent 生成选项意图
    NPC/GM Agent 输出：
    {
      "options": [
        {"text": "让守卫通融",  "check": {"skill": "persuasion"}},
        {"text": "翻墙过去",    "check": {"skill": "athletics"}},
        {"text": "拔剑警告",    "action": "initiate_combat"},
        {"text": "算了，换条路", "action": "leave"}
      ]
    }

Step 2: 系统调 ❷ 填充机械参数
    对有 check 的选项：
      ❷ 根据场景计算 DC
      ❷ 根据玩家属性计算 bonus
      → 填入 DC 和成功率提示

Step 3: 玩家看到的选项
    [说服 DC14] 让守卫通融
    [运动 DC12] 翻墙过去
    拔剑警告
    算了，换条路

Step 4: 玩家选择 → 触发 Command
    点击 [说服 DC14]
    → Command(type="skill_check", params={skill:"persuasion", dc:14})
    → ❷ 执行（d20 + CHA_mod + proficiency vs DC14）
    → ExecuteResult { success, rolls, narrative_hints }
    → GM/NPC 叙述结果
```

### 5.2 选项类型

| 类型 | 格式 | 玩家选择后发生什么 |
|------|------|-----------------|
| **普通行动** | "拔剑警告" | 触发对应 Command（如 initiate_combat） |
| **能力检定** | "[说服 DC14] 让守卫通融" | Command(type="skill_check") → ❷ 掷骰 |
| **信息收集** | "仔细观察房间" | Command(type="skill_check", skill="perception") |
| **对话延续** | "追问关于那封信的事" | 玩家发言写入 SceneBus，NPC 继续对话 |
| **离开** | "结束对话" | 无 Command，退出对话模式 |

### 5.3 DC 计算规则

❷ 为对话选项计算 DC 时，考虑：

```
基础 DC = 场景难度基准（由 ❶ 定义或 Agent 建议）
修正 = NPC 好感度（高好感 → DC 降低）
     + 情境加成（有相关证据？→ DC 降低）
     + NPC 性格（固执 → DC 提高）

最终 DC = clamp(base + modifiers, 5, 25)
```

### 5.4 失败时的回退选项

如果 Agent 生成选项失败（LLM 输出格式错误 / 超时），回退到通用选项：

```python
FALLBACK_OPTIONS = [
    {"text": "继续探索", "action": "explore"},
    {"text": "和对方交谈", "action": "dialogue"},
    {"text": "查看周围环境", "check": {"skill": "perception"}},
    {"text": "离开这里", "action": "leave"},
]
```

## 六、Agent 执行流程

### 6.1 AgenticExecutor——统一 Agent 执行器

所有三种 Agent 共用同一个执行器，差异通过 role + tools 参数化：

```python
class AgenticExecutor:
    """统一 Agent 执行器"""

    async def run(self,
                  role: str,                    # "gm" / "npc" / "teammate"
                  character_id: str | None,     # 角色 ID
                  system_prompt: str,            # 系统提示
                  context: AgentContext,          # 执行环境
                  tools: list[AgentTool],         # 可用工具集
                  max_turns: int = 5,            # 最大工具调用轮次
                  ) -> AgentResult:
        """
        Agentic 循环：
        1. 组装上下文 → LLM
        2. LLM 可能输出文本 + 工具调用
        3. 执行工具调用（→ Command → ❷）
        4. 结果反馈给 LLM
        5. 重复直到 LLM 不再调用工具 或 达到 max_turns
        6. 返回最终文本 + 所有工具调用记录
        """

AgentResult = {
    text: str,                       # 最终叙述/对话文本
    tool_calls: list[ToolCallRecord], # 工具调用记录
    commands_issued: list[Command],   # 发出的 Command 列表
    deltas: list[StateDelta],        # 执行产生的状态变更
}
```

### 6.2 GM Agent 执行流程

```
引擎执行完毕（❷ → narrative_hints）
    │
    ▼
AgenticExecutor.run(role="gm", tools=gm_tools)
    │
    ├─ LLM 读取 narrative_hints + SceneBus + 全局状态
    ├─ LLM 决策（可组合，同一轮内可多次调用）：
    │   ├─ 场景有变化 → narrate 环境叙述
    │   ├─ 玩家行为值得点评 → comment 毒舌旁白
    │   ├─ 需要生成选项 → suggest_options → 输出选项意图
    │   └─ 场景平淡且无可评价内容 → pass
    │
    └─ 返回 AgentResult（叙述文本 + 点评文本，无 Command）
```

**常见组合模式**：
- `narrate` + `comment`：进入危险区域时描述环境，顺便吐槽玩家的装备
- 只 `comment`：玩家在安全区做了搞笑操作，不需要环境描述
- 只 `narrate`：纯场景切换，没有可评价的玩家行为
- `pass`：重复操作（第三次查看同一个箱子）

### 6.3 NPC Agent 执行流程

```
玩家对 NPC 说话 / SceneBus 有新内容
    │
    ▼
AgenticExecutor.run(role="npc", character_id="merchant_tom", tools=npc_tools)
    │
    ├─ LLM 读取 SceneBus + 自身记忆 + 性格 + 当前好感
    ├─ LLM 决策：
    │   ├─ 回应对话 → speak("好眼光，这把刀很锋利。")
    │   ├─ 好感变化 → update_feeling(dimension="approval", delta=5)
    │   │              → 构造 Command → ❷ 执行
    │   ├─ 记住某事 → remember("玩家买了匕首")
    │   │              → 构造 Command → ❷ 执行
    │   └─ 提供选项 → 输出对话选项意图
    │
    └─ 返回 AgentResult（文本 + 可能有 Command/Delta）
```

### 6.4 Teammate Agent 执行流程

```
每次动作后，队友依次决策
    │
    ▼
TeammateDecision: 先判断是否发言（response_tendency + 场景重要性）
    │
    ├─ 不发言 → PASS
    │
    └─ 发言 →
        AgenticExecutor.run(role="teammate", character_id="paladin", tools=teammate_tools)
        │
        ├─ LLM 读取 SceneBus + 自身记忆 + 队伍状态
        ├─ LLM 决策：
        │   ├─ 发表看法 → speak("这样做恐怕不太妥当...")
        │   ├─ 审批变化 → express_opinion(delta=-5)
        │   │              → 构造 Command → ❷ 执行
        │   └─ 回忆经历 → share_memory()
        │
        └─ 返回 AgentResult
```

## 七、与 Pipeline 的集成

> Agent 执行被编排到 A/B/C 三阶段和三条独立管线，详见 `编排层设计规范.md` §四（主管线）、§五（NPC 交互管线）、§六（私聊管线）。

### 7.1 格内动作的 Agent 调用顺序

```
玩家动作 → ❷ 执行 → narrative_hints
    │
    ▼
NPC Agent（如果正在对话）
    → 读 SceneBus + hints → 回应 + 可选 Command
    │
    ▼
GM Agent
    → 读 SceneBus + hints → 叙述 + 点评（场景平淡且无可评价内容时 PASS）
    │
    ▼
Teammate Agent（依次）
    → 读 SceneBus → 决定是否发言 → 发言 + 可选 Command
    │
    ▼
对话选项生成
    → Agent 输出选项意图 → ❷ 填充 DC → 推送给玩家
    │
    ▼
SSE 推送所有响应
```

### 7.2 格结算的 Agent 调用

```
TickCoordinator.tick_settlement()
    │
    ├─ AI Osiris 推理 → Command 列表 → ❷ 批量执行
    │
    ├─ 如有玩家可感知的变化：
    │   → GM Agent 叙述结算结果 + 可选点评
    │   → narrate: "夜风中似乎传来了一些窃窃私语，神殿区的气氛变得微妙起来..."
    │   → comment: "当然了，你在酒馆喝到失忆的时候，外面的世界可没闲着。"
    │
    └─ SceneBus 重置 → 进入新格
```

### 7.3 NPC 直接交互管线

```
POST .../interact/stream (SSE)
    │
    ├─ NPC Agent 回应（AgenticExecutor + npc_tools）
    ├─ GM 观察（默认 PASS，需要环境渲染时介入）
    ├─ Teammate 旁观（依次决策是否发言）
    ├─ 对话选项生成（Agent 意图 + ❷ 填充 DC）
    └─ 统一持久化
```

### 7.4 私聊管线——叙事行为设计

私聊是关系深化、秘密吐露、romance 展开的核心场景。

> **机械层**（进入条件、场景生成、上下文注入、秘密机制）见 `❺ NPC与队友运行时规范.md` §七。
> **编排层调度**见 `编排层设计规范.md` §六（PrivateChatCoordinator）。
> 本节只定义**叙事行为**——NPC 在私聊中怎么说话、什么语气、什么风格。

#### 7.4.1 公开交互 vs 私聊的叙事差异

| 维度 | 公开交互 | 私聊 |
|------|---------|------|
| **人格面具** | 维持社会角色（商人谈生意、骑士讲荣誉） | 面具松动——流露角色背后的真实想法 |
| **话题深度** | 任务/交易/世界信息为主 | 个人经历、内心感受、对玩家的真实评价 |
| **情感表达** | 克制、社会性（公众场合的礼貌/愤怒） | 更直接、更脆弱（卸下防备后的真实反应） |
| **秘密意愿** | 几乎不吐露（公众场合约束） | trust 门槛达到就可能吐露 |
| **romance** | 最多到暗示层面 | 实质性进展的主要场所 |
| **记忆引用** | 偏向世界知识、任务相关 | 偏向个人/共同记忆 |
| **语气** | 正式、角色化 | 更口语化、更真实、可能有犹豫和停顿 |

> 核心原则：私聊 ≠ 换个场景的公开对话。私聊是**关系的催化剂**——同样的话，NPC 在私聊中愿意说，在公开场合不会说。

#### 7.4.2 关系阶段 → 私聊语气

关系阶段定义见 `❺ NPC与队友运行时规范.md` §六。此处只描述每个阶段的**叙事表现风格**：

| 关系阶段 | 语气基调 | 对话示例 |
|---------|---------|---------|
| **相识** | 礼貌但有距离感，回避个人话题 | *"你找我有什么事吗？"* |
| **朋友** | 放松、愿意分享、会问玩家想法 | *"说实话，今天那个任务……我差点以为我们回不来了。"* |
| **挚友** | 坦诚、脆弱、不再逞强 | *"有时候我会想……如果当初没有离开家乡，现在会是什么样子。"* |
| **灵魂伴侣** | 无保留的信任、独特情感色彩 | *"只要你在，我觉得……什么都能撑过去。"* |

**负面阶段**：

| 关系阶段 | 语气表现 |
|---------|---------|
| **冷淡** | 敷衍、极简。*"嗯。""还有别的事吗？"* |
| **厌恶** | 讽刺、拒绝。*"我不觉得我们有什么好聊的。"* |
| **敌对** | 威胁、摊牌。*"你最好离我远一点。这是最后一次警告。"* |

#### 7.4.3 Trust 与对话深度

trust 决定 NPC 愿不愿意在你面前卸下防备。以下是**叙事表现**（数值阈值见运行时规范 §七.5）：

| trust 层级 | NPC 的叙事表现 |
|-----------|---------------|
| 闭锁 | 回避所有个人话题，用反问打太极。*"为什么突然问这个？"* |
| 表面 | 聊天气聊任务，个人话题一笔带过。*"我？没什么特别的。"* |
| 浅层 | 分享看法和喜好，但不涉及过去。*"我倒是挺喜欢这种安静的地方。"* |
| 中层 | 提及过去的片段，暗示内心矛盾。*"以前……也有人对我说过类似的话。"* |
| 深层 | 吐露秘密、恐惧、真正的动机。语速变慢，会有停顿和犹豫 |
| 无保留 | 只对玩家说过的话。可能带着释然、感激、或脆弱的微笑 |

#### 7.4.4 Romance 叙事表现

Romance 的实质性进展几乎只在私聊中发生。公开场合最多到暗示（眼神、脸红）。

| romance 阶段 | 叙事表现 |
|-------------|---------|
| 无感 | 纯粹友谊语气，无暧昧成分 |
| 在意 | 不自觉的关心。*"你……小心点。"*（说完自己也愣了一下） |
| 心动 | 紧张、找借口接近。*"我只是……想确认你没受伤。"* |
| 倾心 | 试探、醋意。*"你对那个人……挺上心的？不，没什么。"* |
| 挚爱 | 直接表达感情。风格因性格而异——战士型直接、学者型含蓄、害羞型迂回 |

**叙事约束**：`romance > 60` 但 `trust < 40` 时，NPC 表现为暗恋但不敢说——内心戏多，言语上却刻意保持距离。这种"想说又不说"本身就是精彩的叙事张力。

#### 7.4.5 GM 在私聊中的角色

默认：**GM 不介入**——私聊的亲密感来自于只有两个人在场。

**例外——稀有内心旁白**（玩家内心独白，非旁白者视角）：

| 触发时机 | 内心独白示例 |
|---------|------------|
| 首次私聊 | *（你意识到这是你第一次和她单独说话。莫名有点紧张。）* |
| NPC 吐露重大秘密 | *（她从来没有对任何人说过这些。你能感受到这份信任的分量。）* |
| romance 转折 | *（你的心跳似乎快了一拍。也可能是两拍。）* |
| 关系降级 | *（空气突然变冷了。你知道这段关系可能再也回不去了。）* |

> 使用 `gm_comment` SSE 事件（tone = `"introspective"`），前端用柔和斜体渲染，区别于毒舌旁白。

## 八、自然生长记忆系统与 ❺ 的关系

### 8.1 记忆注入流程

```
NPC Agent 被调用时：
    │
    ├─ 1. 从 SceneBus 提取当前话题关键词
    ├─ 2. 扩散激活检索 MemoryGraph → 相关记忆节点
    ├─ 3. 记忆节点注入系统提示（L6 层）
    ├─ 4. LLM 生成回应（自然融入记忆）
    │
    └─ 对话结束后：
        ├─ 新对话写入工作记忆（ContextWindow）
        └─ 工作记忆达阈值 → MemoryGraphizer 自动图谱化
```

### 8.2 记忆影响叙事

NPC 的记忆直接影响对话质量：

| 记忆深度 | 对话表现 |
|---------|---------|
| 无记忆（首次见面） | 通用问候，不认识玩家 |
| 浅记忆（几次交互） | 记得名字，知道大致来历 |
| 深记忆（频繁互动） | 引用过往经历，个性化反应，情感丰富 |

这就是"自然生长"——NPC 不需要 tier 标签，记忆深度自然决定了角色表现深度。

> 完整的记忆系统设计（三层图谱 + 图谱化管线 + 扩散激活参数）详见 `NPC与队友子系统设计规范.md` §四 和 §十二。

## 九、SSE 事件格式

Agent 的输出通过 SSE 推送给前端：

| 事件类型 | 内容 | 来源 |
|---------|------|------|
| `gm_narration` | GM 环境/场景叙述文本 | GM Agent `narrate` |
| `gm_comment` | GM 毒舌点评文本（前端可用不同样式渲染，如斜体/不同颜色） | GM Agent `comment` |
| `npc_response` | NPC 对话文本 + 情感标签 | NPC Agent |
| `teammate_response` | 队友对话文本 + 情感标签 | Teammate Agent |
| `dice_roll` | 骰子结果（d20 动画用） | ❷ ExecuteResult.rolls |
| `state_change` | 状态变化摘要（HP/金币/好感） | ❷ ExecuteResult.delta |
| `dialogue_options` | 对话选项列表（含 DC） | 选项生成流程 |
| `engine_action` | 引擎执行摘要 | ❷ narrative_hints |
