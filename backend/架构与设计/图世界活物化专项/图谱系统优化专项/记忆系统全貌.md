# 记忆系统全貌（代码对齐版）

> 更新时间：2026-02-22  
> 维护者：Codex（GPT-5 coding agent）  
> 核验基线：当前工作区代码

---

## 一、一句话结论

当前记忆系统已经形成可运行闭环：

1. 读链路：`recall_experience` → `SessionRuntime.recall()` → `WorldGraphRecallOrchestrator` → `SpreadingActivation`
2. 写链路A：`form_impression` / `create_memory` → `SessionRuntime.record_memory()` → `WorldGraph`
3. 写链路B：上下文窗口超阈值 → `MemoryGraphizer.graphize()` → `WorldGraph`（NPC 实例窗口 + SessionHistory 窗口）
4. 存档链路：`SessionRuntime.persist()/restore()` 负责 `WorldGraph` 快照写入/恢复

## 二、三层职责（当前实现）

| 层级 | 关键文件 | 当前职责 |
|------|----------|----------|
| L1 Agent 层 | `app/world/immersive_tools.py`, `app/world/role_registry.py`, `app/world/agentic_executor.py` | 向 LLM 暴露记忆工具（`recall_experience` / `form_impression` / `create_memory`） |
| L2 中层门面 | `app/runtime/session_runtime.py`, `app/services/admin/pipeline_orchestrator.py` | 统一读写 API、权限校验、图谱化触发编排、统一持久化 |
| L3 底层记忆核 | `app/world/world_graph.py`, `app/world/recall.py`, `app/world/spreading_activation.py`, `app/services/memory_graphizer.py` | 内存图容器、扩散召回、图谱化合并算法 |

主链路里，旧 `app/services/admin/recall_orchestrator.py` 与 `app/services/memory_graph.py` 已不是在线记忆主路径。

## 三、读链路（Recall）

### 3.1 工具入口

`recall_experience(seeds)` 在工具层调用：

- `ctx.session.recall(role=ctx.role, actor_id=ctx.agent_id, seeds=..., intent_type="recall")`

此外，机械意图链路 `IntentExecutor` 在进入子地点时也会调用 `session.recall(...)` 生成系统提示信息。

### 3.2 SessionRuntime 门面

`SessionRuntime.recall()` 当前行为：

1. `world_graph` 不可用则返回空
2. 构造 `WorldGraphRecallOrchestrator`
3. 按角色执行 `recall_for_role`
4. 对激活结果排序并裁剪 `limit`
5. 富化为 `{node_id, name, summary, type, relevance}` 返回

### 3.3 WorldGraphRecallOrchestrator 行为

- 意图模板：`RECALL_CONFIGS`（`exploration/dialogue/recall/combat/...`）
- 角色种子扩展：
  - `npc`：`[character_id] + seeds`
  - `teammate`：`[character_id, "camp"] + seeds`
  - `gm`：仅 `seeds`
- 前缀扩展：自动补全 `person_/character_/location_/area_` 变体
- 好感偏置：读取角色节点 `state.dispositions[*].approval`，把种子初值调整到 `0.5~1.0`
- 过滤：排除 `properties.placeholder=true` 节点

### 3.4 扩散激活（WorldGraph 版）

`app/world/spreading_activation.py` 的关键规则：

1. 前向 + 反向传播（反向系数 `0.7`）
2. 跨视角衰减 `perspective_cross_decay=0.5`
3. 跨章节衰减 `cross_chapter_decay=0.4`（camp 例外）
4. 跨 owner 衰减 `cross_owner_decay=0.3`
5. Hub 惩罚 + 因果边保底信号
6. 达到收敛阈值提前停止

## 四、写链路（Record Memory）

### 4.1 工具入口

- `form_impression(...)`：全角色可调用，底层走 `session.record_memory(memory_type="impression")`
- `create_memory(...)`：GM 工具，底层走 `session.record_memory(memory_type="memory")`

### 4.2 SessionRuntime.record_memory()

统一写入门面流程：

1. 检查 `world_graph` 可用
2. 执行角色级权限校验
3. 校验 `owner_id` 存在
4. 规范化 `memory_type`、`node_id`、`importance`
5. 创建 `WorldNode`
6. 添加 `owner -> memory` 的 `has_memory` 边

### 4.3 当前权限矩阵

| 角色 | 可写类型 |
|------|----------|
| GM | 全部 |
| NPC | `impression` |
| 队友 | `impression`, `memory_event` |

## 五、图谱化双闭环

## 5.1 闭环A：NPC 实例工作记忆（InstanceManager）

入口在 NPC 对话链：

- `FlashCPUService._npc_dialogue_with_instance()`
  - 用户消息加入 `context_window`
  - 助手消息加入 `context_window`
  - 任一侧 `add_message(...).should_graphize=True` 时触发 `maybe_graphize_instance(...)`

`InstanceManager.maybe_graphize_instance()` 当前行为：

1. 加锁取实例
2. 检查 `ContextWindow.check_graphize_trigger()`
3. 组装 `GraphizeRequest`
4. 调 `MemoryGraphizer.graphize(request, world_graph=...)`
5. 标记并清理已图谱化消息，回收 token

注意：若 `world_graph is None`，实例图谱化会被跳过（debug 日志）。

## 5.2 闭环B：SessionHistory 主会话窗口

主 Pipeline 三条路径都已在持久化前触发：

- `process()`
- `process_interact_stream()`
- `process_private_chat_stream()`

统一走 `PipelineOrchestrator._maybe_graphize_session_history()` → `history.maybe_graphize(...)`。

### 5.3 MemoryGraphizer 现状

`MemoryGraphizer.graphize()` 关键点：

1. **必须传 `world_graph`**（未传则返回失败）
2. 获取已有节点上下文：角色记忆最多 30 + 世界上下文最多 20
3. LLM 提取结构化元素：`event_group/sub_events/new_nodes/edges/state_updates`
4. 合并到 WorldGraph（同步内存写入）
5. LLM 失败时走最小 fallback 提取，确保不丢记录

当前合并关系要点：

- `owner -> event_group`：`has_memory`
- `event_group -> sub_event`：`contains`
- 参与者关系：`participated`
- 地点关系：`located_in`（目标节点存在时）

## 六、WorldGraph 容器现状

### 6.1 记忆相关节点类型

`event_group`, `memory_event`, `impression`, `knowledge`, `rumor`, `memory`

### 6.2 记忆相关索引

- `_owner_index`：owner → memory nodes
- `_name_index`：name.lower() → nodes
- `_day_index`：game_day → nodes
- `_participant_index`：participant → nodes
- `_edge_id_index`：edge_key → (src, tgt, key)

### 6.3 快照

- 写入：`SessionRuntime._persist_world_graph_snapshot()`
- 恢复：`SessionRuntime._restore_world_graph_snapshot()`
- Firestore 路径：`worlds/{wid}/sessions/{sid}/world_snapshot/current`

## 七、Firestore I/O 真相（按当前代码）

不是“全程零 I/O”，而是“回合内记忆计算在内存，存档与部分历史仍走 Firestore”。

| 模块 | I/O 行为 | 说明 |
|------|---------|------|
| `SessionRuntime` | WorldGraph 快照读写 | 会话级存档/恢复 |
| `SessionRuntime.persist()` | `metadata.admin_state` 写入 | GameState 同步到 session 文档 |
| `SessionHistory` | 消息 fire-and-forget 写入 | 每轮历史会写入 `messages` 子集合 |
| `SessionHistoryManager` | 首次读取历史 | `get_or_create()` 时从 Firestore 回放 |
| `InstanceManager` | NPC profile/state 读写 | 实例创建读取，实例 persist 写回 |

## 九、当前差异与待补齐项

### 9.1 已完成的关键收口

1. Player 持久化无 fallback（快照失败保留脏标记）
2. 队友生成无 agentic→simple fallback
3. SessionHistory 图谱化触发点已补齐到三条 Pipeline 主路径
4. NPC 实例持久化接口统一为 `instance.persist()`（不再外部传 `graph_store`）

### 9.2 仍需关注的点

1. `SessionRuntime` 的“首次知识加载”依赖 `_graph_store` 注入；当前主 Pipeline 初始化未注入该依赖，默认会走“跳过知识加载”分支
2. `ContextWindow.build_context_with_injection()` 仍在，但不是当前主管线记忆注入主路径（当前主路径由工具调用实时召回）
3. `SessionRuntime.graphize_messages()` 已可用，但当前主链路仍主要由 `InstanceManager` / `SessionHistory` 触发图谱化
