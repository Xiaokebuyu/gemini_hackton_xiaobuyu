## 设计哲学：渐进深入，每段闭合

经过 Planner 域全量代码审计，核心发现：**基础设施已经过度完善（23 directive 全链路、三层任务自动完成、6步NPC管线、7层上下文组装），问题不在管道而在管道里流的东西。** 改动分布：prompt重写~50%、schema/数据~25%、代码逻辑~15%、新增模块~10%。

因此采用**渐进深入**策略：每段都是闭合可验证的，段一效果够好就不急做段二，段二跑通就按需拣选段三。

```
段一（调频层）──→ 验收 ──→ 效果够？停。不够 ↓
段二（手术层）──→ 验收 ──→ 效果够？停。不够 ↓
段三（完善层）──→ 验收
```

## 段一：调频（Prompt + 微量代码）

**目标**：不改架构，用最小代码改动获取最大体验提升。

**核心假设**：当前系统的机械设施已经够用，体验问题主要来自 prompt 基调不对 + 好感变化失控 + NPC 对话缺乏关系分层。

### 1a: UpdateFeelingTool delta 钳位

**改什么**：`narrative/character_tools.py` 中 UpdateFeelingTool 的 delta 参数。
**怎么改**：硬校验 clamp — approval [-3,+3], trust [-2,+2], romance [-1,+2]。超范围 clamp + 日志警告。
**为什么最先做**：当前 LLM 可能一次对话 +15 approval，直接从 stranger 跳到 friend，所有后续关系分层都没意义。几行代码，堵住最大漏洞。

### 1b: NPC prompt 注入关系阶段对话指引

**改什么**：`narrative/context_builder.py` 中 NPC system prompt 组装逻辑。
**怎么改**：根据当前 relationship_stage 注入分层对话指引：
- stranger → 客套公事，不透露私事，称呼正式
- acquaintance → 可闲聊日常，但保持适当距离
- friend → 主动聊私事，分享心情，称呼亲切
- close_friend → 更深层话题，可提及过去和秘密
- intimate → 最坦诚，语气亲密

同时检测 CharacterTemplate 是否有 values/likes/dislikes 字段，有则注入（数据没就位时跳过，不报错）。

### 1c: GM prompt 日常氛围化

**改什么**：`app/narrators.py` 中 AgenticGmNarrator 的 system prompt。
**怎么改**：
- 基调从"dark-fantasy冒险叙述"改为"日常生活氛围描写"
- 注入时间段（dawn/day/dusk/night）差异化描写指引
- 读取 NPC blackboard.mood 融入场景描写
- 控制输出长度（2-4句，不要长篇大论）

### 1d: Planner prompt 日常向微调

**改什么**：`app/narrators.py` 中 AgenticNarrativePlanner._SYSTEM_PROMPT。
**怎么改**：不重写，微调：
- 升级阶梯 L0-L5 的描述从冒险向改为日常向
- 强化"任务驱动一切"原则（任务把玩家带到正确地点和人面前）
- 增加日常任务模板引导（帮忙修围栏、采药、送货，不是讨伐/清剿）
- direct_npc 优先级提高，让 NPC 更主动

### 1v: 实跑验证

**做法**：启动实际 LLM session，走最小循环：
- Planner 产出 directive → 是否有效？
- NPC 对话 → 好感变化是否在合理范围？对话深度是否随阶段分层？
- GM 叙述 → 风格是否日常化？

**验收标准**：
- [ ] UpdateFeelingTool delta 被正确钳位（日志可验证）
- [ ] NPC 对话中能感受到 stranger vs friend 的明显差异
- [ ] GM 叙述从"阴暗奇幻冒险"变为"日常生活氛围"
- [ ] Planner 产出的任务偏向日常（非纯战斗）
- [ ] 现有测试基线全通过

**涉及文件**（完整清单）：
- `app/game_core/narrative/character_tools.py` — delta 钳位
- `app/game_core/narrative/context_builder.py` — 关系阶段指引注入
- `app/narrators.py` — GM prompt + Planner prompt 微调

**预估改动量**：~100 行代码改动 + prompt 文本修改

## 段二：手术（Schema 重构 + 剧本系统）

**前置**：段一完成且验收通过。段一验收中发现的实际问题校准段二优先级。

**目标**：Clue 系统可靠化 + 剧本驱动叙事上线。

### 2a: Clue 简化

从"2~4 选项 × 三分支 outcomes"简化为"base_effects（必定触发）+ 可选 check（额外收益）+ narrative（上下文注入）"。

**涉及模块**：
- `game_core/clue_investigation.py` — schema 重定义
- `rules/handlers/clue.py` — ClueHandler 重写
- `planning/world_builder.py` — `_translate_environmental_clue_payload()` 适配
- `planning/directive_contracts.py` — fill_location clue 校验适配
- `app/agent_orchestration.py` — clue 调查后反应链适配

### 2b: 剧本生成器

MilestoneOutlineGenerator 从"5-10 step 大纲"升级为"~8000字完整剧本"。

**涉及模块**：
- `app/narrators.py` — MilestoneOutlineGenerator prompt + 输出解析
- `state/slices/narrative_plan.py` — 新增 milestone_script / current_act / script_progress 字段

### 2c: Planner prompt 重构

从"观察世界 → 自由决策"改为"读剧本 + 读进度 → 对照执行"。

**涉及模块**：
- `app/narrators.py` — AgenticNarrativePlanner._SYSTEM_PROMPT 重写
- `orchestration/hooks/narrative_planner.py` — `_build_planner_context()` 注入剧本和进度

### 2d: 检定效果梯度

skill_check 支持 margin 分级（excellent/good/poor/bad），检定不决定"能不能"而是调节"好不好"。

**涉及模块**：
- `rules/handlers/skill_check.py` — margin 等级
- `rules/handlers/clue.py` — check 结果分级

### 2v: 验收

- [ ] 新 schema clue 通过 plant_environmental 正确创建
- [ ] 调查 clue → base_effects 必定触发 + check 效果分级
- [ ] LLM 生成完整剧本 → 存入 NarrativePlanSlice → Planner 参照执行
- [ ] 完整走通一个里程碑的剧本流程
- [ ] 现有测试基线全通过 + 新增测试覆盖

## 段三：完善（全域补漏 + 内容 + 高级特性）

**前置**：段二核心循环跑通。

### 3a: 全域验证性扫描

快速过 04-任务 / 06-世界 / 07-LLM / 08-Tick / 10-基础设施 / 11-玩家经济，确认无遗漏。

### 3b: 开场序列改造

角色创建 + 来镇理由 → LLM 生成第一份剧本 → 执行第一幕 → 进入游戏。

### 3c: NPC 角色数据手写

16 个 NPC 补充 values/likes/dislikes/romance_triggers/turn_offs/gift_preferences/npc_relationships。
必须手写，不可 LLM 生成。

### 3d: 新增功能（按需拣选）

| 优先级 | 项目 | 实现方式 |
|--------|------|---------|
| 高 | 天气系统 | set_flag("weather") + GM/NPC prompt，零新代码 |
| 高 | 场景记忆 | flags["visited_xxx"] + GM 区分首次/回访 |
| 高 | 情绪染色 | GM 读取最近关系变化染色场景描写 |
| 高 | 关键记忆钉住 | blackboard.pinned_memories 不参与 cap=10 轮换 |
| 中 | 送礼机制 | 新增 ReceiveGiftTool + gift_preferences 匹配 |
| 中 | NPC 主动送礼 | Planner 按关系阶段安排 + grant_item |
| 中 | 玩家的家 | fill_room 创建宿舍 + Planner 剧本固定场景 |
| 低 | 废弃私聊系统 | 统一走 NpcInteractionCoordinator |
| 低 | 小镇口碑 | reputation_level flag + NPC 态度分级 |
| 低 | 恋爱竞争感 | Planner ripple 机制 |

### 3v: 验收

端到端完整体验：角色创建 → 剧本生成 → 日常任务 → NPC 交互 → 关系发展 → 里程碑完成。
