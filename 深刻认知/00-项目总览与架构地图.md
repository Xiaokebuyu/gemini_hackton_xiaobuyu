## 一、项目定位

**类博德之门 3 的 AI CRPG 后端引擎**，以 Google Gemini 为 LLM 核心，实现：
- 纯 Python 六边形内核（零外部依赖，~160 模块）
- 多角色 AI Agent 系统（GM / NPC / Teammate）
- 实时 SSE 流式输出 + React 前端
- D&D 5e 规则子集（战斗 / 施法 / 成长 / 经济）

### Tick 生命周期（核心主循环）

```
Player Input
    │
    ▼
ActionDispatcher.dispatch(input)
    │ → Command
    ▼
RulesEngine.execute(command)
    │ → StateDelta
    ▼
StateContainer.apply(delta)        ← 原子状态变更
    │
    ▼ (每当 accumulated_time >= 1.0)
SettlementHooks 优先级链 P10→P90
    ├─ P30: AIOsiris (因果判定)
    ├─ P35: NarrativePlanner
    ├─ P40: Encounter
    ├─ P50: Relationship
    ├─ P60: NpcSchedule
    ├─ P75: PrivateChatTrigger
    └─ P90: GmNarration (LLM)
    │
    ▼
SSEPresentationPort → 累积 events → flush to HTTP stream
```

## 四、技术栈速查

### 后端
- **语言**: Python 3.13
- **框架**: FastAPI + uvicorn
- **LLM**: Google Gemini Flash (gemini-3-flash-preview)
- **图数据库**: NetworkX (内存知识图谱)
- **持久化**: 本地 JSON / Firebase Firestore（可切换）
- **测试**: pytest, ~1291 passed

### 前端
- **语言**: TypeScript
- **框架**: React
- **状态**: Zustand (12个 store)
- **样式**: Tailwind CSS
- **实时通信**: SSE (Server-Sent Events)

## 五、核心设计原则

1. **六边形架构** — game_core 零外部依赖，外部能力通过 Port Protocol 注入
2. **不变状态 + StateDelta** — 所有状态变更描述为 delta，原子应用，可审计可回放
3. **Settlement Hook 链** — 新功能 = 在合适优先级插入一个 Hook，不改核心
4. **LLM 可降级** — 每个 LLM 集成点都有确定性 fallback，无 API KEY 游戏正常运行
5. **59 命令类型** — 玩家所有行为统一为 Command，集中分发，易于扩展
6. **L0–L7 上下文装配** — 按需最小化构建 LLM context，节省 token，保持相关性
