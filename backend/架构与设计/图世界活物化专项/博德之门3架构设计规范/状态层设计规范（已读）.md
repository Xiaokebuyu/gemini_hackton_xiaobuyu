> ❸ 状态层 = 游戏世界的"当前现实"，所有系统读写的唯一真理来源。
> 采用 **State Slice 注册制**：每个子系统拥有并管理自己的状态切片，状态层是容器 + 注册表。

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **唯一真理** | 所有系统读写同一份状态，不存在分裂（P3） |
| **切片自治** | 每个子系统拥有自己的切片，定义 schema + read/write API |
| **持续可扩展** | 新增子系统 = 新增切片 + 注册，零侵入现有代码 |
| **权限隔离** | L2 按角色暴露切片的不同访问级别（只读 / 角色权限写 / 完整写） |
| **机械确定性** | 状态变更只通过 ❷ 规则引擎或引擎验证后的指令，AI 不能直接写 |

## 二、整体架构：StateContainer + Slice 注册表

```
StateContainer（状态容器，会话级单例）
    │
    │  职责：
    │  - 持有所有已注册切片的引用
    │  - 统一生命周期（restore / persist / snapshot）
    │  - 提供跨切片查询接口（给 ContextAssembler 用）
    │  - dirty tracking 汇总
    │
    │  接口：
    │  - get_slice(name) → Slice
    │  - snapshot() → 全局快照（给 AI Osiris 用）
    │  - restore(session_data) → 从持久化数据恢复所有切片
    │  - persist() → 遍历所有切片，持久化 dirty 数据
    │  - register(name, slice) → 注册新切片
    │
    ├─ TimeSlice
    ├─ PlayerSlice
    ├─ RelationSlice
    ├─ QuestSlice
    ├─ FlagSlice
    ├─ AreaSlice
    ├─ EventSlice
    ├─ PartySlice
    ├─ SceneSlice
    ├─ NarrativePlanSlice          ← NarrativePlanner 规划状态（详见 `NarrativePlanner设计规范.md` §七）
    └─ ... 未来扩展
```

### 2.1 Slice 基类

每个切片实现统一接口：

```python
class StateSlice(ABC):
    """状态切片基类"""

    @property
    @abstractmethod
    def name(self) -> str:
        """切片名称，用于注册和寻址"""

    @abstractmethod
    def restore(self, data: dict) -> None:
        """从持久化数据恢复"""

    @abstractmethod
    def serialize(self) -> dict:
        """序列化为可持久化的数据"""

    @abstractmethod
    def snapshot(self) -> dict:
        """生成只读快照（给 AI Osiris / ContextAssembler）"""

    @property
    def dirty(self) -> bool:
        """是否有未持久化的变更"""
```

### 2.2 StateContainer

```python
class StateContainer:
    """状态容器——所有切片的注册表和生命周期管理器"""

    def __init__(self):
        self._slices: dict[str, StateSlice] = {}

    def register(self, slice: StateSlice):
        self._slices[slice.name] = slice

    def get_slice(self, name: str) -> StateSlice:
        return self._slices[name]

    # 便捷访问器（高频切片直接暴露）
    @property
    def time(self) -> TimeSlice: ...
    @property
    def player(self) -> PlayerSlice: ...
    @property
    def relations(self) -> RelationSlice: ...
    @property
    def quests(self) -> QuestSlice: ...
    @property
    def flags(self) -> FlagSlice: ...

    def snapshot(self) -> dict:
        """全局快照，供 AI Osiris 和 ContextAssembler 使用"""
        return {name: s.snapshot() for name, s in self._slices.items()}

    def restore(self, session_data: dict):
        for name, s in self._slices.items():
            if name in session_data:
                s.restore(session_data[name])

    def persist(self) -> dict:
        """只持久化 dirty 切片"""
        result = {}
        for name, s in self._slices.items():
            if s.dirty:
                result[name] = s.serialize()
        return result
```

### 3.1 TimeSlice — 时间子系统

```python
class TimeSlice(StateSlice):
    name = "time"

    # --- schema ---
    day: int                    # 当前天数（从 1 开始）
    slot: int                   # 当前格编号（1-24）
    period: str                 # 时段：dawn / day / dusk / night
    action_count: int           # 格内动作计数（累积 6 次 = 1 格）
    accumulated: float          # 格内累积时间消耗（>= 1.0 触发结算）

    # --- read API ---
    def get_current_time(self) -> dict:
        """返回 {day, slot, period}"""

    def get_period_info(self) -> dict:
        """返回当前时段属性（危险系数、营业状态、NPC 活动）"""

    # --- write API ---
    def advance(self, slots: int = 1):
        """推进 N 格，自动处理时段切换和日期翻转"""

    def add_action(self, cost: float):
        """累积动作时间成本"""

    def reset_action_count(self):
        """格结算后重置"""
```

**时段映射**（来自玩法设计 §三A）：

| 时段 | 时间格 | 危险系数 | 营业 | NPC 活动 |

| 🌅 黎明 | 5-7 | 0.8 | 准备开门 | 守卫交班 |
| ☀️ 白天 | 8-17 | 0.5 | 商店 8-20 | 正常活动 |
| 🌆 黄昏 | 18-19 | 1.0 | 打烊中 | 收摊回家 |
| 🌙 夜晚 | 20-4 | 1.5 | 酒馆热闹 | 夜间活动 |

| 转换 | 条件 |

| 朋友 → 挚友 | trust > 60 且 1+ 次危机选择 且 10+ 次共同经历 |
| 挚友 → 灵魂伴侣 | trust > 80 且 romance > 70 且特殊事件触发 |

## 四、AI Osiris 指令 → 切片映射

| AI Osiris 指令 | 目标切片 | 调用的 write API |
|---------------|---------|-----------------|
| `set_flag` | FlagSlice | `flags.set(key, value)` |
| `modify_disposition` | RelationSlice | `relations.modify_disposition(npc, dim, delta)` |
| `modify_approval` | PartySlice | `party.modify_approval(char, delta)` |
| `advance_quest` | QuestSlice | `quests.advance_quest(quest_id, to_state)` |
| `schedule_event` | EventSlice | `events.schedule(pending_event)` |
| `create_rumor` | EventSlice | `events.add_rumor(rumor)` |
| `modify_location` | AreaSlice | `areas.modify_property(loc, key, value)` |
| `add_knowledge` | RelationSlice | `relations.add_knowledge(char, knowledge)` |
| `modify_completion` | QuestSlice | `quests.modify_completion(chapter, delta)` |
| `adjust_danger` | AreaSlice | `areas.adjust_danger(area, delta)` |

每种指令有且仅有一个目标切片——不存在一条指令写多个切片的情况。

## 五、权限模型

L2（SessionRuntime）根据调用者角色暴露不同的切片访问：

| 调用者 | 可读切片 | 可写切片 |
|--------|---------|---------|
| **引擎**（pre-tick） | 全部 | 全部 |
| **AI Osiris**（通过引擎间接） | 全部（snapshot） | Flag / Relation / Quest / Area / Event（通过指令） |
| **GM Agent** | 全部 | **无**（纯只读） |
| **NPC Agent** | Scene + 自身 Relation + Flag | Relation（仅自身好感度）+ Scene |
| **队友 Agent** | Scene + 自身 Party + Flag | Scene + Party（仅自身审批值相关） |

GM 的零写入权限是架构的硬约束（P2：先执行后展示）。

## 六、持久化策略

### 6.1 本地优先 + 云端异步同步

对齐 BG3 存档模式——本地即时保存，云端是备份/跨设备同步。

```
SaveStore（存档管理器）
    │
    ├─ 本地存档（主存储，同步写入，零延迟）
    │   saves/{session_id}/
    │       ├─ state/time.json        ← TimeSlice
    │       ├─ state/player.json      ← PlayerSlice
    │       ├─ state/relations.json   ← RelationSlice
    │       ├─ state/quests.json      ← QuestSlice
    │       ├─ state/flags.json       ← FlagSlice
    │       ├─ state/areas.json       ← AreaSlice
    │       ├─ state/events.json      ← EventSlice
    │       ├─ state/party.json       ← PartySlice
    │       ├─ meta.json              ← 存档元数据
    │       └─ (scene 不持久化——格级生命周期)
    │
    └─ 云端存档（备份，异步上传，不阻塞游戏）
        Firestore: worlds/{world_id}/sessions/{session_id}/state/*
```

### 6.2 Dirty Tracking

每个切片内部维护 `_dirty: bool` 标记。`persist()` 时只写 dirty 切片，减少 I/O。

### 6.3 恢复流程

```
SaveStore.load(session_id)
    → 优先读取本地存档 saves/{session_id}/state/
    → 本地不存在时回退到 Firestore 云端存档
    → StateContainer.restore(data)
    → 每个切片各自 restore 自己的部分
```

### 6.4 云端同步策略

| 场景 | 行为 |
|------|------|
| 每次动作后 | 本地写入 + 标记 cloud pending |
| 格结算后 | 本地写入 + 立即云端同步（重要节点） |
| 玩家主动保存 | 本地写入 + 立即云端同步 |
| 后台定时 | 批量上传 pending（每 30 秒） |
| 网络不可用 | 本地正常运行，恢复后自动同步 |
| 跨设备恢复 | 从云端下载到本地，以时间戳较新者为准 |

## 七、与现有系统的关系

| 现有组件 | 演化方向 |

| `WorldGraph` | 拆分：静态拓扑 → ❶ WorldInstance；动态状态 → AreaSlice + FlagSlice |
