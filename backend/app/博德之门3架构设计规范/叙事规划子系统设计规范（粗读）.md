# 叙事规划子系统设计规范

> **子系统组成**：
> - **NarrativePlanner**：主动叙事规划核心（LLM 推理 + 8 种指令）
> - **DynamicSubAreaManager**：动态子区域生命周期管理（被 NarrativePlanner / AI Osiris / EventEngine 等多源调用）
> - **QuestRegistry 演化**：故事里程碑图（"价值"端，NarrativePlanner 为唯一消费者）

创建时间：2026-02-26
状态：设计中
前置文档：`AI-Osiris设计规范.md`（P30 反应式姊妹组件），`编排层设计规范.md`（P35 Hook 集成），`内容层设计规范.md`（QuestRegistry 里程碑数据），`状态层设计规范.md`（NarrativePlanSlice + QuestSlice），`❺ NPC与队友运行时规范.md`（PasserbyPool 投递 + NPC Directive），`叙事层设计规范.md`（NPC Agent 消费 Directive）

> NarrativePlanner = 主动叙事规划器。AI Osiris 的姊妹组件。
> AI Osiris 向后看（发生了什么 → 后果），NarrativePlanner 向前看（现在在哪 → 下一步引导什么）。
>
> **核心隐喻：价值与价格。**
> ❶ QuestRegistry 存储"价值"——主线里程碑节点（从世界书提取的故事骨架）。
> NarrativePlanner 生成"价格"——动态任务（围绕里程碑、随玩家行为波动的具体任务）。

## 一、定位

### 1.1 与 AI Osiris 的关系

```
                    格结算链（SettlementHooks）
                    │
    P30: AI Osiris  │  反应式因果引擎
         ↓          │  "偷窃 → 商人 2 格后发现"
    P35: NarrativePlanner  │  主动叙事规划器
         ↓          │  "进度 15% → 该引导玩家去调查牧场了"
    P40: Encounter  │
```

| 维度 | AI Osiris | NarrativePlanner |
|------|-----------|------------------|
| 方向 | 过去 → 现在（因果） | 现在 → 未来（引导） |
| 本质 | 推理后果 | 设计任务 |
| 输入 | 本格状态变化 | 故事里程碑 + 玩家行为 |
| 输出 | 后果指令（flag/好感/事件） | 动态任务 + 投递指令 |
| 频率 | 每格（非平凡格） | 条件触发 + 兜底 |
| 状态 | 无状态 | **有状态**（NarrativePlanSlice） |

### 1.2 不做什么

| 职责 | 归属 | NarrativePlanner 只做 |
|------|------|----------------------|
| 因果推理 | ⊕ AI Osiris | 不推理后果 |
| 任务状态机 | ❸ QuestSlice | 不管理任务状态流转 |
| 叙述文本 | ❺ GM Agent | 不生成叙述（只生成任务结构 + 投递指令） |
| 规则计算 | ❷ RulesEngine | 不计算 DC/奖励数值 |
| 任务完成判定 | ❷ + EventEngine | 不判定目标是否完成 |

## 二、故事里程碑——QuestRegistry 演化

### 2.1 设计理念

原 QuestRegistry 存储详细任务模板（目标、奖励、前置条件）。现在：

```
旧模型：QuestRegistry 存详细任务 → 管线直接消费
新模型：QuestRegistry 存故事里程碑 → NarrativePlanner 消费 → 动态生成任务
```

**里程碑 = 故事骨架上的节点**。每个里程碑是一个"玩家必须经历的故事节拍"，但不规定玩家如何到达——那是 NarrativePlanner 的工作。

### 2.2 StoryMilestone Schema（替代旧 QuestTemplate）

```python
StoryMilestone = {
    id: str,                          # "investigate_western_farm"
    name: str,                        # "调查西部牧场"
    tags: list[str],                  # [MAIN_QUEST, GOBLIN, INVESTIGATION]

    # === 故事定位 ===
    chapter_id: str,                  # 所属章节 "ch1_goblin_crisis"
    completion_value: int,            # 对章节完成度的贡献（5-30）
    sequence: int,                    # 章节内排序（10, 20, 30...）
    prerequisites: list[str],         # 前置里程碑 ID

    # === 叙事上下文（给 NarrativePlanner 的创作素材）===
    narrative_context: str,           # 故事背景描述
    # "西部牧场是边境最大的农业聚居地，最近频繁遭受哥布林袭击。
    #  公会收到了多份来自牧场的求援报告，但尚无冒险者前去调查。"

    key_elements: list[str],         # 关键叙事元素（NarrativePlanner 生成任务时必须包含）
    # ["goblin_attacks", "western_farm", "refugees", "guild_request"]

    involved_npcs: list[str],         # 相关 NPC ID（可用于投递任务）
    involved_locations: list[str],    # 相关地点 ID

    # === 达成判定 ===
    success_conditions: list[MilestoneCondition],
    # [
    #   {type: "location_visited", params: {location: "western_farm"}},
    #   {type: "flag_set", params: {key: "farm_investigation_started"}},
    # ]

    failure_conditions: list[MilestoneCondition] | None,
    # [
    #   {type: "time_elapsed", params: {days: 7}},  ← 7 天不去牧场就沦陷
    # ]

    # === 失败后果 ===
    failure_fallback: str | None,     # 失败时的叙事走向描述
    # "牧场被哥布林彻底摧毁，难民涌入边境镇，主线走向改变。"
}

MilestoneCondition = {
    type: str,        # location_visited / flag_set / npc_talked / item_obtained / kill_count / time_elapsed
    params: dict,     # 条件参数
    optional: bool,   # 是否为可选条件（可选条件不影响达成判定）
}
```

### 2.4 QuestRegistry 演化后的查询 API

```python
class QuestRegistry(ContentRegistry):
    """故事里程碑注册表（原 QuestRegistry 演化）"""
    name = "quests"

    milestones: dict[str, StoryMilestone]

    def get_milestone(self, milestone_id: str) -> StoryMilestone: ...
    def get_chapter_milestones(self, chapter_id: str) -> list[StoryMilestone]:
        """获取某章节的所有里程碑，按 sequence 排序"""
    def get_next_milestones(self, completed: list[str]) -> list[StoryMilestone]:
        """获取下一批可达成的里程碑（前置已满足）"""
    def get_milestone_graph(self, chapter_id: str) -> dict:
        """返回里程碑依赖图（用于可视化 / NarrativePlanner 规划）"""
```

### 3.2 输出设计：指令类型

NarrativePlanner 输出一个 `plan` 对象，包含 `interventions` 数组：

```json
{
  "reasoning": "玩家已完成 M20（接受调查任务），下一目标是 M30（调查西部牧场）。玩家在酒馆已待了 8 格未出发，应该通过路人 NPC 制造紧迫感。同时考虑到玩家的对话偏好，用 NPC 对话方式投递。",

  "strategy_update": "升级紧迫感——让受伤难民出现在酒馆，通过情感触发推动玩家出发",

  "interventions": [
    {
      "type": "create_quest",
      "params": { ... }
    },
    {
      "type": "spawn_quest_npc",
      "params": { ... }
    }
  ]
}
```

#### 指令类型全集

| 指令类型 | 参数 | 效果 | 典型场景 |
|---------|------|------|---------|
| `create_quest` | quest_def | 创建动态任务，写入玩家任务日志 | 生成引导任务 |
| `spawn_quest_npc` | npc_profile, dialogue_hook, quest_id | 生成携带任务的路人 NPC | 受伤农民冲进酒馆 |
| `direct_npc` | npc_id, directive, quest_id | 指挥现有 NPC 下次交互时主动提及任务 | 公会接待员叫住玩家 |
| `publish_bulletin` | board_id, location, notice, notify_resident_npcs | 在公告板（可交互实体）发布告示，通知驻留 NPC | 公会任务板新增委托 |
| `plant_environmental` | sub_area, target_area, discovery, content_hints | 生成临时子区域，玩家可主动进入探索 | 路边发现马车残骸（可进入调查） |
| `escalate` | escalation_type, commands, narrative_hint | 产生 Command 调整世界数值（danger / flag） | danger 上升、哥布林威胁等级提高 |
| `adjust_pacing` | direction, duration_ticks, suppress_escalation | NarrativePlanner 自我调节（暂缓/加速推进） | 玩家刚打完仗，冻结升级 3 格 |
| `retire_quest` | quest_id, reason, cleanup | 动态任务下架 + 清理关联资源（临时 NPC / 公告 / 子区域） | 玩家已通过其他途径达成目标 |
| `fill_area` | target_area, sub_areas[] | 批量生成 1-3 个非任务驱动的动态子地点（世界丰富度） | 商队营地、古老石碑、废弃营火 |

### 3.5 `direct_npc` 详细格式

```json
{
  "type": "direct_npc",
  "params": {
    "npc_id": "guild_receptionist",
    "directive": "下次玩家与你交谈时，主动提到西部牧场的紧急委托。表现出担忧，暗示这是一个适合瓷级冒险者证明自己的机会。",
    "priority": "high",
    "linked_quest_id": "dq_002",

  }

```

> **实现方式**：NPC Directive 写入 NPC 的工作记忆（ContextWindow），作为优先指令。NPC Agent 下次执行时会自然融入对话。详见 `NPC与队友子系统设计规范.md` §八 NPC Directive。

### 3.6 `plant_environmental` 详细格式

```json
{
  "type": "plant_environmental",
  "params": {
    "sub_area": {
      "name": "路边的马车残骸",
      "description": "一辆商队的马车翻倒在路边，货物散落一地。车轮上还插着几支粗糙的箭矢，空气中弥漫着淡淡的血腥味。",
      "tags": ["CLUE", "GOBLIN", "COMBAT_AFTERMATH"],
      "type": "discovery",
      "interactables": ["overturned_cart", "goblin_arrows", "scattered_goods", "blood_trail"]
    },
    "target_area": "border_road",
    "discovery_mode": "auto",
    "discovery_dc": 0,
    "content_hints": {
      "clues": ["哥布林箭矢指向西部森林方向", "马车上有冒险者公会的运输标记"],
      "possible_npcs": [
        {
          "name": "受伤的车夫",
          "personality": "惊恐但感激",
          "dialogue_hook": "别过来！...等等，你是冒险者？谢天谢地..."
        }
      ]
    },
    "linked_quest_id": "dq_002",
    "linked_milestone": "M30",
    "expiry_ticks": 12,
    "on_expire": "remove"
  }
}
```

> **模块化设计**：`plant_environmental` 委托给子系统内置模块 **DynamicSubAreaManager**（本文档 §十一）。NarrativePlanner 只描述"要什么样的子区域"，创建和生命周期管理由 DynamicSubAreaManager 负责。这与 `spawn_quest_npc` 调用 PasserbyService 是同一模式。
>
> **与 SubLocationTemplate 的关系**：临时子区域遵循 ❶ `SubLocationTemplate` 的 schema（`内容层设计规范.md` §4.1），但存储在 ❸ 状态层（动态数据），不写入 ❶ MapRegistry（静态数据）。NavigationHandler 合并静态 + 动态子地点列表后统一呈现给玩家。
>
> **发现模式（discovery_mode）**：
> - `auto`（DC=0）：自动出现在可用子地点列表中
> - `check`：需要感知/调查检定（复用 ❶ Discovery 机制），失败则不可见
> - `narrated`：由队友或 NPC 主动指出（配合 `direct_npc` 使用）
>
> **多主体叙述**：进入临时子区域后，GM、队友、区域内 NPC 均可参与叙述——所有在场 Agent 共同构建探索体验，不是 GM 独占的场景描写。

### 3.7 `publish_bulletin` 详细格式

```json

  "type": "publish_bulletin",
  "params": {
    "board_id": "guild_quest_board",
    "location": {"area": "border_town", "sub_location": "adventurer_guild"},
```

> **公告板 = 可交互迷你实体**：公告板是子地点内的可交互物件（`SubLocationTemplate.interactables`），拥有动态内容（告示列表）。玩家可查看公告板内容，NPC 可在对话中引用。
>
> **`notify_resident_npcs`**：为 `true` 时，自动为该子地点的驻留 NPC 生成隐式 `direct_npc` 指令，使其知晓新告示内容，可在对话中自然提及（如公会接待员说"公告板上刚贴了新委托"）。

### 3.8 `escalate` 详细格式

```json
{
  "type": "escalate",
  "params": {
    "escalation_type": "danger_increase",
    "commands": [
      {"type": "set_flag", "params": {"key": "goblin_threat_level", "value": 3}},
      {"type": "modify_danger", "params": {"area": "border_region", "delta": 0.1}}
    ],
    "narrative_hint": "边境地区哥布林活动明显增加",
    "linked_milestone": "M30"
  }
}
```

> **纯数值操作**：`escalate` 产生 Command 列表交给 ❷ RulesEngine 执行（详见 `规则引擎层设计规范.md` §3.1 FlagHandler、§3.3 NavigationHandler）。不做叙事效果——世界状态变化后，后续 Hook（P40 遭遇检定、P80 GM 叙述）会自然反映变化。
>
> **可用 Command 类型**：`set_flag`、`modify_danger`、`modify_reputation`。不允许直接操作角色属性或触发战斗——NarrativePlanner 只调世界态势，不操作个体。

### 3.9 `adjust_pacing` 详细格式

```json
{
  "type": "adjust_pacing",
  "params": {
    "direction": "slow_down",
    "duration_ticks": 3,
    "reason": "玩家刚完成艰难战斗，暂缓推进让其恢复",
    "suppress_escalation": true
  }
}
```

> **自我调节**：`adjust_pacing` 不影响外部系统，只更新 NarrativePlanSlice 内部状态：
> - `suppress_escalation: true` → 冻结 `ticks_since_milestone_progress` 计数器，暂停升级等级上升
> - `direction`: `slow_down`（暂缓）/ `speed_up`（加速）/ `hold`（保持当前节奏）
> - `duration_ticks` 到期后自动恢复正常节奏

### 3.10 `retire_quest` 详细格式

```json
{
  "type": "retire_quest",
  "params": {
    "quest_id": "dq_001",
    "reason": "玩家已通过其他途径接近里程碑 M30，此任务不再需要",
    "cleanup": {
      "despawn_npcs": ["_temp_informant"],
      "remove_bulletins": ["guild_quest_board.notice_001"],
      "remove_sub_areas": ["_temp_carriage_wreck"]
    }
  }
}
```

> **级联清理**：`retire_quest` 不仅更新任务状态（→ `retired`），还清理该任务关联的所有资源：
> - `despawn_npcs`: 移除临时 NPC（调用 PasserbyService，详见 `NPC与队友子系统设计规范.md` §九）
> - `remove_bulletins`: 移除公告板告示
> - `remove_sub_areas`: 移除临时子区域（调用 DynamicSubAreaManager.expire()，本文档 §十一）
>
> 清理字段均为可选——如果任务没有关联资源，`cleanup` 可为空对象。

> **与 `plant_environmental` 的区别**：
>
> | 维度 | `plant_environmental` | `fill_area` |
> |------|----------------------|-------------|
> | 目的 | 任务投递（引导玩家） | 世界丰富度（探索乐趣） |
> | linked_quest_id | 通常非空 | **必然为空** |
> | linked_milestone | 通常非空 | **必然为空** |

> | 触发条件 | 任务引导需要 | 区域子地点不足 |
> | 子地点风格 | 任务相关 | 区域 `fill_tags` 偏好 |
>

>
> | 层级 | expiry_ticks | 特征 | 示例 |
> |------|-------------|------|------|
> | **常驻 permanent** | -1（永不过期） | 被发现后一直存在，珍贵 | 隐藏洞穴、古代石碑、废弃矿坑 |
> | **限时 timed** | 24-72（1-3 天） | 长周期存在，自然衰退 | 商队营地、旅行者篝火、临时集市 |
> | **临时 temporary** | 6-12（几小时） | 短期附属，事件结束清理 | 受伤农民处、马车残骸、侦察营 |
>
> **执行流程**：
> ```
> fill_area 指令执行:
>   for sub_area_spec in params.sub_areas:
>     1. 读取 ❶ AreaTemplate.sub_area_cluster_config
>     2. 检查 cluster capacity → 容量不足则跳过剩余
>     3. tier=permanent 且 permanent_count >= max_permanent_dynamic → 跳过
>     4. 构造 TemporarySubArea（source="narrative_planner"）
>     5. DynamicSubAreaManager.create(spec)
>     6. 如有 resident_npcs → PasserbyService.spawn()
> ```

## 四、触发条件

### 4.1 条件触发（主路径）

| 触发条件 | 检查方式 | 示例 |
|---------|---------|------|
| **里程碑状态变化** | QuestSlice 监听 | M20 完成 → 规划 M30 的引导 |
| **进入新区域** | AreaSlice 变化 | 进入 goblin_forest → 检查是否需要调整引导 |
| **玩家行为标记** | FlagSlice 变化 | `farm_quest_accepted` 被设 → 里程碑达成检查 |
| **AI Osiris 输出** | P30 结果 | Osiris 设了 `goblin_danger_rising` → 可能需要升级引导 |
| **动态任务到期** | NarrativePlanSlice 检查 | `dq_001` 过期了 → 需要替换策略 |
| **升级阈值** | 停滞检测 | `ticks_since_progress >= N` → 升级引导 |
| **区域丰富度不足** | AreaSlice.count_dynamic_sub_areas() | 当前区域动态子地点 < 容量阈值 → 触发 `fill_area` |

### 4.2 周期兜底（防遗漏）

```python
class NarrativePlannerHook(SettlementHook):
    priority = 35
    name = "narrative_planner"

    FALLBACK_INTERVAL = 6  # 兜底间隔：每 6 格（约 1 小时游戏时间）

    def should_skip(self, change_log: list[StateChange]) -> bool:
        # 条件触发：任何触发条件满足 → 不跳过
        if self._has_trigger_condition(change_log):
            return False

        # 区域丰富度不足 → 不跳过（触发 fill_area）
        if self._area_needs_filling():
            return False

        # 兜底：距上次运行超过 N 格 → 不跳过
        if self._ticks_since_last_run() >= self.FALLBACK_INTERVAL:
            return False

        # 既无触发条件也未到兜底周期 → 跳过
        return True

    def _area_needs_filling(self) -> bool:
        """检查当前区域动态子地点是否低于填充阈值。
        阈值由 ❶ AreaTemplate.sub_area_cluster_config.fill_density 决定：
          sparse: remaining/max > 0.8（仅 < 20% 容量使用时触发）
          normal: remaining/max > 0.6（< 40% 时触发）
          dense:  remaining/max > 0.4（< 60% 时触发）
        """
```

### 4.3 触发后的完整执行流程

```
NarrativePlannerHook.execute()
    │
    ├─ 1. 加载输入
    │     故事蓝图 ← ❶ QuestRegistry.get_chapter_milestones()
    │     里程碑状态 ← ❸ QuestSlice
    │     玩家画像 ← ❸ PlayerSlice + AreaSlice + 行为分析
    │     当前计划 ← ❸ NarrativePlanSlice
    │     世界上下文 ← ❶ CharacterRegistry + MapRegistry + LoreRegistry
    │
    ├─ 2. 预处理
    │     检查活跃动态任务状态（到期？完成？失效？）
    │     计算停滞指标（ticks_since_progress）
    │     判定当前升级等级
    │
    ├─ 3. LLM 推理
    │     构建 prompt → NarrativePlanner LLM 调用
    │     → 输出 reasoning + strategy_update + interventions
    │     → JSON 解析 + 格式验证
    │
    ├─ 4. 指令执行（逐条验证合法性后执行）
    │     create_quest        → 写入 QuestSlice.dynamic_quests（state=discovered）+ 关联里程碑推进到 ACTIVE
    │     spawn_quest_npc     → PasserbyService.spawn() + 注入 dialogue_hook / linked_quest
    │     direct_npc          → 写入目标 NPC 的 ContextWindow（directive_queue）
    │     publish_bulletin    → 写入 NarrativePlanSlice.active_bulletins + 隐式 direct_npc 通知驻留 NPC
    │     plant_environmental → DynamicSubAreaManager.create()（§十一）→ 写入 ❸ AreaSlice.temporary_sub_areas
    │     escalate            → 产生 Command 列表 → ❷ RulesEngine.batch_execute()
    │     adjust_pacing       → 更新 NarrativePlanSlice（冻结/恢复升级计数器）
    │     retire_quest        → 任务状态 → retired + 级联清理（despawn NPC / 移除公告 / 移除子区域）
    │
    ├─ 5. 更新 NarrativePlanSlice
    │     strategy_notes 更新
    │     last_run_tick 更新
    │     quest_history 更新（如有任务完成/退出）
    │
    └─ 6. 返回 HookResult
          commands: 产生的 Command 列表
          sse_events: 任务通知 SSE 事件（如有直接发布的任务）
```

## 五、递进引导策略（升级机制）

### 5.1 停滞检测

NarrativePlanner 跟踪玩家在主线方向上的"停滞程度"：

```
停滞指标 = ticks_since_last_milestone_progress
```

| 停滞格数 | 升级等级 | 引导策略 | 示例 |
|---------|---------|---------|------|
| 0-3 | L0 无干预 | 玩家在正常探索，不打扰 | — |
| 4-6 | L1 暗示 | 环境中自然出现主线相关线索 | 酒馆客人谈论西部的消息 |
| 7-9 | L2 推荐 | NPC 主动提及/推荐任务 | 公会接待员叫住玩家 |
| 10-12 | L3 紧迫 | 生成紧迫事件，直接投递任务 | 受伤农民冲进酒馆 |
| 13-15 | L4 危机 | 世界状态恶化，错过窗口的后果开始显现 | 第二波难民涌入、danger 上升 |
| 16+ | L5 失败倒计时 | 明确告知后果，给最后机会 | "牧场最后的防线即将崩溃" |

### 5.2 升级策略不是线性的

NarrativePlanner 会根据**玩家行为类型**调整升级方式：

```
对话型玩家（DIALOGUE_HEAVY）
  → 偏好用 NPC 对话投递
  → L1: 酒馆 NPC 闲聊提及  →  L2: 公会 NPC 正式推荐  →  L3: 受伤农民求助

探索型玩家（EXPLORER）
  → 偏好用环境线索投递
  → L1: 路边发现马车残骸  →  L2: 发现逃难的村民  →  L3: 路上遭遇哥布林侦察兵

战斗型玩家（COMBAT_FOCUSED）
  → 偏好用遭遇/冲突投递
  → L1: 小镇外哥布林小队出没  →  L2: 哥布林袭击商队  →  L3: 哥布林直接攻击小镇
```

这些**不是硬编码规则**——NarrativePlanner 作为 LLM，在 prompt 中被告知玩家行为倾向后自主决策投递方式。升级等级表只是参考框架。

### 5.3 减速机制

如果玩家刚经历了重大事件（大战、重要对话、升级），NarrativePlanner 应该**暂缓**而非继续推进：

```python
# 减速条件（示例）
should_slow_down = (
    recent_combat_ended  # 刚打完仗，让玩家喘口气
    or milestone_just_completed  # 刚完成里程碑，享受成就感
    or player_in_private_chat  # 正在私聊，不打断
    or party_hp_low  # 队伍血量低，应该先休息
)
```

减速时 NarrativePlanner 不生成新干预，只更新 strategy_notes："玩家刚完成 M30，暂缓推进，等待 2 格后再评估。"

## 六、动态任务生命周期

### 6.1 任务状态

```
generated ──→ delivered ──→ discovered ──→ accepted ──→ completed
    │              │             │             │            │
    │              │             │             │            └→ 贡献里程碑进度
    │              │             │             └→ 目标跟踪（EventEngine）
    │              │             └→ 出现在任务日志
    │              └→ 投递指令已执行（NPC 出现/公告板更新）
    └→ NarrativePlanner 生成
                                   ↘ expired（到期未接受）
                                   ↘ retired（被 NarrativePlanner 主动下架）
```

### 6.2 DynamicQuest 完整数据结构

```python
@dataclass
class DynamicQuest:
    """NarrativePlanner 生成的动态任务"""

    # === 标识 ===
    id: str                           # 自动生成：f"dq_{timestamp}_{seq}"
    title: str                        # "受伤农民的求助"
    description: str                  # 任务描述（叙事风格）

    # === 定位 ===
    target_milestone: str             # 指向哪个里程碑
    urgency: str                      # low / medium / high / critical

    # === 目标 ===
    objectives: list[QuestObjective]  # 任务目标列表
    # QuestObjective = {
    #     description: str,
    #     type: str,         # talk_to / reach_location / collect / kill / escort / investigate
    #     target: dict,      # 目标参数
    #     optional: bool,
    #     completed: bool,
    # }

    # === 奖励 ===
    rewards: QuestRewards             # {xp, gold, items, reputation}

    # === 投递 ===
    delivery_method: str              # spawn_npc / direct_npc / bulletin / environmental / direct
    delivery_params: dict             # 投递参数（NPC 信息 / 地点 / 公告板位置）
    delivery_status: str              # pending / delivered / acknowledged

    # === 生命周期 ===
    status: str                       # generated / delivered / discovered / accepted / completed / expired / retired
    created_at_tick: int              # 创建时的时间格
    expiry_ticks: int | None          # 过期时间（None = 不过期）
    on_expire: str                    # ignore / escalate / retire
    # ignore = 静默过期
    # escalate = 过期时升级（NarrativePlanner 下次运行生成更紧迫的替代）
    # retire = 标记为 retired，从活跃列表移除

    # === 溯源 ===
    generated_by_escalation: int      # 被哪个升级等级触发生成的
    planner_reasoning: str            # NarrativePlanner 的生成理由
```

### 6.3 任务完成判定

动态任务的目标完成判定**不由 NarrativePlanner 负责**，而是复用已有系统：

```
DynamicQuest.objectives[i] (type="reach_location", target={location: "western_farm"})
    ↓
NarrativePlanner 生成时同步创建 EventSlice 条件
    ↓
EventEngine.check_conditions()（A6/C1/P50）
    → 条件满足 → 更新 DynamicQuest.objectives[i].completed = true
    → 所有必选目标完成 → DynamicQuest.status = "completed"
    → 检查是否满足关联里程碑的 success_conditions
```

## 七、NarrativePlanSlice——❸ 新增状态切片

### 7.1 Schema

```python
@dataclass
class NarrativePlanSlice(StateSlice):
    """NarrativePlanner 的有状态计划。❸ 状态层新增切片。

    注意：动态任务和里程碑状态存储在 QuestSlice（唯一真理）。
    本 Slice 只存储规划元数据，不存储任务/里程碑副本。
    """

    name = "narrative_plan"

    # === 进度跟踪 ===
    current_chapter: str                    # 当前章节 ID
    current_target_milestone: str | None    # 当前目标里程碑 ID
    chapter_completion: float               # 章节完成百分比（冗余快照，权威值在 QuestSlice）

    # === NPC 指令队列 ===
    npc_directives: list[NpcDirective]      # 待执行的 NPC 指令
    # NpcDirective = {npc_id, directive, priority, quest_id, expires_tick}

    # === 公告板告示 ===
    active_bulletins: list[BulletinNotice]  # 活跃的公告板告示
    # BulletinNotice = {board_id, location, title, content, urgency, linked_quest_id, created_tick, expiry_ticks}

    # === 历史（精简）===
    quest_history: list[QuestSummary]       # 已结束任务的摘要
    # QuestSummary = {id, title, target_milestone, status, created_tick, resolved_tick}

    # === 规划状态 ===
    escalation_level: int                   # 当前升级等级（0-5）
    ticks_since_milestone_progress: int     # 距上次里程碑进展的格数
    strategy_notes: str                     # NarrativePlanner 的当前策略描述
    last_run_tick: int                      # 上次运行的时间格
    next_scheduled_tick: int | None         # 下次计划运行的时间格（兜底）
    pacing_frozen: bool                     # 是否冻结升级计数器

    # === 玩家行为画像 ===
    play_style_tags: list[str]              # 累积的玩家风格标签
    behavior_window: list[BehaviorEntry]    # 最近 N 格的行为记录（滑动窗口）
    # BehaviorEntry = {tick, action_type, location, details}

    # === 动态任务读取（从 QuestSlice，不在此存储）===
    # NarrativePlanner 通过 state.quests.dynamic_quests 读取活跃任务
    # 里程碑状态通过 state.quests.milestone_states 读取
    # 已完成里程碑通过 state.quests.get_available_milestones() 反向推断
```

### 7.2 持久化

NarrativePlanSlice 与其他 Slice 统一持久化：

```
saves/{session_id}/state/narrative_plan.json
```

云端路径：`worlds/{world_id}/sessions/{session_id}/state/narrative_plan`

### 7.3 行为画像更新

玩家行为画像不是由 NarrativePlanner 更新的——它在**每次 Pipeline 处理时**由编排层自动记录：

```python
# TickCoordinator.process() 中，记录行为
self.state.narrative_plan.record_behavior(
    tick=current_tick,
    action_type=result.action_type,   # dialogue / combat / trade / explore / rest
    location=self.state.area.current_location,
    details=result.brief_summary,
)
```

## 九、与 TickCoordinator 集成

### 9.1 SettlementHook 实现

```python
class NarrativePlannerHook(SettlementHook):
    """叙事规划器结算钩子。P35，AI Osiris 之后。"""

    priority = 35
    name = "narrative_planner"

    FALLBACK_INTERVAL = 6  # 兜底间隔（格数）

    def __init__(self, planner: NarrativePlanner):
        self._planner = planner

    def should_skip(self, change_log: list[StateChange]) -> bool:
        plan_slice = self._get_plan_slice()

        # 条件触发
        if self._has_milestone_change(change_log):
            return False
        if self._has_area_change(change_log):
            return False
        if self._has_relevant_flag_change(change_log):
            return False
        if self._has_quest_expiry(plan_slice):
            return False

        # 升级阈值触发
        if plan_slice.ticks_since_milestone_progress >= self._escalation_threshold(plan_slice):
            return False

        # 兜底
        current_tick = self._get_current_tick()
        if current_tick - plan_slice.last_run_tick >= self.FALLBACK_INTERVAL:
            return False

        return True

    def _escalation_threshold(self, plan: NarrativePlanSlice) -> int:
        """下一个升级等级的阈值"""
        thresholds = [4, 7, 10, 13, 16]  # L1, L2, L3, L4, L5
        level = plan.escalation_level
        if level < len(thresholds):
            return thresholds[level]
        return self.FALLBACK_INTERVAL  # L5 之后每 6 格检查一次

    async def execute(self, context: SettlementContext) -> HookResult:
        result = await self._planner.evaluate(
            state=context.state,
            world=context.world,
            change_log=context.change_log,
        )
        return HookResult(
            commands=result.commands,
            sse_events=result.sse_events,
        )
```

### 9.2 更新后的结算链

```
tick_settlement()
    │
    ├─ P10: ScheduledEventHook       ← 延时事件检查

    ├─ P30: AIOsirisHook ★           ← 反应式因果推理
    ├─ P35: NarrativePlannerHook ★   ← 【新增】主动叙事规划
```

## 十一、DynamicSubAreaManager — 动态子区域管理

本子系统的执行模块，管理运行时动态生成的临时子区域。被 NarrativePlanner（`plant_environmental`，§3.6）、AI Osiris、EventEngine 等 SettlementHook 调用。

**核心职责**：创建 / 查询 / 过期 / 清理临时子区域。

### 11.1 TemporarySubArea Schema

```python
@dataclass
class TemporarySubArea:
    """动态生成的临时子区域。❶ SubLocationTemplate schema 的运行时超集。"""

    # === SubLocationTemplate 兼容字段（❶ 内容层设计规范 §4.1）===
    id: str                          # "_temp_carriage_wreck"（自动生成，_temp_ 前缀）
    name: str                        # "路边的马车残骸"
    description: str                 # 叙事描述
    tags: list[str]                  # [CLUE, GOBLIN, COMBAT_AFTERMATH]
    type: str                        # discovery / encounter / event_site / camp
                                     # ↑ 新增 "encounter"（随机遭遇生成）、"camp"（营地）
    available_hours: tuple[int,int]  # 默认 (0, 24) — 临时子区域通常全天可用
    resident_npcs: list[str]         # 临时 NPC ID（由 PasserbyService 生成）
    interactables: list[InteractableTemplate]  # 可交互物件（含 visibility_dc 感知门槛 + checks 多路径检定）
                                     # schema 见 ❶ 内容层 InteractableTemplate
                                     # NarrativePlanner 生成子区域时可同时生成交互物

    # === 敌对配置（新增）===
    hostile_config: HostileConfig | None  # 敌对子地点配置（schema 见 ❶ 内容层 §4）
    # NarrativePlanner 的 plant_environmental 可生成含 hostile_config 的子区域
    # EncounterHandler 随机遭遇生成时自动填充
    # None → 非敌对子区域（原有行为不变）

    # === 营地配置（新增）===
    camp_type: str | None            # "safe"（酒馆/旅馆）/ "wilderness"（野外）
                                     # 仅 type="camp" 时有效，影响守夜检定（❷ RestHandler §3.7）

    # === 动态扩展字段 ===
    target_area: str                 # 所属区域 ID
    content_hints: dict              # LLM 辅助内容（clues, possible_npcs）
                                     # → 供 Agent 叙述时参考，不是硬编码脚本
    discovery_mode: str              # auto / check / narrated
    discovery_dc: int                # check 模式的 DC（auto/narrated 模式忽略）
    discovery_check: str             # perception / investigation / nature

    # === 关联 ===
    linked_quest_id: str | None      # 关联的动态任务 ID
    linked_milestone: str | None     # 关联的里程碑 ID
    source: str                      # 创建来源："narrative_planner" / "ai_osiris" / "event_engine" / "discovery" / "private_chat" / "encounter" / "permanent" / "camp"

    # === 生命周期 ===
    created_at_tick: int             # 创建时间格
    expiry_ticks: int                # 存活格数（-1 = 永不过期）
    on_expire: str                   # remove（直接移除）/ decay（描述变化但保留残骸）
    status: str                      # active / discovered / entered / expired
```

### 11.2 API

```python
class DynamicSubAreaManager:
    """动态子区域管理器。本子系统内置模块，开放给其他 SettlementHook 调用。"""

    def create(self, spec: TemporarySubArea) -> str | None:
        """创建临时子区域。写入 ❸ AreaSlice.temporary_sub_areas。

        增强：簇限制检查。
        1. 读取 ❶ AreaTemplate.sub_area_cluster_config（无配置则用 DEFAULT）
        2. 统计当前区域动态子地点数量（count_dynamic_sub_areas）
        3. total >= max_dynamic → 拒绝创建，返回 None
        4. tier=permanent 且 permanent_count >= max_permanent_dynamic → 拒绝，返回 None
        5. 通过 → 原有创建逻辑，返回生成的 ID

        层级判定：
          expiry_ticks == -1  → permanent
          expiry_ticks >= 24  → timed
          其他               → temporary
        """

    def get_cluster_status(self, area_id: str) -> ClusterStatus:
        """返回区域子地点簇状态（供 NarrativePlanner 决策用）。
        ClusterStatus = {
            static_count: int,        # ❶ 静态子地点数量
            permanent_count: int,     # 常驻动态
            timed_count: int,         # 限时动态
            temporary_count: int,     # 临时动态
            total_dynamic: int,       # 动态总数
            max_dynamic: int,         # 上限（来自 ❶ SubAreaClusterConfig）
            remaining_capacity: int,  # 剩余容量 = max_dynamic - total_dynamic
        }"""

    def list_active(self, area_id: str) -> list[TemporarySubArea]:
        """查询指定区域的活跃临时子区域。
        NavigationHandler 合并查询时调用（见下方集成说明）。"""

    def get(self, sub_area_id: str) -> TemporarySubArea | None:
        """按 ID 查询单个临时子区域。"""

    def mark_discovered(self, sub_area_id: str) -> None:
        """标记为已发现。check 模式下玩家通过检定后调用。
        status: active → discovered，出现在可用子地点列表中。"""

    def mark_entered(self, sub_area_id: str) -> None:
        """标记为已进入。玩家 enter_sub_location 时调用。
        status: discovered → entered。"""

    def expire(self, sub_area_id: str) -> None:
        """手动过期。retire_quest 级联清理时调用。
        status → expired，从活跃列表移除。"""

    def tick_cleanup(self, current_tick: int) -> list[str]:
        """格结算时调用，清理已到期的子区域。
        返回被清理的 ID 列表。挂载于 P90 SceneBusResetHook 附带执行。"""
```

### 11.3 与 NavigationHandler 集成（❷ 规则引擎层 §3.3）

```
玩家查询可用子地点 / NavigationHandler 验证 enter_sub_location：

    MapRegistry.get_sub_locations(area_id)         ← 静态子地点（❶ 内容层）
  + DynamicSubAreaManager.list_active(area_id)     ← 动态子地点（❸ 状态层）
  ──────────────────────────────────────────────
  = 合并后的完整子地点列表

NavigationHandler 验证流程扩展：
  1. 先查 MapRegistry（静态）
  2. 未命中 → 查 DynamicSubAreaManager（动态）
  3. 均未命中 → 验证失败
  4. check 模式的子区域需 status >= discovered 才可进入
```

### 11.4 与 ContextAssembler 集成

ContextAssembler 组装 L3（地点细节）时，对动态子区域使用 `content_hints` 作为 Agent 上下文的一部分，使 GM / NPC / 队友 Agent 知晓该子区域的叙事要素（线索、可能的 NPC、氛围），从而自然协作叙述。
