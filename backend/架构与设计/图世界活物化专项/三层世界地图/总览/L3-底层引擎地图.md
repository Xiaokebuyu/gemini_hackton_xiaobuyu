## 4. 当前 L3 结构性屎点

### P0（阻断运行）

1. `app/world/player/character.py:16` 仍 import 已删 `CharacterStore`。
2. `app/world/player/ability_check.py:6` 仍 import 已删 `CharacterStore`。
3. `app/runtime/session_runtime.py` 与 `app/runtime/event_machine.py` 仍引用已删 `area_runtime`。

### P1（中高）

1. 实际循环依赖：
   - `app/world/graph/builder.py:33` → `SessionRuntime`
   - `app/runtime/session_runtime.py:424` → `GraphBuilder`
2. L3 超大文件集群（5 个 >1000 行），修改回归面大。
3. L3 宽异常集中：
   - `session_runtime.py`：18
   - `event_machine.py`：7
   - `intent/executor.py`：6

### P2（中）

1. 部分模块仍保留历史兼容路径（注释/字段），增加认知负担。
2. `snapshot` 对图容器内部细节耦合偏深（封装边界偏软）。

## 6. L3 治理建议

1. 先打断循环依赖（`builder` 改为接收 Protocol/DTO，不 import `SessionRuntime`）。
2. 对 `combat_engine/narrative_service/builder/session_runtime` 做纵向拆分（目标单文件 <900 行）。
3. 将 `session_runtime/event_machine/intent_executor` 的宽异常改为分级异常。
4. 清理 player/runtime 对已删 Store/AreaRuntime 的残留引用，避免“结构已好但基础不稳”。

> 结论：L3 迁移形态已经对，但仍需从“集中的大引擎”继续演进成“边界明确的子系统”。
