# P27 — 三层嵌套地点系统 + Directive 修复

## 背景

P25 代码验证确认所有 locality/feedback/milestone 代码已就位，但玩家体验无变化。根因：`move_area` 后 `current_location` 被清空为 None，导致：
1. Osiris `_build_nearby_npcs()` 回退全区域 NPC → 好感度全图广播
2. `is_colocated()` 让有 sub_location 的 NPC 对玩家不可见
3. 现有 sub_location 基础设施（NavigationHandler、scene_views、前端）全部就位但从未激活

附带修复：escalate delta 缺类型强转 + dispatcher log 缺 reason_code。

## Phase 0：Directive 修复（已完成 2026-03-12）

### 0-1. escalate delta 类型强转

**文件**：`app/game_core/planning/directive_contracts.py` (L339-350)

之前 escalate 验证仅接受原生 `int`（且排除 bool），拒绝 `float` 和 `str` 类型的数值。
修改为先排除 `bool`，再用 `int()` 强转，参照同文件 `expiry_ticks` 的处理模式。

变更前：
```python
delta = normalized.get("delta")
if not isinstance(delta, int) or isinstance(delta, bool):
    return False, normalized, "invalid_delta"
```

变更后：
```python
raw_delta = normalized.get("delta")
if isinstance(raw_delta, bool):
    return False, normalized, "invalid_delta"
try:
    delta = int(raw_delta)
except (TypeError, ValueError):
    return False, normalized, "invalid_delta"
normalized["delta"] = delta
```

### 0-2. dispatcher log 含 reason_code

**文件**：`app/game_core/orchestration/hooks/narrative_planner.py` (L1265-1268)

之前 log 消息硬写死 `"dispatcher_rejected"`，丢失具体拒绝原因。
修改为使用 L1255 已计算的 `reason_code` 变量直接格式化到 log 消息中。

### 0-3. 新增测试（3 个）

**文件**：`tests/test_planner_directive_contracts.py`

- `test_validate_escalate_coerces_float_delta_to_int` — float 1.0 → int 1
- `test_validate_escalate_coerces_string_delta_to_int` — str "2" → int 2
- `test_validate_escalate_rejects_none_delta` — None → invalid_delta

测试结果：47 passed（含 3 个新测试），全量 2481 passed，0 failures。

## Phase 2：Room 数据模型（已完成 2026-03-12）

### 2-1. RoomTemplate 数据类

**文件**：`app/game_core/content/registries/map_types.py`

新增 `RoomTemplate` dataclass（slots=True）：
- 字段：`id`, `name`, `description`, `tags`, `discoverable`, `discovery_dc`, `resident_npcs`, `interactables`
- `discoverable=True` 表示此房间需要主动发现才可进入；`discovery_dc=0` 表示询问即可知晓

`SubLocationTemplate` 扩展：
- 新增 `rooms: dict[str, RoomTemplate] = field(default_factory=dict)`
- 新增 `default_room: str = ""`（进入此子地点时玩家自动放置的房间 ID）

- 新增 `_build_room()` — 构建单个 `RoomTemplate`，含 interactables 加载（复用 `_build_interactable`）
- `_build_sub_location()` 末尾增加 `rooms` 和 `default_room` 加载，并传入 `SubLocationTemplate` 构造器
- `default_room` 校验：空白字符串视为无效，写入 `_load_issues`

### 2-3. PlayerSlice.current_room

### 2-4. AreaSlice 扩展

**文件**：`app/game_core/state/slices/area.py`

`AreaState` 新增字段：
- `npc_rooms: dict[str, str | None]` — NPC 当前所在房间（与 npc_locations 并列）
- `discovered_rooms: set[str]` — 已发现房间键集合（格式 `{sub_loc_id}__{room_id}`）

`AreaState.snapshot()` 新增这两个字段的序列化。

`AreaSlice` 新增公开方法：
- `set_npc_room(area_id, character_id, room_id)` — 写入 NPC 房间
- `get_npc_room(area_id, character_id)` — 读取 NPC 房间

- `is_room_discovered(area_id, sub_loc_id, room_id)` — 查询是否发现
- `get_discovered_rooms(area_id)` — 返回防御性拷贝 set

`_coerce_area_state()` 两路径（AreaState 拷贝 + Mapping restore）均加入新字段。

`apply_state_change()` 新增路径：
- `areas.set "{area_id}.npc_room.{npc_id}"` — 设置 NPC 房间（None 清空）
- `areas.set "{area_id}.discovered_room.{sub_loc_id}.{room_id}"` — 标记发现（也支持 add 操作）

## Phase 3：Room 导航 + 可见性（已完成 2026-03-12）

### 3-1. enter_room / leave_room 命令

**文件**：`app/game_core/rules/handlers/navigation.py`

- `NavigationHandler.COMMAND_TYPES` 新增 `"enter_room"` 和 `"leave_room"`
- `_validate_enter_room()`：
  - 玩家必须在 sub_location（`current_location` 非 None）
  - `room_id` 参数必须非空（支持 `room` 别名）
  - room 必须存在于当前 sub_location 的 `rooms` dict
  - `discoverable=True` 的 room 必须已在 `discovered_rooms` 中（通过 AreaSlice）
- `_compute_enter_room()`：StateChange `player.current_room`，耗时 1/24 slot
- `_validate_leave_room()`：玩家必须在 room（`current_room` 非 None）
- `_compute_leave_room()`：清空 `current_room`，耗时 0
- 新增静态方法 `_resolve_room_alias(params)` — 支持 `room_id` / `room` 参数别名

### 3-2. leave_sub_location 清空 room

**文件**：`app/game_core/rules/handlers/navigation.py` — `_compute_leave_sub_location()`

离开 sub_location 时同时清空 `current_room`（仅当 `current_room` 非 None 时追加 StateChange）。

### 3-3. defaults.py 注册新命令

**文件**：`app/game_core/orchestration/defaults.py`

`DEFAULT_ACTION_COMMAND_TYPES` 新增：

### 3-4. Presence 三级可见性扩展

**文件**：`app/game_core/orchestration/presence.py` — `is_colocated()`

扩展为四参数签名（向后兼容，`npc_room`/`player_room` 默认 None）：
```python
def is_colocated(
    npc_location: str | None,
    player_location: str | None,
    npc_room: str | None = None,
    player_room: str | None = None,
) -> bool:
```
逻辑：
1. sub_location 必须匹配（原有逻辑）
2. 若 `player_room` 非 None，则 `npc_room` 必须等于 `player_room`
3. `player_room` 为 None → 同 sub_location 即可见（向后兼容）

### 3-5. scene_views room 过滤 + rooms payload

**文件**：`app/scene_views.py` — `build_location_overview()`

- 读取 `player.current_room`（使用 `getattr(..., None)` 保证向后兼容 mock 对象）
- NPC 过滤调用 `is_colocated(..., npc_room, current_room_id)`
  - 当玩家在 room 中时，从 `area_state.npc_rooms` 查询 NPC 房间
- payload 新增 `current_room: str | None`
- payload 新增 `rooms: list[dict]` — 当前 sub_location 的房间列表
  - 每条含 `id`, `name`, `discoverable`, `discovered`
  - `discovered` 逻辑：non-discoverable room 始终为 True；discoverable room 查 `area_state.discovered_rooms`

### 3-6. Osiris room 级局部性

**文件**：`app/game_core/orchestration/hooks/ai_osiris.py` — `_build_nearby_npcs()`

- 新增 `current_room: str | None = None` 参数
- 在 `_build_snapshot()` 调用处，读取 `context.state.player.current_room` 并传入
- 新增 `is_room_local(npc_id)` 内部函数：
  - `current_room` 为 None → True（不过滤）
  - 否则查 `npc_rooms_lookup[npc_id] == current_room`
- 动态源 area_local 过滤：有 sub_location 时进一步按 room 过滤
- 静态补源：有 room 过滤时也过滤（静态补源无 room 信息 → 被排除）
