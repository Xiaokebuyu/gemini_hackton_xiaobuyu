## 二、可直接决策的结论

1. **L3 还没有实现“会话级 memory_graph 运行时化”**。`SessionRuntime` 只有 `world_graph` 生命周期，没有 `memory_graph` 字段、没有 `memory_snapshot` restore/persist 链路（`app/runtime/session_runtime.py:78`, `app/runtime/session_runtime.py:450`, `app/runtime/session_runtime.py:475`）。
2. **GraphScope 6 作用域仍是生产路径，不是历史遗留**：`world/chapter/area/location/character/camp` 全部仍在核心调用中（`app/models/graph_scope.py:16`, `app/services/admin/recall_orchestrator.py:79`, `app/services/admin/recall_orchestrator.py:105`, `app/tools/world_initializer/graph_prefill_loader.py:507`）。
3. **Recall 仍然是“每次从 Firestore 拉多 scope 再合图”**，并非读取会话内本地图（`app/services/admin/recall_orchestrator.py:81`, `app/services/admin/recall_orchestrator.py:175`）。
4. **MemoryGraphizer 仍是直写 Firestore**（节点/边逐条 upsert），不是写 `session.memory_graph`（`app/services/memory_graphizer.py:593`, `app/services/memory_graphizer.py:624`, `app/services/memory_graphizer.py:687`）。
5. **`scene_bus_graphizer.py` 与 `mcp/tools/graph_tools.py` 已删除**（当前代码确已清理这条链路）。
6. **`SessionHistory.maybe_graphize()` 目前没有主管线调用方**，主流程仅记录历史，不触发该链路；`AdminCoordinator._run_graphization()` 目前处于“定义但未被调用”状态（`app/services/admin/admin_coordinator.py:506`）。
7. **已补一个真实缺陷**：`RecallOrchestrator` 之前未使用 `RECALL_CONFIGS.depth`；现已修复为驱动 `max_iterations`（`app/services/admin/recall_orchestrator.py:68`, `app/services/admin/recall_orchestrator.py:287`），并新增回归测试 `tests/test_recall_orchestrator.py`。

## 五、当前可靠性风险（按优先级）

### P0
1. **架构认知偏差风险**：若按“只剩 3 scope”推进删除，会直接破坏 Recall/Prefill/测试链路。  
2. **迁移路径断层**：`SessionRuntime` 未承载 memory graph，无法实现“先本地改、后统一快照”的目标闭环。

### P1
1. **SessionHistory 图谱化未接主管线**：`_run_graphization()` 未被调用，导致会话历史窗口只累积不转图。  
2. **读写分散**：Recall/MemoryGraphizer/ImmersiveTools/FlashService/EventService 各自直连 GraphStore，后续切换到 runtime-local 改造面大。

### P2
1. **双 GraphScope 定义**：`app/models/graph_scope.py` 与 `app/models/graph_nodes.py` 各有一份 GraphScope，易混淆（后者当前主要用于 worldbook 工具类型体系）。  
2. **ContextWindow state 序列化不含 system_prompt**：`to_state/from_state` 仅保存 token，不保存提示词正文（`app/services/context_window.py:444`, `app/services/context_window.py:478`）。

## 七、建议的”从下往上”重构顺序（基于真实现状）

1. **先做 L3-0 基线冻结**：明确”当前仍是 6 scope + Firestore 直读写”为基线，先不删 scope。
2. **落地 L3-1 容器化**：在 `SessionRuntime` 增加 `memory_graph` + `memory_snapshot`（restore/persist）。
3. **落地 L3-2 读路径切换**：Recall 优先读 `session.memory_graph`，保留 Firestore fallback。
4. **落地 L3-3 写路径切换**：MemoryGraphizer/ImmersiveTools/FlashService 写入改为会话内存图，C 阶段统一 persist。
5. **最后做 L3-4 scope 收缩**：待读写都脱离 scope 后，再执行 chapter/camp/location 数据迁移与删减。

> **注**：以上路径在总方案 Rev 2 之后已被 WorldGraph 统一方案取代。当前执行路径为 L3-底层执行方案 Phase 1-6。
