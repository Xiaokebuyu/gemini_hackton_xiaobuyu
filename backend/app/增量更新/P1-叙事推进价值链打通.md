## 问题背景

当前叙事推进价值链存在三个关键断点：

```
QuestRegistry（里程碑骨架）
    |
NarrativePlanner
    | [断点1] LLM 收到的上下文只有 5/15+ 字段
    | spawn_quest_npc / direct_npc
    |
NarrativePlanSlice.npc_directives（写入成功）
    | [断点2] NPC Agent 对话时完全不读取 npc_directives
    |
NPC Agent（能说话，但不知道该引导玩家做什么）
    | speak / offer_quest
玩家交互
    | [断点3-a] success_conditions 未映射到 EventSlice
    | [断点3-b] milestone COMPLETED 后下游不解锁（设计文档漏洞）
    |
EventEngine（条件检查能力完整，但不处理 milestone 条件）
    |
NarrativePlanner 下一轮
```

## 设计补丁（对设计文档漏洞的补充）

### 补丁1：milestone 下游解锁的职责归属

**设计文档现状**：
- 初始化时 `create_new()` 根据 prerequisites 设 LOCKED/AVAILABLE
- 运行时 milestone COMPLETED 后，设计文档说"NarrativePlanner 下次读到新 AVAILABLE 里程碑自动播种"
- 但**没有指定谁负责把下游 milestone 从 LOCKED 转为 AVAILABLE**

**补丁决策**：新建 **MilestoneUnlockHook (P25)** 独立 Hook。理由：
- 职责最清晰——单一职责，只做 prerequisites 检查 + LOCKED→AVAILABLE 转换
- 不侵入 EventConditionHook (P20) 或 NarrativePlannerHook (P35) 的现有职责边界
- P25 排在 P20 (EventCondition) 之后、P35 (NarrativePlanner) 之前——同一 settlement 内完成解锁，Planner 直接看到 AVAILABLE
- 符合"不写 god file"原则

### 补丁2：NPC 指令消费走 NPCInstance 队列

**设计文档要求**：
- NPCInstance.directive_queue + consume_directive() + expires_at_tick + consumed 标记
- 完整方案依赖 NPCInstance 生命周期管理

**补丁决策**：按设计文档实现，通过 NPCInstance.directive_queue 路径。
- InstanceManager.get_or_create() 时从 NarrativePlanSlice 注入队列
- consume_directive() 弹出最高优先级未过期指令
- 注入 system prompt（`[重要行为指令]` 格式）
- **实例回收时回写 State**——LRU 淘汰前将未消费指令的 consumed 状态回写到 NarrativePlanSlice
- 需要 NPCInstance 新增 directive_queue 字段 + consume/expire/writeback 方法

## P1-A: Planner LLM 上下文补全

### 问题

LLM planner 已注入但 `_format_planner_context()` 只传了 5 个字段，Hook 构建了 15+ 字段。

```
Hook 构建的完整上下文（15+ 字段）:
  current_tick, time(day/slot/period), location(area_id/location_id),
  changed_slices, change_count, recent_changes(详细 StateChange),
  quests(available/active/completed + dynamic_quests),
  narrative_plan(chapter/target/completion/escalation/strategy_notes/behavior_window_size),
  area_cluster(area_id/has_capacity/total_dynamic),
  scene(entry_count/state_change_count)

LLM 实际收到（5 字段）:
  current_chapter, escalation_level, ticks_since_milestone_progress,
  current_target_milestone, available/active_milestones, pacing_frozen
```

### 设计对齐

设计文档（NarrativePlanner设计规范 §3.1 + §8）要求 plan() 接收四部分输入：
1. **故事蓝图**：当前章节里程碑图 + 状态 ← 当前只传了 milestone 列表
2. **玩家行为画像**：level, location, play_style_tags, recent_actions, area_cluster ← 完全缺失
3. **当前叙事计划状态**：活跃任务、升级等级、策略备注 ← 部分传了
4. **世界上下文**：area_npcs, area_description, relevant_factions ← 完全缺失

### 实施方案

**文件**：`app/narrators.py` — `_format_planner_context()`
**动作**：重写此函数，将 Hook 构建的完整上下文按设计文档四部分格式化为 LLM 可读文本。

补充字段：
- time/location（环境感知）
- recent_changes + changed_slices（触发上下文）
- strategy_notes（避免重复决策）
- area_cluster（fill_area 触发条件：has_capacity + total_dynamic）
- behavior_window 内容（不只是 size）

### 附带清理

| NarrativePlanSlice 字段 | 状态 | 处理 |
|------------------------|------|------|
| `play_style_tags` | 死数据（无消费者） | 暂保留，P1-D 时消费 |
| `behavior_window` | 半死（只传了 size） | P1-A 时传完整历史 |

## P1-B: NPC 指令消费链路

### 问题

`direct_npc` 指令成功写入 `NarrativePlanSlice.npc_directives`，但 NPC Agent 对话时零感知。

### 设计对齐

设计文档（NPC与队友运行时规范 §九）定义了完整路径：
- NPCInstance.directive_queue → consume_directive() → 系统提示注入
- 指令有 expires_at_tick + consumed 标记 + priority 排序

**按设计文档实现**（见设计补丁2）。

### 实施方案

**Step 1**：`instance_manager.py` — InstanceManager.get_or_create()
```
创建/恢复 NPCInstance 时：
  1. 从 NarrativePlanSlice.npc_directives 过滤该 npc_id 的指令
  2. 注入 instance.directive_queue（按 priority 排序）
  3. 过滤已过期指令（expires_at_tick < current_tick）
```

**Step 2**：`instance_manager.py` — NPCInstance 新增方法
```
directive_queue: list[NpcDirective]  # 新字段

consume_directive(current_tick) -> NpcDirective | None:
  - 过期检查：移除 expires_at_tick < current_tick 的指令
  - 弹出最高 priority 的未 consumed 指令
  - 标记 consumed = True
  - 返回指令（或 None）

flush_to_state(npc_directives: list) -> None:
  - LRU 淘汰前回调
  - 将 consumed 状态回写到 NarrativePlanSlice 对应条目
```

**Step 3**：`npc_interaction.py` — NpcInteractionCoordinator
```
execute_interaction() Step 1 中：
  if context_window is not None:
    directive = context_window.instance.consume_directive(current_tick)
    if directive:
      在 system_prompt 中追加 [重要行为指令] 块
```

**Step 4**：`context_builder.py` — `_build_npc_prompt_text()`
```
新增可选参数 active_directive: dict | None
若非空，在角色背景之后、工具规则之前追加：
  "## 行为指令
   [重要] 你收到了以下行为指令，请在对话中自然地融入：
   - {directive.kind}: {directive 详情} ..."
```

**Step 5**：`character_tools.py` — offer_quest 工具
- 修正 source 从 `"ai_osiris"` 改为 `"npc"`

## P1-C: 任务生命周期闭环

### 问题

手动推进已闭合（advance_quest 命令），自动推进三处断裂。

### 设计对齐

设计文档（叙事规划子系统设计规范 §6.3）明确：
> "动态任务的目标完成判定**不由 NarrativePlanner 负责**，而是复用 EventEngine"

职责分工：
- **NarrativePlanner (P35)** → 生成任务 + 投递指令（create_quest / direct_npc）
- **EventConditionHook (P20)** → 评估 success_conditions → 推进 milestone 状态
- **MilestoneUnlockHook (P25)** → 下游 prerequisites 检查 + LOCKED→AVAILABLE（设计补丁1）
- **NarrativePlanner 下一轮** → 读到新 AVAILABLE → Priority 1 播种

### 实施方案（三阶段）

#### Phase 1: success_conditions → EventSlice 映射

**触发点**：`NarrativePlannerHook._apply_directive()` 的 create_quest 分支
**动作**：
1. 从 `world.quests.get(milestone_id)` 读取关联 MilestoneTemplate
2. 遍历 `success_conditions`，为每条构造 Event 对象：
   ```
   event_id: f"milestone_{milestone_id}_sc_{index}"
   conditions: [{type: condition.type, params: condition.params}]
   state: "dormant"
   on_trigger: [{type: "advance_quest", params: {quest_id: milestone_id, to_state: "COMPLETED"}}]
   ```
3. 写入 EventSlice（`state.events.add_event()`）
4. 同理处理 failure_conditions（on_trigger → to_state: "FAILED"）

**文件**：`app/game_core/orchestration/hooks/narrative_planner.py`

#### Phase 2: EventEngine 自动推进 quest

**现状**：EventConditionHook 已能检查 7 种条件并执行 on_trigger 命令。
**需要验证**：Phase 1 生成的 Event 对象格式是否与 EventConditionHook 兼容。
**可能改动**：
- 确保 on_trigger 中的 `advance_quest` 命令在 `_ALLOWED_COMMAND_TYPES` 中（已在）
- 确保 Event dormant→triggered→active 状态机正常工作

**文件**：`app/game_core/orchestration/hooks/event_condition.py`（验证为主，可能无需改动）

#### Phase 3: 下游 milestone 自动解锁

**新建**：`MilestoneUnlockHook` (P25)
**位置**：`app/game_core/orchestration/hooks/milestone_unlock.py`
**职责**：
1. `should_skip(change_log)` — 检查 change_log 是否有 milestone 状态变为 COMPLETED
2. `execute(context)` — 对每个新 COMPLETED milestone：
   - 从 `world.quests` 读取 `next_milestones`
   - 对每个下游 milestone，从 `world.quests` 读取 `prerequisites`
   - 检查所有 prerequisites 是否在 `state.quests.milestone_states` 中为 COMPLETED
   - 满足则执行 `advance_quest(quest_id=next_id, to_state="AVAILABLE")`

**注册**：`defaults.py` 添加到 settlement hooks（P25，在 EventCondition P20 之后、NarrativePlanner P35 之前）
