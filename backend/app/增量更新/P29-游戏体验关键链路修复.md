# P29: 游戏体验关键链路修复

## Context

Live 测试暴露了一组**相互关联的系统性缺陷**：NPC 无法派发任务、动态子地点是空壳、战斗触发不了、Planner 大量 directive 被拒、私聊脆弱断裂、任务完成条件模糊、前端选项面板粒度不足。

修复分两批：**Batch A（后端）** 打通数据管线断点，**Batch B（前端）** 重构展示层让内容可见可交互。

**所有修改必须遵守架构边界**（详见 `app/博德之门3架构设计规范/`）：
- 状态变更走 Command→Handler→StateDelta
- 内容层只读，Planner 只做规划不做判定
- Planner 输出走 directive_contracts 校验
- NarrativePlanSlice 直接写入是唯一受控例外

## A6: 遗迹固定敌人（内容层驱动 + Planner 放置）

**目标**: 在 ancient_ruins 的 3 个子地点定义固定敌人配置，由 Planner 读取后通过 `planner_plant_encounter` 命令放置。

### 6a. 数据：maps.json 添加 hostile_config

**文件**: `data/goblin_slayer/v2/maps.json` — ancient_ruins 的 3 个子地点

| 子地点 | monster_ids | stealth_dc | blocking | threat_level | 叙事理由 |
|--------|------------|------------|----------|-------------|---------|
| outer_cloisters | `["goblin", "goblin", "goblin"]` | 12 | false | easy | 哨兵巡逻，可潜行绕过 |
| sacrificial_altar | `["hobgoblin", "goblin", "goblin"]` | 14 | true | moderate | 祭坛守卫，必须清除 |
| inner_sanctum | `["goblin_rider", "hobgoblin", "goblin", "goblin"]` | 16 | true | hard | Boss 房，精锐护卫 |

每个子地点加 `hostile_config` 字段：
```json
"hostile_config": {
  "hostile_groups": [
    {"monster_ids": ["goblin", "goblin", "goblin"], "role": "patrol"}
  ],
  "stealth_dc": 12,
  "blocking": false,
  "ambient_description": "回廊深处传来零散的脚步声和低沉的嘟囔。"
}
```

### 6b. Planner 上下文注入（整合到 A5）

**文件**: `app/game_core/orchestration/hooks/narrative_planner.py` — `_build_planner_context()`

在 `_build_planner_context()` 中（A5 已在修改此方法），添加 `hostile_config_locations` 字段：

```python
# 遍历当前区域的子地点模板
hostile_config_locations = []
if area_template:
    for sub_id, sub_tmpl in area_template.sub_locations.items():
        if sub_tmpl.hostile_config is not None:
            existing = context.state.areas.get_hostile_state(sub_id)
            hostile_config_locations.append({
                "sub_location_id": sub_id,
                "sub_location_name": sub_tmpl.name,
                "monster_ids": [mid for g in sub_tmpl.hostile_config.hostile_groups for mid in g.monster_ids],
                "stealth_dc": sub_tmpl.hostile_config.stealth_dc,
                "blocking": sub_tmpl.hostile_config.blocking,
                "already_planted": existing is not None and not existing.get("cleared", False),
                "already_cleared": existing is not None and existing.get("cleared", False),
            })
```

### 6c. Planner 引导文案（整合到 A5 的 guidance）

```
"encounter_guidance": "hostile_config_locations 列出了设计上应有敌人的子地点。对于 already_planted=false 且 already_cleared=false 的条目，应使用 planner_plant_encounter 指令放置敌人。参数：area_id, sub_area_id=子地点ID, monster_ids=怪物列表, threat_level, blocking, stealth_dc, map_category='ruins', expiry_ticks=-1（不过期，一次性）。"
```

### 6d. 已有机制确认（无需改动）

- `planner_plant_encounter` → `PlannerHandler._compute_plant_encounter()` ✓
- `NavigationHandler._compute_enter_sub_location()` line 230-267 ✓
- `HostileAreaHandler.enter_hostile` ✓
- **一次性不重生**：cleared 后 `already_cleared=true` → Planner 不会重复放置

**测试** (~4): hostile_config 解析 / planner context 状态 / 不重复放置
