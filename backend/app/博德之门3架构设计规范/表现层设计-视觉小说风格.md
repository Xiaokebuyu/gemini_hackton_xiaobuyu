# 表现层设计 — 视觉小说 (Galgame) 风格

创建时间：2026-02-26
状态：立项，后端先行适配
前置文档：`编排层设计规范.md`（SSE 事件来源），`叙事层设计规范.md`（Agent 叙述输出），`状态层设计规范.md`（SceneSlice 场景数据），`NPC与队友子系统设计规范.md`（四维好感模糊描述）

> 对应 BG3 六层架构的 ❻ 表现层。目标：让文字 CRPG 具备 Galgame 级视觉体验——场景背景、角色立绘、转场动画、粒子氛围。

---

## 一、视觉目标

```
┌─────────────────────────────────────────────────┐
│  [背景图：酒馆内部，暖色调，壁炉火光]              │
│                                                   │
│     [立绘：女神官]          [立绘：哥布林杀手]      │
│      (left, worried)        (right, neutral)      │
│                                                   │
│  ┌─────────────────────────────────────────────┐ │
│  │  女神官                                      │ │
│  │  "那个村庄的人们...我们必须尽快赶过去。"       │ │
│  │                        ▼ 打字机效果           │ │
│  │                                              │ │
│  │  [🎲 说服 DC12] 安抚她   [直接出发]   [再等等] │ │
│  └─────────────────────────────────────────────┘ │
│  HP ████████░░ 42/60    ⏰ 14:00 午后    💰 230G  │
└─────────────────────────────────────────────────┘
```

核心视觉元素：
- **场景背景** — 每个地点一张（可选：时段变体 morning/afternoon/evening/night）
- **角色立绘** — 全身立绘 + 表情差分（neutral/happy/angry/sad/surprised）
- **对话框** — 底部半透明面板，打字机效果，角色名高亮
- **选项按钮** — 支持能力检定标签 `[说服 DC14]`
- **转场动画** — 场景切换时 fade/dissolve/slide
- **粒子氛围** — 雨/雪/火星/魔法光点/灰尘（按地点 ambiance 标签）
- **HUD** — HP 条、时间槽、金币，常驻底栏或角落

## 二、前端技术栈（推荐）

| 层 | 技术 | 职责 |
|---|---|---|
| 视觉渲染 | **PixiJS 8** | 背景图、立绘、转场、粒子特效、光影 |
| 游戏 UI | **React 19** | 对话框、选项、背包、角色面板、地图 |
| 桥接 | **@pixi/react** | PixiJS 场景嵌入 React 组件树 |
| 状态管理 | **Zustand** | 轻量，适合游戏状态 |
| 通信 | **EventSource (SSE)** | 接后端流式事件 |
| 构建 | **Vite** | 快速 HMR |

不选的方案及原因：
- Phaser — 完整游戏引擎太重，VN 不需要物理/碰撞
- Three.js — 3D 引擎，文字游戏不需要
- 纯 CSS — 粒子/转场效果受限，无法做复杂视觉
- Monogatari.js — VN 专用但封闭，扩展不了 RPG 系统（背包/战斗/地图）

## 三、SSE 视觉事件协议

这是前后端的"合同"。后端 SSE 事件需要携带视觉指令，前端据此驱动渲染。

> **实现偏差注记（D-O21）— `action_result` / `stream_end` 等未按本文档归入编排层产出**
>
> 本文档将 `action_result` 定义为 SSE 事件协议的一部分，流程图（编排层 §A4）中写作
> "→ SSE action_result"，暗示它与 `dice_roll`、`scene_change` 等游戏内事件同源。
> 但当前实现中，`action_result`、`stream_end`、`stream_error`、`input_parsed`、`input_rejected`
> 均由应用层（`app/routers/gameplay.py`）构造，**不在** `PipelineResult.sse_events` 中。
>
> **未对齐的原因**：这些事件的内容不代表游戏世界里发生了什么，而是代表"这个 SSE 端点
> 该怎么和客户端交互"——`action_result` 是 PipelineResult 的摘要投影（与 REST 端点的
> `_action_execution_response` 是同一份数据的两种呈现），`stream_end/error` 是传输协议
> 信号，`input_parsed/rejected` 是解析器反馈。如果下沉到 game_core，编排层就会耦合
> 前端展示字段选择和流式传输协议。
>
> **后续对齐方向**：若将来需要统一，可在本文档中将这类事件单独标记为"端点级表现事件"，
> 与游戏内流式事件区分开。判定标准：事件内容描述游戏世界 → 编排层；事件内容描述
> 会话交互 → 应用层。

### 3.1 现有事件扩展

```jsonc
// npc_response — 扩展 character 视觉信息 + 情感
{
  "event": "npc_response",
  "data": {
    "character_id": "priestess",
    "character_name": "女神官",
    "text": "那个村庄的人们...我们必须尽快赶过去。",
    "emotion": "worried",        // ← FEELING_MAP 情感维度映射
    "portrait": "priestess/worried.png",  // 表情立绘 key
    "is_streaming": true         // 是否流式输出（打字机效果）
  }
}

// gm_narration — 环境叙述（无立绘，可能触发氛围变化）
{
  "event": "gm_narration",
  "data": {
    "text": "壁炉的火光在墙壁上投下摇曳的影子...",
    "ambiance_hint": "firelight"  // 可选：前端据此加粒子
  }
}

// gm_comment — GM 毒舌点评（不同渲染风格：斜体/灰色/旁白框）
{
  "event": "gm_comment",
  "data": {
    "text": "又在酒馆坐了整整一天，哥布林表示感谢。",
    "tone": "sarcastic"          // sarcastic | dry | impressed | ominous
  }
}

// dialogue_options — 扩展检定标签
{
  "event": "dialogue_options",
  "data": {
    "options": [
      {"id": 1, "text": "安抚她", "check": {"type": "persuasion", "dc": 12}},
      {"id": 2, "text": "直接出发", "check": null},
      {"id": 3, "text": "再等等", "check": null}
    ]
  }
}
```

**`action_result`**：玩家通过 `/action/stream` 触发的结构化动作执行结果汇总

```jsonc
{
  "event": "action_result",
  "data": {
    "action_type": "cast_spell",       // 动作类型标识（对应 ActionDispatcher 注册表）
    "success": true,                    // 兼容字段：= executed
    "executed": true,                   // 引擎执行是否成功
    "outcome": {                        // 可选：领域结果（检定/对抗/二值结果）
      "category": "check",
      "passed": true,
      "margin": 4
    },
    "summary": "你施放了火球术",        // 人类可读摘要
    "time_cost": 0.167,                 // 消耗的格数（1/6 格）
    "narrative_hints": ["火球在两只哥布林中间爆炸"],  // 叙事提示（传递给 GM Agent）
    "rolls": [                          // 关联的骰子投掷（与 dice_roll 事件的汇总）
      {"dice": "8d6", "result": 28, "type": "fire"}
    ]
    // 前端: 显示骰子动画 + 伤害数字 + 关联 VFX
    // 与 dice_roll 事件的关系：先推送 dice_roll × N，再推送 action_result（汇总）
  }
}
```

**`stealth_result`**：进入敌对子地点时自动潜行检定结果（NavigationHandler 触发）

```jsonc
{
  "event": "stealth_result",
  "data": {
    "success": true,
    "roll": 16,                                // d20 裸骰
    "dc": 13,                                  // 潜行 DC（= 敌人被动感知 + alert 修正）
    "modifier": 5,                             // DEX_mod + proficiency
    "advantage": false,                        // 是否优势骰（夜间 = true）
    "disadvantage": false,                     // 是否劣势骰（重甲 = true）
    "narrative": "你屏住呼吸，悄悄接近了营地...",
    "options": [                               // 仅潜行成功时有多选项
      {"action": "surprise_attack", "label": "发动突袭"},
      {"action": "sneak_through", "label": "潜行通过（不战斗）"},  // 仅 blocking=false 可选

    ]
    // 潜行失败时：options 为空（直接进入战斗，无选择）
    // 前端视觉：
    //   成功 → 暗色调 + 潜行图标 + 骰子动画（绿色）
    //   失败 → 画面闪红 + 警报音效 + 骰子动画（红色）
    //   大败（roll < dc-5）→ 额外"被突袭"提示（敌人反突袭轮）
  }
}
```

### P2：AssetResolver — 资产解析模块

机械模块，负责将资产 key 解析为可用 URL。不含 LLM——prompt 构造是模板化的。

**三级解析链**：

```
SSE 事件需要资产（如 scene_change.background）
    │
    ├─ L1: 缓存命中？→ 返回 URL（内存 / Redis）
    │
    ├─ L2: 静态资产表命中？→ 返回 URL
    │       资产表来源：❶ WorldInstance 加载时带入的 visual 字段
    │       格式：{ asset_key: url }
    │       覆盖：预制角色立绘、手绘场景、表情差分
    │
    └─ L3: 动态生成 → 构造 prompt → 调生图 API → 上传 Cloud Storage → 缓存 → 返回 URL
            触发场景：临时子区域（DynamicSubAreaManager）、临时路人 NPC（PasserbyService）、
                      缺失的时段变体、从未访问的地点首次进入
```

**Prompt 构造（模板化，非 LLM）**：

```python
class AssetPromptBuilder:
    """从结构化数据拼接生图 prompt。不调用 LLM。"""

    def build_scene_prompt(self, location_data: dict) -> str:
        """从地点数据构造场景生图 prompt。

        输入：description + tags + terrain_type + lighting + ambiance
        输出：结构化 prompt 字符串
        """
        # 示例输出：
        # "fantasy RPG scene, interior of a medieval tavern, warm firelight,
        #  wooden beams, stone walls, busy atmosphere, afternoon lighting,
        #  visual novel style, detailed background, no characters"

    def build_portrait_prompt(self, character_data: dict, emotion: str) -> str:
        """从角色数据构造立绘生图 prompt。

        输入：appearance + personality + tags + emotion
        输出：结构化 prompt 字符串
        """
        # 示例输出：
        # "fantasy RPG character portrait, middle-aged male farmer,
        #  torn clothes, bandaged left arm, fearful expression,
        #  visual novel style, full body, transparent background"
```

**API**：

```python
class AssetResolver:
    """资产解析器。机械模块，非 Agent。"""

    async def resolve(self, asset_key: str, context: dict | None = None) -> str:
        """解析资产 key 为 URL。context 用于 L3 动态生成时提供描述信息。

        asset_key 格式约定：
          场景：  "locations/{location_id}/{time_variant}.png"
          立绘：  "characters/{character_id}/full_body.png"
          表情：  "characters/{character_id}/{emotion}.png"
          临时：  "temp/{sub_area_id}/background.png"
                  "temp/{npc_id}/portrait.png"
        """

    async def resolve_batch(self, keys: list[str], contexts: dict[str, dict]) -> dict[str, str]:
        """批量解析。场景切换时可能同时需要背景 + 多个角色立绘。"""

    async def prefetch(self, asset_keys: list[str], contexts: dict[str, dict]) -> None:
        """预取。NarrativePlanner 生成临时子区域时提前调用，
        避免玩家进入时才触发生图（延迟太高）。"""

    def invalidate(self, asset_key: str) -> None:
        """缓存失效。临时子区域过期清理时调用。"""
```

**与 Pipeline 的集成**：

```
NarrativePlanner.plant_environmental()
    → DynamicSubAreaManager.create(sub_area)
    → AssetResolver.prefetch(["temp/{id}/background.png"], context=sub_area)  ← 预取，不阻塞
    ...（若干格后）...
玩家 enter_sub_location
    → AssetResolver.resolve("temp/{id}/background.png")  ← 命中缓存，立即返回
    → SSE: scene_change { background: url }

PasserbyService.spawn(npc)
    → AssetResolver.prefetch(["temp/{npc_id}/portrait.png"], context=npc_profile)
    ...
NPC 出现在对话中
    → AssetResolver.resolve("temp/{npc_id}/portrait.png")
    → SSE: character_enter { sprite: url }
```

**资产来源优先级**：

| 来源 | 质量 | 延迟 | 成本 | 适用 |
|------|------|------|------|------|
| 手工素材（画师/素材包） | 最高 | 0 | 前期投入 | 主要角色、核心场景 |
| AI 生成 + 缓存 | 中等 | 首次 3-10s，后续 0 | 按次计费 | 临时内容、缺失变体 |
| 通用占位图 | 低 | 0 | 0 | 兜底（生图失败/超时） |

**兜底策略**：生图 API 超时或失败时，返回同类型通用占位图（如 `fallback/forest_generic.png`），不阻塞游戏流程。前端收到占位图后正常渲染，后台异步重试生图。

## 补遗：增量实现中确立的图片生成系统（2026-03-05 追记）

> AssetResolver 模块在原始设计中仅有三级解析链概念。以下为实现中确立的具体系统。

### A. 缓存结构

磁盘缓存按 `scenes/{world_id}/{area_id}/{location_id}/{period}.png` 和 `portraits/{world_id}/{character_id}/{emotion}.png` 组织。场景按时段（dawn/day/dusk/night）生成变体。

### B. 两阶段立绘生成

1. **Base 生成**：纯文本 prompt 生成基础立绘
2. **Emotion 变体**：将 base 作为参考图输入，生成表情变体以保持角色一致性

### C. Gemini Multimodal API 集成

场景和 base 立绘使用纯文本生成；表情变体使用 prompt + 参考图的 multimodal 输入。
