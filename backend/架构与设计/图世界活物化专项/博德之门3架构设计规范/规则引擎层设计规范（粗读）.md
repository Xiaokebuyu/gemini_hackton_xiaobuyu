# ❷ 规则引擎层设计规范

创建时间：2026-02-26
状态：设计中
前置文档：`博德之门3架构深度分析.md` §二.❷，`内容层设计规范.md`，`状态层设计规范.md`，`AI-Osiris设计规范.md`

> ❷ 规则引擎 = 我们的 Mineflayer。
> 统一的指令执行器——所有决策方（玩家/AI Osiris/NPC Agent/战斗 AI）通过结构化 Command 交互，
> ❷ 负责验证、计算、返回 StateDelta。LLM 永远不直接碰状态。
>
> **核心约束：无状态纯函数。** 读 ❶ 模板 + ❸ 当前值 → 计算结果 → 返回 Delta，不自己写任何状态。

---

## 一、设计原则

| 原则 | 说明 |
|------|------|
| **统一入口** | 所有操作都通过 `Command → RulesEngine → StateDelta` 这一条路径，不可能绕过规则 |
| **无状态纯函数** | 不持有状态，不写 ❸。相同输入必得相同输出（骰子除外，但骰子种子可控） |
| **验证前置** | 每条 Command 先验证合法性，非法直接拒绝，不进入计算 |
| **真/假执行统一** | execute() 和 dry_run() 走同一条计算路径，区别只在调用方是否 apply delta |
| **Handler 注册制** | 按 command.type 分发到子处理器，新操作 = 新 Handler + 注册，零侵入 |
| **LLM 只决策不执行** | LLM 输出 Command JSON，❷ 执行。LLM 的"幻觉"在验证层就被拦截 |

---

## 二、核心架构

```
         任何决策来源
    ┌────────────────────────┐
    │ 玩家按钮 → Command     │
    │ AI Osiris → Command   │
    │ NPC Agent → Command   │
    │ 战斗 AI → Command     │
    │ GM extra_tools → Cmd  │
    └──────────┬─────────────┘
               │
               ▼
    ┌─── RulesEngine ──────────────────────────┐
    │                                           │
    │  1. 路由：command.type → Handler          │
    │  2. 验证：Handler.validate(cmd, state, w) │  ← 读 ❶ + ❸
    │  3. 计算：Handler.compute(cmd, state, w)  │  ← 纯函数 + 骰子
    │  4. 返回：ExecuteResult { delta, ... }    │  ← 不写 ❸
    │                                           │
    │  内部 Handler 注册表：                     │
    │  ├─ "attack"          → CombatHandler     │
    │  ├─ "cast_spell"      → SpellHandler      │
    │  ├─ "skill_check"     → SkillCheckHandler │
    │  ├─ "trade_buy"       → EconomyHandler    │
    │  ├─ "set_flag"        → FlagHandler       │
    │  ├─ ...               → ...               │
    │  └─ (新操作注册即可)                        │
    │                                           │
    └──────────────┬────────────────────────────┘
                   │
                   ▼
          ExecuteResult {
              success: bool,
              delta: StateDelta,          ← 要写入 ❸ 的变更集
              narrative_hints: [...],     ← 给 ❺ GM 的叙述提示
              rolls: [...],              ← 骰子记录（前端展示用）
              errors: [...]              ← 验证失败原因
          }
                   │
                   ├─ 真执行 → 调用方 apply(delta) 写入 ❸
                   └─ 假执行 → 调用方只读 delta（战斗 AI 评分）
```

### 2.1 核心接口

```python
class RulesEngine:
    """统一指令执行器——我们的 Mineflayer"""

    def __init__(self):
        self._handlers: dict[str, CommandHandler] = {}

    def register(self, handler: CommandHandler):
        self._handlers[handler.command_type] = handler

    def execute(self, command: Command, state: StateSnapshot, world: WorldInstance) -> ExecuteResult:
        """
        真执行（但不直接写 ❸——返回 delta 由调用方 apply）
        """
        handler = self._handlers.get(command.type)
        if not handler:
            return ExecuteResult.error(f"Unknown command type: {command.type}")

        # 1. 验证
        validation = handler.validate(command, state, world)
        if not validation.ok:
            return ExecuteResult.error(validation.reason)

        # 2. 计算
        return handler.compute(command, state, world)

    def validate(self, command: Command, state: StateSnapshot, world: WorldInstance) -> ValidationResult:
        """纯验证不执行——用于 UI 提前检查按钮可用性"""
        handler = self._handlers.get(command.type)
        if not handler:
            return ValidationResult(ok=False, reason="Unknown command type")
        return handler.validate(command, state, world)

    def dry_run(self, command: Command, state: StateSnapshot, world: WorldInstance) -> ExecuteResult:
        """假执行——和 execute 完全相同，语义标记为不应 apply"""
        result = self.execute(command, state, world)
        result.is_dry_run = True
        return result

    def batch_execute(self, commands: list[Command], state: StateSnapshot, world: WorldInstance) -> list[ExecuteResult]:
        """批量执行（AI Osiris 的 consequences 列表）"""
        results = []
        for cmd in commands:
            result = self.execute(cmd, state, world)
            if result.success:
                state = state.apply(result.delta)  # 在快照上叠加，保证顺序依赖
            results.append(result)
        return results
```

### 2.3 ExecuteResult 结构

```python
ExecuteResult = {
    success: bool,
    delta: StateDelta | None,        # 状态变更集（成功时）
    narrative_hints: list[str],       # 叙述提示（给 ❺ GM Agent 参考）
    rolls: list[DiceRoll],           # 骰子记录
    time_cost: float,                # 时间成本（格数，给 TickCoordinator）
    errors: list[str],               # 错误信息（失败时）
    is_dry_run: bool,                # 是否为假执行
}

StateDelta = {
    changes: list[StateChange],
    # StateChange = {
    #     slice: str,         # 目标切片名
    #     operation: str,     # "set" / "add" / "remove" / "modify"
    #     path: str,          # 字段路径 "player.hp" / "flags.stolen_idol"
    #     value: Any,         # 新值或增量
    # }
}

DiceRoll = {
    purpose: str,             # "attack_roll" / "damage" / "saving_throw" / "skill_check"
    dice: str,                # "1d20" / "2d6" / "8d6"
    result: int,              # 掷骰结果
    modifiers: list[dict],    # [{source: "proficiency", value: 3}, {source: "str_mod", value: 4}]
    total: int,               # 最终值 = result + sum(modifiers)
    critical: bool | None,    # 自然20/自然1（仅 d20）
}
```

### 2.4 CommandHandler 基类

```python
class CommandHandler(ABC):
    """指令处理器基类——每种 command.type 对应一个"""

    @property
    @abstractmethod
    def command_type(self) -> str:
        """处理的指令类型"""

    @abstractmethod
    def validate(self, cmd: Command, state: StateSnapshot, world: WorldInstance) -> ValidationResult:
        """验证指令合法性"""

    @abstractmethod
    def compute(self, cmd: Command, state: StateSnapshot, world: WorldInstance) -> ExecuteResult:
        """计算执行结果，返回 StateDelta"""
```

### 3.1 战斗领域 — CombatHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `attack` | `{attacker, target, weapon_id?}` | d20 攻击检定 → 伤害骰 → 状态附加 | 玩家/战斗AI |
| `cast_spell` | `{caster, spell_id, targets}` | 法术位消耗 → 效果计算（伤害/治疗/控制） | 玩家/战斗AI |
| `defend` | `{character}` | 本轮 +2 AC | 玩家/战斗AI |
| `disengage` | `{character}` | 本轮移动不触发借机攻击 | 玩家/战斗AI |
| `dash` | `{character}` | 额外移动力 = speed | 玩家/战斗AI |
| `shove` | `{attacker, target}` | STR 对抗 → 目标俯卧 | 玩家/战斗AI |
| `flee` | `{character}` | d20 ≥ 10 成功脱离战斗 | 玩家/战斗AI |
| `use_combat_item` | `{character, item_id, target?}` | 消耗品效果（药水/火油/圣水） | 玩家/战斗AI |
| `offhand_attack` | `{attacker, target}` | 副手武器攻击（bonus action） | 玩家/战斗AI |
| `start_combat` | `{monsters, surprise_state}` | 初始化战斗（含先攻检定 + 突袭轮） | 引擎 |

**战斗初始化与突袭轮（start_combat）**：

```
start_combat(monsters, surprise_state):

  surprise_state = "player_surprise" / "enemy_surprise" / "none"
  # 由 NavigationHandler 潜行检定结果决定

  1. 先攻检定（已有流程不变）：
     所有参战者 d20 + DEX_mod → 排序

  2. 突袭轮处理（新增）：
     if surprise_state == "player_surprise":
       Round 0（突袭轮）：
         → 仅玩家方行动（敌人方跳过整轮）
         → 突袭轮内的攻击对目标有 advantage
         → narrative_hint: "敌人还没反应过来！"
       Round 1+: 正常轮次

     elif surprise_state == "enemy_surprise":
       Round 0（被突袭轮）：
         → 仅敌方行动（玩家方跳过整轮）
         → narrative_hint: "你们被包围了！"
       Round 1+: 正常轮次

     else:  # "none"
       正常战斗，无突袭轮（直接从 Round 1 开始）
```

**攻击流程（attack Handler 内部）**：

```
0. 行动阻止检查（状态效果集成）
   if attacker.is_action_prevented():
     → 返回错误 "被眩晕，无法行动"
     → narrative_hint: "{attacker} 被眩晕了，无法采取任何行动"

1. 验证
   - attacker 有行动点？
   - target 在攻击范围内？
   - 武器熟练？

2. 优势/劣势判定（状态效果集成）
   attacker 劣势: 中毒(attack劣势) / 恐惧(attack劣势) → disadvantage
   attacker 优势: 隐匿(首次攻击) → advantage
   target 被攻击优势: 致盲 / 束缚 / 俯卧(近战) → advantage
   优劣势相消: advantage + disadvantage → 正常掷骰

3. 攻击检定
   d20 + attack_bonus vs effective_ac
   attack_bonus = proficiency + stat_mod + weapon_bonus
   stat_mod = STR_mod（近战）或 DEX_mod（远程/FINESSE）
   effective_ac = target.ac + target.get_effect_modifiers().get("ac", 0)
   # 例: 防御中(+2)、诅咒(-1) 等效果修正

4. 命中判定
   - 自然 20 → 暴击（伤害骰翻倍）
   - 自然 1 → 必定未命中
   - total ≥ effective_ac → 命中
   - total < effective_ac → 未命中

5. 伤害计算（命中时）
   damage = roll(weapon.damage_dice) + stat_mod
   暴击：damage = roll(weapon.damage_dice × 2) + stat_mod

6. 伤害类型处理
   - target 有 resistance(damage_type) → damage ÷ 2
   - target 有 vulnerability(damage_type) → damage × 2
   - target 有 immunity(damage_type) → damage = 0

7. 专注豁免检定（状态效果集成）
   if target.concentration and final_damage > 0:
     con_dc = max(10, final_damage // 2)
     con_save = d20 + target.CON_mod + (proficiency if 体质豁免熟练)
     if 失败:
       → break_concentration(target) → 移除相关效果
       → SSE concentration_broken

8. 状态效果附加
   if weapon 附带状态效果（effect_id）:
     template = SkillRegistry.get_status_effect(effect_id)
     if template.save_end_of_turn:
       save_dc = 8 + proficiency + STR_mod（武器效果）
       save = d20 + target.get_modifier(save_ability)
       if 失败: → apply_effect(target, effect_id, attacker, duration, save_dc)
     else:
       → 直接 apply_effect（无豁免效果如俯卧）

9. 隐匿消耗
   if attacker.has_effect("hidden"):
     → remove_effect(attacker, "hidden")  # 攻击后自动暴露

10. 返回 StateDelta
    - target.hp -= final_damage
    - attacker.action_used = true
    - (如有) target.active_effects += [effect]

11. 返回 narrative_hints
    ["暴击！匕首刺入要害", "地精弓箭手受到 12 点穿刺伤害"]
```

**施法流程**：`cast_spell` 委托给 §3.13 SpellHandler 处理，包含完整的法术位消耗、戏法缩放、升槽加骰、专注管理、效果附加等逻辑。详见 §3.13。

**战斗回合末效果结算**：

```
每个参战者回合结束时：
  1. 执行 tick_effects(character)（委托 §3.12 StatusEffectHandler）
     → tick 伤害/治疗 + 豁免检定 + 持续时间倒计 + 过期移除
  2. 专注检定: 本回合累计受伤 → CON save（如有）
  3. 回合限定效果过期: defending 等（end_of_next_turn 类型）
```

### 3.2 能力检定领域 — SkillCheckHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `skill_check` | `{character, skill, dc, advantage?, context?}` | d20 + 属性修正 + 熟练 vs DC | 玩家/引擎 |
| `saving_throw` | `{character, ability, dc}` | d20 + 属性修正 vs DC | 引擎（法术/陷阱触发） |
| `contest` | `{actor, target, actor_skill, target_skill}` | 双方各掷 d20 对抗 | 引擎（推撞/擒抱） |

**检定流程**：

```
d20 + ability_mod + (proficiency_bonus if proficient) vs DC

优势(advantage):  掷两次取高
劣势(disadvantage): 掷两次取低

自然 20 → 大成功（narrative_hint: 超乎寻常的成功）
自然 1  → 大失败（narrative_hint: 灾难性的失败）

返回:
  success: bool
  margin: int (total - dc，正=成功余量，负=差多少)
  rolls: [DiceRoll]
  narrative_hints: ["说服检定成功，守卫犹豫了一下让开了路"]
```

**DC 参考**（来自 ❶ SkillRegistry / 玩法设计）：

| DC | 难度 | 典型场景 |
|----|------|---------|
| 5 | 极简 | 爬一棵矮树 |
| 10 | 简单 | 撬一把普通锁 |
| 12 | 普通 | 说服一个中立 NPC |
| 15 | 困难 | 潜行通过警戒的守卫 |
| 18 | 极难 | 说服一个敌对 NPC |
| 20+ | 近乎不可能 | 欺骗一个洞察力极强的角色 |

### 3.3 导航领域 — NavigationHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `move_area` | `{from, to}` | 区域间移动，返回 travel_slots 时间成本 | 玩家 |
| `enter_sub_location` | `{area, location}` | 进入子地点 | 玩家 |
| `leave_sub_location` | `{area}` | 离开子地点回到区域 | 玩家 |

**移动验证**：

```
1. 连接存在？（MapRegistry 查询）
2. 连接未被阻断？（❸ AreaSlice 查询 blocked 状态）
3. 子地点营业时间？（SubLocationTemplate.available_hours vs 当前时段）

时间成本 = Connection.travel_slots（1-3 格）
子地点切换 = 0 格
```

**子地点合并查询**：`enter_sub_location` 验证时，合并两个来源：

```
可用子地点 = MapRegistry.get_sub_locations(area)      ← 静态（❶）
           + DynamicSubAreaManager.list_active(area)   ← 动态（❸）
```

动态子区域由 NarrativePlanner / AI Osiris 等 Hook 运行时生成，详见 `叙事规划子系统设计规范.md` §十一 DynamicSubAreaManager。`check` 模式的动态子区域需 `status >= discovered` 才可进入。

**导航成功后处理**：`move_area` / `enter_sub_location` 成功时，ExecuteResult 额外携带 `snapshot` 字段：

```python
LocationSnapshot = {
    area_id: str,
    location_id: str | None,              # 子地点 ID（如在子地点内）
    present_npcs: list[NpcPresence],       # 当前在场 NPC
    sub_locations: list[SubLocationBrief], # 可进入的子地点
    interactables: list[InteractableBrief],# 可交互物件
    exits: list[ExitBrief],               # 可前往的区域
    discovery_results: list[DiscoveryResult],  # 被动感知检定结果
}

NpcPresence = {
    character_id: str,
    name: str,
    role: str,              # main / secondary / passerby
    disposition_hint: str,  # friendly / neutral / wary / hostile（模糊四档，不暴露精确数值）
}

SubLocationBrief = {
    id: str,
    name: str,
    type: str,              # shop / quest / rest / visit / ...（来自 ❶ SubLocationTemplate.type）
    available: bool,        # 当前时段是否开放（available_hours vs TimeSlice.slot）
    tags: list[str],
}

InteractableBrief = {
    id: str,
    name: str,
    description_hint: str,  # 简短描述（"一块积灰的告示板"）
    requires_check: bool,   # 是否需要检定才能交互（来自 ❶ InteractableTemplate.check）
}

    target_area_id: str,
    name: str,
    travel_slots: int,
    blocked: bool,

```

LocationSnapshot 组装流程：

```
导航成功后（move_area / enter_sub_location）：
    1. present_npcs:
       ❶ CharacterRegistry.get_at_location(area, location, period)
       + ❸ 路人列表（如有）
       → 每个 NPC 查 ❸ RelationSlice → disposition_hint

    2. sub_locations:
       ❶ MapRegistry.get_sub_locations(area)
       + ❸ DynamicSubAreaManager.list_active(area)
       → 过滤 available_hours

    3. interactables（被动感知过滤）:
       ❶ SubLocationTemplate.interactables（InteractableTemplate 列表）
       + 动态子区域的 interactables（TemporarySubArea.interactables）
       → 过滤 one_time 且已交互的
       → 对有 visibility_dc 的物件做被动感知过滤（见下方）

    4. exits:
       ❶ MapRegistry.get_connections(area)
       → 查 ❸ AreaSlice blocked 状态

    5. discovery_results: → 见下方被动感知
```

**被动感知自动检定**：导航成功后 NavigationHandler 自动执行。纯机械，不掷骰。**两个扫描目标**：区域 Discovery + 可交互物 visibility_dc。

```
passive_perception = 10 + WIS_mod（来自 ❸ PlayerSlice）

═══ 扫描 1：区域 Discovery ═══
对目标区域的每个 Discovery（❶ AreaTemplate.discoveries）：
    if discovery.id ∈ ❸ AreaSlice.discovered_items:
        跳过（已发现过）
    elif passive_perception >= discovery.dc:
        ❸ AreaSlice.mark_discovery(area_id, discovery.id)
        → DiscoveryResult(success=True)
        → 若 reward.type == "sub_location":
            DynamicSubAreaManager.create(source="discovery") → 新子地点出现
    else:
        不显示（玩家不知道错过了什么）

═══ 扫描 2：可交互物感知门槛 ═══
对当前地点的每个 InteractableTemplate：
    if visibility_dc is None:
        始终可见 → 加入 location_overview
    elif passive_perception >= visibility_dc:
        可见 → 加入 location_overview
    else:
        不可见 → 不出现在 location_overview
        （玩家升级 WIS 后回来可能看到）

═══ 扫描 3：容器陷阱检测 ═══
对当前地点的每个 type="container" 且 container_data.trap != None 的 InteractableTemplate：
    if passive_perception >= trap.detect_dc:
        ❸ AreaSlice.container_states[id].trap_detected = true
        location_overview 中该容器追加 trapped_hint: true
        （不推送 discovery_reveal，陷阱信息在交互时才展示）
    else:
        trap_detected = false（玩家不知道有陷阱）
```

**成功发现 → 明确通知玩家**：被动感知成功时推送 SSE `discovery_reveal`，前端用明显视觉效果展示（如画面边缘闪光 + 提示文字），**不静默**。

```python
DiscoveryResult = {
    discovery_id: str,
    name: str,
    method: str,        # passive（被动感知）/ active（主动 skill_check）
    success: bool,
    check_type: str,    # perception / investigation / nature
    dc: int,
    roll: int | None,   # 被动感知 = None，主动检定 = d20 结果
    reward_hint: str,   # "你注意到灌木丛后面似乎有一条隐蔽的小径"
    reward_type: str | None,  # sub_location / item / quest_hook（触发对应后续）
}
```

注意：
- 被动感知**不掷骰**（无 SSE `dice_roll`），但成功时明确推送 SSE `discovery_reveal`（玩家看到发现提示）
- 未通过感知门槛的物件/Discovery **不出现** — 玩家不知道有东西错过了
- 同一 Discovery 只触发一次（`discovered_items` 去重）
- **可交互物的 visibility_dc 不去重** — 每次进入都重新计算（因为玩家可能升级了 WIS）
- 主动探索（玩家选择"查看周围环境"→ `skill_check` perception）走现有 SkillCheckHandler 路径，可发现被动感知错过的内容

**敌对子地点进入流程**：在被动感知扫描之后、LocationSnapshot 返回之前，新增敌对检测：

```
enter_sub_location 敌对检测（被动感知扫描之后）：

  if sub_location.hostile_config != None
     and sub_location 未 cleared（查 ❸ AreaSlice.hostile_tracking）:

    1. 潜行检定（自动，不需要玩家手动触发）：
       stealth_roll = d20 + DEX_mod + (proficiency if stealth_proficient)
       dc = hostile_config.stealth_dc
            + (5 if alert_state == "alert" else 0)

       修正：
         重甲 → disadvantage（掷两次取低）
         盗贼职业 → 可加 expertise（double proficiency_bonus）
         夜间（night period）→ advantage（掷两次取高）

    2. 推送 SSE stealth_result：
       {success, roll, dc, modifier, advantage, narrative}

    3. 根据结果设置战斗初始状态：
       a. 潜行成功（roll >= dc）：
          → 玩家获得突袭优势
          → SSE stealth_result 提供选项：
            - "突袭"：发起战斗，敌人被突袭（round 0 无法行动）
            - "潜行通过"：跳过战斗，直接进入子地点（仅非 blocking 可选）
            - "撤退"：返回上级区域

       b. 潜行失败（roll < dc）：
          → 敌人发觉入侵
          → 正常战斗（无突袭）
          → 若 roll < dc - 5（大败）且 hostile_config 有 role="ambush" 的组：
            敌人反突袭（round 0 玩家方无法行动）

  "潜行通过"后续（仅 blocking=false 且潜行成功时可选）：
    → 玩家进入子地点但跳过战斗
    → 子地点内敌人仍存在（未 cleared）
    → 可交互物正常可用（搜宝箱等）
    → 离开时需再次潜行检定（DC +2，敌人更警觉）
    → 失败 → 被围堵，强制战斗（无法撤退选项）
```

### 3.5 经济领域 — EconomyHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `trade_buy` | `{buyer, seller_npc, item_id, count?}` | 购买物品 | 玩家 |
| `trade_sell` | `{seller, buyer_npc, item_id, count?}` | 出售物品 | 玩家 |
| `refresh_shop` | `{npc_id}` | 刷新商店库存 | 引擎（长休/日期变化） |

**定价公式**：

```
购买价 = item.base_price × npc.sell_markup × disposition_discount(approval)
出售价 = item.base_price × npc.buy_rate

disposition_discount(approval):
    approval ≥ 80  → 0.70（最大折扣）
    approval ≥ 50  → 0.80
    approval ≥ 20  → 0.90
    approval < 20  → 1.00（原价）

验证:
    - buyer 有足够金币？
    - seller 商店库存中有该物品且 remaining > 0（或 unlimited）？
    - 商店是否营业？（当前时段检查）
    - 购买后 remaining -= count（unlimited 不减）
```

**商店刷新（`refresh_shop`）**：

```
1. 读取 ❶ CharacterTemplate.shop_inventory
2. base_pool 中 restock=true 的物品：补回到 count 数量
3. rotating_pool 中随机抽 rotating_slots 个物品
   → level_scaling=true 时过滤 min_player_level > 玩家等级的
4. 合并 base + rotating → 写入 ❸ RelationSlice.shop_state.current_stock
5. 更新 last_refresh_tick

触发时机（编排层）：
  - ❷ RestHandler.rest_long 成功后 → 对当前区域所有 refresh_on="long_rest" 的商人执行
  - P70 TimeAdvanceHook 日期变化时 → 对当前区域所有 refresh_on="daily" 的商人执行
```

**升级流程**：

```

   if current_xp + amount >= xp_for_next_level:
       trigger level_up

   - HP += ceil(hit_die/2) + 1 + CON_mod

   if class_template.spellcasting:

        new_slots = sc.spell_slots.get(new_level, {})

     b. 学习新戏法
        old_cantrips = sc.cantrips_known.get(old_level, 0)
        new_cantrips = sc.cantrips_known.get(new_level, old_cantrips)

     c. 学习新法术（已知型施法者，如法师）

4. 职业资源进阶:
   for feature in level_features.get(new_level, []):
     if feature.type == "resource":
       if feature.id in class_resources:
         → 提升 max（从 feature.resource_config.max_at_level）
         → current = max（升级时充满）
       else:
         → 新增资源（首次获得）
```

### 3.7 休息领域 — RestHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|

| `rest_long` | `{character, location?}` | 长休息 | 玩家 |

| `set_camp` | `{area_id, location_id?}` | 在当前位置建立营地 | 玩家 |

**短休息**：

```

- 恢复 recovery="short_rest" 的职业资源（第二风、气点等）
  → restore_resources_by_recovery("short_rest")
- 清除 cure_conditions 含 "short_rest" 的状态效果
  → 遍历 active_effects → template.cure_conditions 含 "short_rest" → remove_effect
- 不恢复法术位（标准 D&D 5e 规则）
- 时间成本：1 格
- 每天限 2 次
```

**长休息**：

```
- 恢复全部 HP
- 恢复全部法术位
  → restore_spell_slots()（全部等级 current = max）
- 恢复所有职业资源（recovery="long_rest" 和 "short_rest" 均恢复）

  → restore_resources_by_recovery("short_rest")

- 清除大部分状态效果
  → 遍历 active_effects → "long_rest" in cure_conditions → remove_effect

  → 返回标记 "may_prepare_spells": true
  → 玩家可发出 prepare_spells 指令
- 时间成本：剩余全部格（跳到次日 05:00）
- 每天限 1 次
- 守夜检定根据营地类型决定是否触发（见下方）
```

### 3.9 遭遇领域 — EncounterHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|

**遭遇检定（改造：不再直接开战，改为生成敌对子地点）**：

```
encounter_check(area_id, period):

  概率 = area.base_danger × period_multiplier
  period_multiplier: dawn=0.8, day=0.5, dusk=1.0, night=1.5

  roll = random()
  if roll < 概率:
    1. 从 area.encounter_table 加权随机抽一组敌人
    2. 构造 TemporarySubArea：
       {
         id: f"_encounter_{area_id}_{tick}",
         name: encounter_entry.description,      # "一队巡逻的哥布林"
         type: "encounter",
         target_area: area_id,
         hostile_config: {
           hostile_groups: [{
             monster_ids: encounter_entry.monster_ids,
             count: "按 encounter_entry 定义",
             role: "patrol",
           }],
           stealth_dc: 敌人群体最高 passive_perception,
           alert_state: "patrolling",
           blocking: danger_level >= 0.6,        # 高危区域 → 阻断型
           ambient_description: "你发现前方道路上有动静...",
         },
         discovery_mode: "auto",                 # 始终可见
         expiry_ticks: 6,                        # 6 格后消散
         source: "encounter",
       }
    3. DynamicSubAreaManager.create(spec) → 写入 ❸
    4. 注册到 ❸ AreaSlice.hostile_tracking
    5. SSE encounter_spotted 推送
    6. 玩家下次获取 location_overview 时看到该子地点
```

**clear_hostile（战后清除）**：

```
clear_hostile(sub_area_id):
  1. ❸ AreaSlice.hostile_tracking[sub_area_id].cleared = true
  2. ❸ AreaSlice.hostile_tracking[sub_area_id].cleared_at_tick = current_tick
  3. sub_area.hostile_config = None（运行时标记，不再触发潜行检定）
  4. narrative_hint: "这片区域已经安全了"

  后续处理（按 source 分流）：
    source="encounter"  → expiry_ticks 内自动移除（TemporarySubArea 机制）
    source="quest"      → 关联里程碑推进后由 NarrativePlanner retire
    source="permanent"  → 进入刷新等待（refresh_delay_ticks 后从 hostile_pool 抽新的）
    source="static"     → 标记 cleared，不刷新
```

**掉落生成**：

```
对每个击败的怪物:
    gold += roll(monster.gold_drop)
    for entry in monster.loot_table:
        if random() < entry.chance:
            items.append({id: entry.item_id, count: roll(entry.count)})
```

**掉落结果结构**：

```python
LootResult = {
    gold: int,                        # 总金币
    items: list[LootItem],            # 掉落物品列表
    source: str,                      # 来源描述（"3 只哥布林的战利品"）
}

LootItem = {
    item_id: str,
    name: str,                        # 冗余（前端展示用，免查 ItemRegistry）
    count: int,
    rarity: str,
}
```

**消费流程**：

```
generate_loot 返回 LootResult 后：

1. ExecuteResult.loot = LootResult
   → SSE loot_display（展示掉落列表，玩家可选取）

2. 金币自动入账：
   ❸ PlayerSlice.modify_gold(loot.gold)
   → 不需要玩家手动拾取

3. 物品由玩家选取（前端发 pick_up 命令）：
   Command(type="pick_up", params={item_id, count, source="loot"})
   → InventoryHandler 正常入库（走 ItemStack 堆叠逻辑）

4. 未拾取物品：
   本格结束后丢弃（不持久化，战场临时物）
   narrative_hint: "地上还散落着一些你不需要的东西..."

5. 尸体容器生成（显著敌人）：
   对每个阵亡的"显著敌人"（is_significant=true / boss / mini_boss 标签 / named NPC）：
     a. 从敌人 ❶ CharacterTemplate.equipment 收集装备物品
     b. 构造 InteractableTemplate(type="container", container_data={
          container_type: "corpse", locked: false, breakable: false, trap: None,

        })
     c. 注册到 ❸ AreaSlice.container_states（opened=false, source="corpse"）
     d. 追加到当前地点 interactables → 下次 location_overview 可见
   普通杂兵：不生成独立尸体，其掉落已汇入共享 LootResult

   判定"显著敌人"：
     - ❶ CharacterTemplate 中 is_significant=true
     - 或 tags 含 boss / mini_boss
     - 或 GM Agent 在战斗叙述中标记
```

### 3.10 容器领域 — ContainerHandler

处理 BG3 风格场景容器（宝箱/尸体/木桶等）的交互——开锁、拆陷阱、拾取内容物。

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `open_container` | `{container_id}` | 开启容器（含陷阱/锁完整流程） | 玩家 |

| `take_all` | `{container_id}` | 一键全拿 | 玩家 |

**open_container 完整流程**：

```
open_container(container_id):

1. 查 ❸ AreaSlice.container_states[container_id]
   → 已有 state 且 opened=true → 直接展示 remaining_items（SSE loot_display）
   → 不存在 → 从 ❶ InteractableTemplate 初始化 ContainerState

2. 陷阱检查（trap != None 且 trap_status != "disarmed"）：
   a. trap_detected == false（玩家未察觉陷阱）：
      → 触发陷阱！
      → 玩家受 trap.damage 伤害（❸ PlayerSlice.modify_hp）
      → SSE trap_triggered
      → narrative_hint: "宝箱上的符文闪烁了一下——火焰喷射而出！"
      → trap_status = "triggered"
      → 继续打开流程

   b. trap_detected == true 且 trap_status == "armed"：
      → 返回提示："你发现了陷阱，是否先拆除？"
      → SSE interact_check_options（含 disarm 路径 + "冒险打开" 选项）
      → 等待玩家选择（disarm_trap 或继续打开）

3. 锁检查（locked == true 且 lock_status != "unlocked"）：
   → SSE interact_check_options（撬锁 / 强行破开 / ...）
   → 玩家选择检定路径 → ❷ SkillCheckHandler 掷骰
   → 成功 → lock_status = "unlocked"，继续
   → 失败 → fail_consequence + 本次交互结束

4. 打开容器：
   a. 首次打开：掷骰 LootTable → 生成具体物品
      → gold 自动入账（❸ PlayerSlice.modify_gold）
      → items 存入 container_states[id].remaining_items
   b. 重复打开：直接展示 remaining_items

5. 推送 SSE loot_display：
   {source: container.name, container_id: id, gold, items}

6. 更新状态：
   container_states[id].opened = true
```

**disarm_trap 流程**：

```
disarm_trap(container_id):

1. 查 ❸ container_states → trap_status 必须为 "armed" 且 trap_detected == true
   （未检测到陷阱时不可拆除——玩家不知道有陷阱）
2. ❷ SkillCheckHandler.execute(thieves_tools, trap.disarm_dc)
3. 成功 → trap_status = "disarmed"
         → narrative_hint: "你小心翼翼地拆除了陷阱机关"
4. 失败 → 触发陷阱（同 open_container 步骤 2a）
```

**take_from_container / take_all**：

```
take_from_container(container_id, item_id, count=1):
  → 从 container_states[id].remaining_items 中扣减
  → 调 ❷ InventoryHandler.pick_up(item_id, count, source="container:{id}")
  → remaining_items 为空时 → looted = true
  → narrative_hint: "从 {container.name} 中取出了 {name} ×{count}"

take_all(container_id):
  → 遍历 remaining_items → 逐个调 pick_up
  → 清空 remaining_items → looted = true
  → narrative_hint: "你搜刮了 {container.name} 中的所有物品"
```

### 3.12 状态效果领域 — StatusEffectHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `apply_effect` | `{target, effect_id, source?, duration?, save_dc?, from_concentration?}` | 附加状态效果到目标 | 引擎/战斗AI |
| `remove_effect` | `{target, instance_id}` | 移除特定效果实例 | 引擎 |
| `remove_effect_by_type` | `{target, effect_id}` | 移除目标所有同类效果 | 引擎 |
| `tick_effects` | `{character}` | 结算一次所有活跃效果（P20 Hook / 战斗回合末调用） | 引擎 |

**apply_effect 流程**：

```
apply_effect(target, effect_id, source, duration?, save_dc?, from_concentration?):

  1. 验证
     - effect_id 在 SkillRegistry.status_effects 中？
     - target 存在（PlayerSlice 或战斗参与者）？

  2. 读取模板
     template = SkillRegistry.get_status_effect(effect_id)

  3. 叠加逻辑
     if target 已有同 effect_id 活跃:
       if template.stackable:
         existing.stack_count = min(existing.stack_count + 1, 3)  # 上限 3 层
         existing.remaining_duration = max(existing.remaining_duration, duration)
         → narrative_hint: "{name} 效果叠加到 {stack_count} 层"
       else:
         existing.remaining_duration = max(existing.remaining_duration, duration)  # 刷新持续时间
         → narrative_hint: "{name} 持续时间刷新"
     else:
       构造 ActiveEffect 实例
       → delta: target.active_effects += [new_effect]
       → narrative_hint: "{target} 受到了 {name} 效果！"

  4. 即时修正
     if template.modifiers:
       → delta 含 AC/攻击/速度调整（通过 get_effect_modifiers 聚合）
       → narrative_hint: "AC 降低了 2 点" 等

  5. 返回 StateDelta + narrative_hints
     time_cost = 0（效果附加是瞬时的，属于其他动作的一部分）
```

**remove_effect 流程**：

```
remove_effect(target, instance_id):
  1. 验证: target 有该 instance_id 的效果？
  2. 从 active_effects 移除
  3. if 效果有 modifiers → 修正自动在 get_effect_modifiers 聚合时消失
  4. narrative_hint: "{effect_name} 效果消失了"
  5. time_cost = 0
```

**tick_effects 流程**（P20 StatusEffectHook 和战斗回合末的核心）：

```
tick_effects(character):

  按 applied_at_tick 顺序处理每个 ActiveEffect:
    template = SkillRegistry.get_status_effect(effect.effect_id)

    1. Tick 伤害/治疗
       if template.tick_damage:
         damage = DiceEngine.roll(template.tick_damage)
         final_damage = damage.total × effect.stack_count  # 叠加层数倍增
         → delta: character.hp -= final_damage
         → rolls: [DiceRoll(purpose="effect_tick_damage", dice=...)]
         → narrative_hint: "{character} 受到 {name} 造成的 {final_damage} 点 {tick_damage_type} 伤害"

       if template.tick_heal:
         heal = DiceEngine.roll(template.tick_heal)
         → delta: character.hp = min(hp + heal, max_hp)
         → narrative_hint: "{character} 恢复了 {heal} 点生命值"

    2. 专注伤害检定（如果角色正在专注且受到了 tick 伤害）
       if character.concentration and damage_taken > 0:
         con_dc = max(10, damage_taken // 2)
         con_save = d20 + CON_mod + (proficiency if 体质豁免熟练)
         → rolls: [DiceRoll(purpose="concentration_save", ...)]
         if 失败:
           → break_concentration(character)
           → narrative_hint: "{character} 无法维持专注！{spell_name} 消散了"

    3. 回合结束豁免
       if template.save_end_of_turn:
         save = d20 + character.get_modifier(template.save_end_of_turn)
         dc = effect.save_dc or template.save_dc
         → rolls: [DiceRoll(purpose="effect_save", ...)]
         if 成功:
           → 移除效果
           → narrative_hint: "{character} 挣脱了 {name} 的束缚"

    4. 持续时间倒计
       effect.remaining_duration -= 1
       if remaining_duration == 0:
         → 移除效果
         → narrative_hint: "{name} 效果自然消退"

  返回: StateDelta（累计所有变更）+ DiceRolls + narrative_hints
```

### 3.13 法术领域 — SpellHandler

| command.type | params | 效果 | 来源 |
|-------------|--------|------|------|
| `cast_spell` | `{caster, spell_id, targets, slot_level?}` | 完整施法流程 | 玩家/战斗AI |
| `prepare_spells` | `{character, spell_ids}` | 准备当日法术列表 | 玩家（长休后） |
| `break_concentration` | `{character}` | 主动中断专注 | 玩家/引擎 |

**cast_spell 完整流程**：

```
cast_spell(caster, spell_id, targets, slot_level?):

  1. 读取模板
     spell = SkillRegistry.get_skill(spell_id)
     assert spell.category == "spell"

  2. 验证
     a. 是施法职业？（class 有 SpellcastingConfig）
     b. 法术已知或已准备？
        准备型: spell_id in prepared_spells?
        已知型: spell_id in known_spells?
     c. 行动类型可用？（spell.cost.action_type 与本轮可用行动匹配）
     d. 法术位检查：
        if spell.spell_level == 0:  # 戏法
          → 无需法术位，跳到步骤 4
        slot_level = slot_level or spell.spell_level  # 默认=基础等级
        assert slot_level >= spell.spell_level  # 不能降槽
        assert caster.has_spell_slot(slot_level)
     e. 目标在范围内？（spell.effect.range 检查）
     f. 资源检查（如有 spell.cost.resource）

  3. 专注检查
     if spell.effect.concentration:
       if caster.concentration is not None:
         old_spell = caster.concentration.spell_id
         → break_concentration(caster)  # 自动中断旧专注
         → narrative_hint: "{caster} 放弃了对 {old_spell} 的专注"

  4. 消耗资源
     if spell.spell_level > 0:
       → delta: caster.spell_slots[slot_level].current -= 1
     if spell.cost.resource:
       → delta: caster.class_resources[resource].current -= 1

  5. 效果计算（按 spell.effect.type 分支）

     === damage ===
     base_dice = spell.effect.dice

     升槽加骰:
       if slot_level > spell.spell_level and spell.effect.upcast_dice:
         extra_levels = slot_level - spell.spell_level
         base_dice += spell.effect.upcast_dice × extra_levels
         # 例: 治疗术 1d8 + upcast_dice="1d8" → 2 级槽=2d8, 3 级槽=3d8

     戏法缩放:
       if spell.spell_level == 0:
         base_dice = cantrip_scale(caster.level, spell.effect.dice)

     for each target:
       if spell.effect.save:  # 豁免类法术（火球等）
         spell_dc = 8 + proficiency + spellcasting_mod
         save = d20 + target.get_modifier(spell.effect.save) vs spell_dc
         if 成功 and half_on_save: damage = roll(base_dice) // 2
         elif 成功 and not half_on_save: damage = 0
         else: damage = roll(base_dice)
       else:  # 法术攻击（光线等）
         spell_attack = d20 + proficiency + spellcasting_mod vs target.effective_ac
         if 命中: damage = roll(base_dice)
         if 暴击: damage = roll(base_dice × 2)
         else: damage = 0

       → delta: target.hp -= damage
       if spell.effect.applies_status and (无豁免 or 豁免失败):
         → apply_effect(target, spell.effect.applies_status, caster,
                        duration=spell.effect.status_duration,
                        save_dc=spell_dc,
                        from_concentration=spell.effect.concentration)

     === heal ===
     heal = roll(base_dice) + spellcasting_mod
     升槽: heal += roll(upcast_dice) × extra_levels
     → delta: target.hp = min(hp + heal, max_hp)

     === buff / debuff ===
     → apply_effect(target, spell.effect.applies_status, caster, ...)

     === control ===
     save = target 豁免检定 vs spell_dc
     if 失败 → apply_effect(target, ...)

  6. 设置专注（如适用）
     if spell.effect.concentration:
       caster.concentration = ActiveConcentration(
         spell_id=spell_id,
         target_ids=targets,
         remaining_duration=spell.effect.status_duration or -1,
         applied_effects=[刚施加的效果 instance_ids],
       )

  7. 返回 StateDelta + DiceRolls + narrative_hints
     time_cost = 按 action_type: action→1/6, bonus_action→0, reaction→0
```

**专注机制**（跨系统规则）：

```
规则 1: 同时只能维持一个专注法术
  → 施放新专注法术自动中断旧的

规则 2: 受到伤害 → 体质豁免
  → con_dc = max(10, damage_taken // 2)
  → d20 + CON_mod + (proficiency if 体质豁免熟练)
  → 失败 → 专注中断

规则 3: break_concentration(character)
  1. 获取 concentration.applied_effects → 效果 instance_id 列表
  2. 对每个 instance_id → remove_effect（含目标身上的多目标效果）
  3. character.concentration = None
  4. narrative_hint: "{spell_name} 的效果消散了"

规则 4: 专注持续时间由 tick_effects 每回合倒计，归零 → 自动中断

集成点:
  - CombatHandler.attack 步骤 7: 伤害后对专注者触发 CON 豁免
  - StatusEffectHandler.tick_effects 步骤 2: tick 伤害后对专注者触发 CON 豁免
  - SpellHandler.cast_spell 步骤 3: 新专注 → 中断旧
  - RestHandler.rest_long: 长休 → 中断专注（睡着了）
```

**戏法缩放表**：

```
角色等级  骰子倍数  示例（base "1d10"）
1-4      ×1       1d10
5-10     ×2       2d10
11-16    ×3       3d10
17-20    ×4       4d10
```

**prepare_spells 流程**：

```
prepare_spells(character, spell_ids):
  1. 验证
     a. 职业使用准备系统？（SpellcastingConfig.prepared_formula != None）
     b. 数量不超限？max = eval(prepared_formula)  # 如 "WIS_mod + level" = 3 + 4 = 7
     c. 所有 spell_id 在 known_spells 中？
     d. 所有法术等级 <= 有法术位的最高等级？
  2. delta: character.prepared_spells = spell_ids
  3. narrative_hint: "{character} 准备了 {len(spell_ids)} 个法术"
  4. time_cost = 0（长休期间完成，不额外消耗时间）
```

## 五、骰子系统 — DiceEngine

所有随机性集中在 DiceEngine 中，其他 Handler 通过它获取随机数。

```python
class DiceEngine:
    """骰子引擎——所有随机性的唯一来源"""

    def roll(self, dice_expr: str) -> DiceRoll:
        """
        掷骰：支持 "1d20", "2d6+3", "8d6" 等表达式
        返回 DiceRoll（记录每个骰子的值，用于前端展示和审计）
        """

    def roll_check(self, modifier: int, dc: int, advantage: bool = False, disadvantage: bool = False) -> CheckResult:
        """
        d20 检定的便捷方法
        返回 CheckResult { success, total, roll, critical_success, critical_failure, margin }
        """

    def roll_with_seed(self, dice_expr: str, seed: int) -> DiceRoll:
        """
        确定性掷骰（测试用）——给定种子，结果确定
        """
```

骰子引擎是 ❷ 中唯一的非确定性来源。通过 `roll_with_seed` 可以让整个引擎在测试中完全确定。

## 六、假执行与战斗 AI

### 6.1 战斗 AI 效用评分流程

```
❹ 战斗 AI 的回合：

1. 读取战场快照（❸ 状态层）
2. 枚举所有合法动作（通过 RulesEngine.validate 过滤）
3. 每个动作 dry_run → 得到 ExecuteResult
4. 效用评分：
   score = success_rate × expected_damage × target_priority - self_risk

5. 选择最高分动作
6. RulesEngine.execute → 返回 delta
7. 调用方 apply(delta) → 写入 ❸
```

### 6.2 假执行的实现

假执行和真执行走**完全相同的代码路径**。区别：

| | 真执行 | 假执行 |
|---|---|---|
| 验证 | ✅ | ✅ |
| 计算 | ✅ | ✅ |
| 骰子 | 真随机 | 可选：真随机（蒙特卡洛）或期望值 |
| 返回 delta | ✅ | ✅ |
| 调用方 apply | ✅ | ✗（只看不写） |

战斗 AI 的假执行可以选择两种模式：
- **蒙特卡洛**：真掷骰 N 次取平均（精确但慢）
- **期望值**：用数学期望代替掷骰（快但粗糙）

```python
# 期望值模式
def expected_damage(dice_expr: str) -> float:
    """2d6+3 → 期望值 = 2×3.5+3 = 10.0"""

# 命中率
def hit_probability(attack_bonus: int, target_ac: int) -> float:
    """(21 - (target_ac - attack_bonus)) / 20，裁剪到 [0.05, 0.95]"""

# 效用 = hit_probability × expected_damage
```

## 七、narrative_hints — 给 ❺ 的叙述线索

每个 ExecuteResult 包含 `narrative_hints`——不是最终叙述文本，而是**事实性的线索**，帮助 GM Agent 生成叙述：

```python
# 攻击命中
narrative_hints = [
    "玩家用短匕首攻击哥布林弓箭手",
    "攻击检定: d20(17) + 5 = 22 vs AC 13, 命中",
    "伤害: 1d4(3) + 3 = 6 穿刺伤害",
    "哥布林弓箭手剩余 HP: 1/7"
]

# 潜行偷窃失败
narrative_hints = [
    "玩家尝试偷窃商人的治疗药水",
    "潜行检定: d20(4) + 3 = 7 vs DC 12(商人被动察觉), 失败",
    "商人发现了偷窃行为"
]

# AI Osiris: 好感度变化
narrative_hints = [
    "商人公会好感度 -5 (原因: 库存差异迟早会被发现)",
    "审判骑士审批值 -15 (原因: 目睹偷窃行为，与信仰冲突)"

```

GM Agent 拿到这些 hints，结合场景上下文生成文学化叙述。hints 是机械事实，叙述是 AI 包装——**P4 原则的直接体现**。

## 八、与其他层的集成

### 8.1 调用方职责

```
调用方（PipelineOrchestrator / TickCoordinator / CombatAI）
    │
    ├─ 构造 Command
    ├─ 调用 RulesEngine.execute(cmd, state_snapshot, world)
    ├─ 检查 result.success
    ├─ 如果成功：apply(result.delta) → 写入 ❸ StateContainer
    ├─ 如果失败：向玩家展示 result.errors
    ├─ 将 result.narrative_hints 传给 ❺ GM Agent
    ├─ 将 result.rolls 传给 ❻ 前端展示骰子动画
    └─ 将 result.time_cost 传给 TickCoordinator 累积
```

### 8.2 与 ❶ 内容层的关系

❷ 的 Handler 大量读取 ❶：
- CombatHandler → ItemRegistry（武器数据）、SkillRegistry（法术数据）、MonsterRegistry（怪物抗性）
- EconomyHandler → ItemRegistry（base_price）、CharacterRegistry（merchant markup）
- GrowthHandler → ClassRegistry（XP 曲线、升级特性）
- EncounterHandler → MapRegistry（遭遇表）、MonsterRegistry（掉落表）

❷ **只读** ❶，永远不写。

### 8.3 与 ❸ 状态层的关系

❷ 读取 ❸ 的快照做验证和计算，返回 StateDelta。

```
❸ StateContainer
    │
    ├─ snapshot() → StateSnapshot（只读快照，传给 ❷）
    │
    ├─ apply(delta) → 将 StateDelta 写入各切片
    │   ├─ delta.changes[0].slice == "player" → PlayerSlice.modify_hp(...)
    │   ├─ delta.changes[1].slice == "flags" → FlagSlice.set(...)
    │   └─ ...
    │
    └─ ❷ 不直接调用 ❸ 的写 API
```

### 8.4 与 AI Osiris 的关系

AI Osiris 的指令 → 转为 Command 列表 → `RulesEngine.batch_execute()` → 逐条验证执行。

```python
# TickCoordinator.tick_settlement() 中
osiris_output = ai_osiris.evaluate(changes, snapshot, rules)

commands = [
    Command(type=inst["type"], params=inst["params"], source="ai_osiris")
    for inst in osiris_output["consequences"]
]

results = rules_engine.batch_execute(commands, state_snapshot, world)
# 只 apply 成功的 delta
for result in results:
    if result.success:
        state_container.apply(result.delta)
```
