# P12 主路径偏离审计与文档对照

## 1. 目的

在 `Companion` 招募/离队链路迁回 `Command` 主路径之后，需要重新审计：

1. 当前后端还有哪些功能偏离了“`Command -> RulesEngine -> StateDelta`”主路径
2. 这些偏离是：
   - 真实实现问题
   - 设计文档内部冲突
   - 还是已被子系统文档明确允许的内部写入
3. 后续修正应该按什么顺序推进

这份文档不是直接给出所有修复方案，而是先建立一个**当前基线**，避免后续继续在“总设计 / 子系统设计 / 实际代码”三者之间来回漂移。

### 2.3 本文计为“偏离”的情况

满足任一条即计为偏离：

1. 设计文档明确要求经 `Command` / `RulesEngine` / 既有服务，但实现直接写状态
2. 设计文档要求复用既有运行时服务，但实现另起一条旁路
3. 直接写状态不在受控例外总表中，且跨越了子系统边界
4. 文档内部互相冲突，已经无法作为可靠边界说明

## 3. NarrativePlanner 叙事规划系统

本域包含 NarrativePlanner 的架构偏离和功能深度缺口。

### 3.1 `escalate` 不落世界状态

**架构偏离**。设计要求 `escalate` 产生 `set_flag / adjust_danger` 等命令交给 RulesEngine，实际只做 `adjust_escalation(delta)` 改内部计数器。

- 设计文档：[`叙事规划子系统设计规范（粗读）.md#L524`](/home/xiaokebuyu/workplace/gemini-hackton/backend/app/博德之门3架构设计规范/叙事规划子系统设计规范（粗读）.md#L524)
- 当前实现：[`narrative_planner.py#L1038`](/home/xiaokebuyu/workplace/gemini-hackton/backend/app/game_core/orchestration/hooks/narrative_planner.py#L1038)
- `escalation_level` 下游零游戏机制消费者（EncounterHook 读的是 `danger_level`，但 escalate 从不改它）
- `adjust_danger` 和 `set_flag` handler **都已存在**，`SettlementContext.execute_command()` 也已可用
- **玩家体感**：拖延主线时只会看到越来越急的任务推送，但世界永远不会变危险
- 修正：~20 行，在两处 `adjust_escalation()` 旁加 `context.execute_command()`

### 3.2 临时 NPC 在对话系统里是空壳

**功能缺失**。`spawn_quest_npc` 创建的 NPC 能出现在场景里、能被点击对话，但 `context_builder` 查 `CharacterRegistry` 查不到时没有 fallback 到 `temporary_npcs`。

- 当前实现：[`narrative_planner.py#L1057`](/home/xiaokebuyu/workplace/gemini-hackton/backend/app/game_core/orchestration/hooks/narrative_planner.py#L1057)
- 设计文档引用的 `PasserbyService` **在代码库中不存在**，是文档过时引用
- Agent 拿不到 NPC 的性格、外貌、对话钩子、关联任务
- **玩家体感**：任务 NPC 像失忆了，不知道自己是谁
- 另外 `despawn_tick` 到期后的自动移除也未实现

### 3.3 指令能力深度不足

**功能缺失**。8 种指令类型全部有代码，但缺少关键游戏机制触发能力。

| 缺口 | 说明 | 影响 |
|---|---|---|
| 不能触发检定 | 没有 `spawn_skill_check` 指令；检定只能由玩家主动或 EncounterHook 概率触发 | 无法实现”调查犯罪现场”等探索场景 |
| 不能投放可发现物品 | `plant_environmental` 只创建子地点，无 items/loot_table 字段 | 无法实现”找到隐藏钥匙”等发现机制 |
| 不能脚本化遭遇 | 遭遇完全由 EncounterHook 概率驱动；NarrativePlanner 无法”在这里安排伏击” | 叙事无法控制战斗时机和场景 |
| 场景变化无显式通知 | `plant_environmental` 静默创建子地点，不发 SSE | 玩家看不到环境变化（难民出现、区域被破坏等） |
| on_trigger 只硬编码 advance_quest | 设计要求任意 command 可被触发，实际只用了一种 | LLM 无法编排细粒度的条件→反应链 |

**用户想法**：场景生成前后应当有显式显示，让玩家知道世界发生了变化。

## 5. 战斗与遭遇系统

本域包含 hostile 状态管理的架构偏离和战斗系统的端到端可用性问题。

### 5.1 hostile 路由直写绕过 TickCoordinator

**架构偏离**。路由层 4 处直接 `upsert_hostile()` + `save_session()`，绕过 Hook 链、change_log、原子性保障。

- `combat.py:365` — sneak_through 选择
- `combat.py:645` — 重置为 spotted
- `combat.py:661` — 战斗结束停用
- `gameplay.py:502` — gameplay 侧重置（和 combat 版微妙不同——是否保留 `last_stealth_choice`）
- 两份 `_reset_hostile_to_spotted()` 实现有差异，设计气味
- **玩家体感**：潜行/战斗关键时刻 GM/队友像不在场一样沉默
- 修正：新建 2-3 个命令类型 + handler，重构 4 处路由调用

### 5.2 端到端不可用

**功能缺失**。后端 handler 齐全（13+ 命令、怪物 AI、状态效果），前端组件也有，但流程不通畅。

| 缺口 | 说明 |
|---|---|
| 遭遇触发条件苛刻 | 必须移动 + danger_level 达标 + 概率通过，很难自然触发 |
| 潜行检定强制介入 | 进入遭遇必过潜行检定，无法直接开打 |
| start_combat 不在 dispatcher | 设计意图 engine-only，缺少调试入口 |
| 怪物 AI bug | flee_chance=0 仍会逃跑 |

## 6. 世界知识积累系统

**功能缺失**。静态知识分发（content registry → 图谱种子 → L6 prompt）有效，但动态积累全链路断裂。

| 缺口 | 说明 | 影响 |
|---|---|---|
| write_episode 从不触发 | ContextWindow max_tokens=200K，溢出阈值 0.9；实际对话量远达不到 | NPC 对话结果不入图谱 |
| keyword 提取质量极差 | 纯空格分词，无 NER，噪音大命中低 | 检索结果不相关 |
| SceneBus → 图谱无反馈 | NPC 对话结果不沉淀到知识图 | NPC A 学到的东西 NPC B 看不到 |
| 对话记忆不持久 | ContextWindow 不持久化，NPC 重启后对话历史丢失 | “上次你跟我说了什么”完全不记得 |
| lore enrichment 几乎不执行 | 幂等保护 + LLM 依赖 + lore 可能为空 | 静态图谱无法被丰富 |

**核心问题**：NPC 知道静态世界背景，但不记得对话历史，也不知道其他地方发生了什么。

## 11. 当前结论

当前系统问题按域聚合后，核心矛盾是：

1. **NarrativePlanner**：骨架完整但指令浅薄，escalate 不改世界状态，临时 NPC 对话空壳，叙事无法驱动检定/物品/遭遇
2. **战斗/遭遇**：handler 齐全但路由绕行 + 触发门槛过高，端到端不可用
3. **世界知识**：静态分发可用，动态积累全断——NPC 不记得对话、不知道其他地方发生了什么
4. **物品/商店**：handler 齐全但游戏数据缺失，系统空转

后续应按 §10 待办清单逐域深化。每个域内先修架构偏离（小改动、闭合循环），再补功能深度（大改动、扩展能力）。
