# 子系统接入手册

创建时间：2026-02-26
状态：设计中
前置文档：所有层设计规范（❶ 内容层、❷ 规则引擎、❸ 状态层、❺ AI 叙事层、编排层）

> 每次新增子系统（坐骑、锻造、天气、声望……）时，遵循本手册的三步注册流程。
>
> 本手册是构建指导 + 操作清单，不是架构原理说明。
> 照着做就能把新子系统"插"进去，核心骨架零侵入。

## 一、核心原则

### 三步注册

```
Step 1.  ❶ 内容层 — 注册 ContentRegistry
         "这种实体的模板/定义长什么样"

Step 2.  ❸ 状态层 — 注册 StateSlice
         "这种实体的运行时状态长什么样"

Step 3.  流程层 — 接入游戏循环（涉及 ❷ + 编排层 + ❺）
         "这种实体参与什么规则、什么流程、Agent 能不能操作它"

         3a. ❷ CommandHandler — 新增的指令类型和规则计算
         3b. 编排层 PipelineHook — 格内管线扩展（可选）
         3c. 编排层 SettlementHook — 格结算钩子（可选）
         3d. ❺ AgentTool — Agent 可调用的工具（可选）
```

### 设计约束

| 约束 | 说明 |
|------|------|
| **零侵入** | 新子系统通过注册接入，不修改已有 Registry / Slice / Handler / Hook 的代码 |
| **模板-实例分离** | ❶ 存不可变模板，❸ 存可变运行时状态。不在 ❸ 中复制 ❶ 的数据 |
| **所有状态变更经 ❷** | 子系统的状态修改必须通过 Command → RulesEngine → delta，不可直接写 ❸ |
| **Agent 通过工具间接操作** | Agent 不直接调用 Handler，而是通过 AgentTool 构造 Command |
| **数据文件独立** | 新 Registry 的数据放在 `data/{world}/structured/` 下的独立 JSON 文件 |

### Step 1: ContentRegistry 基类

来自 ❶ 内容层设计规范。

```python
class ContentRegistry(ABC):
    """❶ 内容注册表基类。只读，加载后不可变。"""

    @property
    @abstractmethod
    def name(self) -> str:
        """注册表名称，用于 WorldInstance 注册寻址。"""

    @abstractmethod
    def load(self, data: dict) -> None:
        """从 JSON 数据加载。服务启动时调用一次。"""

    @abstractmethod
    def validate(self) -> list[str]:
        """自校验。返回错误列表（空 = 通过）。"""

    def get(self, entity_id: str) -> Any:
        """按 ID 查询单个实体模板。"""
        ...

    def all(self) -> list[Any]:
        """返回所有实体模板。"""
        ...

    def query_by_tags(self, tags: list[str]) -> list[Any]:
        """按标签组合查询。"""
        ...
```

注册到 WorldInstance：

```python
# WorldInstance 加载时
world_instance.register_registry("weather", WeatherRegistry())
world_instance.weather_registry.load(weather_data)
```

### Step 2: StateSlice 基类

来自 ❸ 状态层设计规范 §2.1。

```python
class StateSlice(ABC):
    """❸ 状态切片基类。可变，会话级生命周期。"""

    @property
    @abstractmethod
    def name(self) -> str:
        """切片名称，用于 StateContainer 注册寻址。"""

    @abstractmethod
    def restore(self, data: dict) -> None:
        """从持久化数据恢复（本地存档 or 云端）。"""

    @abstractmethod
    def serialize(self) -> dict:
        """序列化为可持久化格式。"""

    @abstractmethod
    def snapshot(self) -> dict:
        """生成只读快照（给 AI Osiris / ContextAssembler）。"""

    @property
    def dirty(self) -> bool:
        """是否有未持久化的变更。"""
        return self._dirty

    def clear_dirty(self) -> None:
        self._dirty = False
```

注册到 StateContainer：

```python
# 新会话创建时（Phase 3）

weather_slice.init_from_template(world.weather_registry.default_for(area_id))
```

### Step 3a: CommandHandler 基类

来自 ❷ 规则引擎层设计规范 §二。

```python
class CommandHandler(ABC):
    """❷ 指令处理器基类。无状态纯函数。"""

    @property
    @abstractmethod
    def command_types(self) -> list[str]:
        """本 Handler 处理的 command.type 列表。"""

    @abstractmethod
    def validate(
        self, cmd: Command, state: StateContainer, world: WorldInstance
    ) -> ValidationResult:
        """验证指令合法性。读 ❶ + ❸，不写任何状态。"""

    @abstractmethod
    def compute(
        self, cmd: Command, state: StateContainer, world: WorldInstance
    ) -> ExecuteResult:
        """计算结果。纯函数 + 骰子。不写任何状态。"""
```

```python
class SettlementHook(ABC):
    """格结算钩子。每格结算时按优先级调用。"""

    @property
    @abstractmethod
    def priority(self) -> int:
        """P10-P19 遗留 | P20-P29 状态tick | P30-P39 AI |
        P40-P49 随机事件 | P50-P59 事件机 | P60-P69 NPC |
        P70-P79 时间推进 | P80-P89 叙述 | P90-P99 清理"""

    @property
    @abstractmethod
    def name(self) -> str: ...

    @abstractmethod
    async def execute(self, change_log, state, world, rules_engine, scene_bus) -> HookResult:
        ...

    def should_skip(self, change_log) -> bool:
        return False
```

**Registry 实现**：

```python
class WeatherRegistry(ContentRegistry):
    name = "weather"

    def load(self, data: dict) -> None:
        self._climate_zones = {
            k: ClimateZone(**v) for k, v in data["climate_zones"].items()
        }
        self._effects = {
            k: WeatherEffect(**v) for k, v in data["weather_effects"].items()
        }

    def validate(self) -> list[str]:
        errors = []
        for zone in self._climate_zones.values():
            for state, transitions in zone.transition_table.items():
                total = sum(transitions.values())
                if abs(total - 1.0) > 0.01:
                    errors.append(f"{zone}: {state} 转移概率总和 {total} ≠ 1.0")
        return errors

    def get_climate(self, area_id: str) -> ClimateZone:
        return self._climate_zones.get(area_id, self._default_zone)

    def get_effect(self, weather: str) -> WeatherEffect:
        return self._effects[weather]
```

### Step 2: ❸ WeatherSlice

```python
class WeatherSlice(StateSlice):
    name = "weather"

    def __init__(self):
        self._dirty = False
        self.current: dict[str, str] = {}       # area_id → weather_type
        self.duration: dict[str, int] = {}       # area_id → 当前天气已持续格数
        self.last_change_slot: dict[str, int] = {}  # area_id → 上次变化的格编号

    def restore(self, data: dict) -> None:
        self.current = data.get("current", {})
        self.duration = data.get("duration", {})
        self.last_change_slot = data.get("last_change_slot", {})

    def serialize(self) -> dict:
        return {
            "current": self.current,
            "duration": self.duration,
            "last_change_slot": self.last_change_slot,
        }

    def snapshot(self) -> dict:
        """AI Osiris / ContextAssembler 看到的天气快照。"""
        return {
            area_id: {"weather": weather, "duration_slots": self.duration.get(area_id, 0)}
            for area_id, weather in self.current.items()
        }

    def get_weather(self, area_id: str) -> str:
        return self.current.get(area_id, "clear")

    def set_weather(self, area_id: str, weather: str, current_slot: int) -> None:
        self.current[area_id] = weather
        self.duration[area_id] = 0
        self.last_change_slot[area_id] = current_slot
        self._dirty = True

    def increment_duration(self, area_id: str) -> None:
        self.duration[area_id] = self.duration.get(area_id, 0) + 1
        self._dirty = True
```

**注册到 StateContainer**：

### Step 3a: ❷ WeatherCommandHandler

天气系统引入一个新指令类型：`weather_change`（由 SettlementHook 产生）。

```python
class WeatherCommandHandler(CommandHandler):
    command_types = ["weather_change"]

    def validate(self, cmd, state, world) -> ValidationResult:
        area_id = cmd.params["area_id"]
        new_weather = cmd.params["new_weather"]

        if area_id not in state.area_slice.areas:
            return ValidationResult(valid=False, errors=["区域不存在"])
        if new_weather not in world.weather_registry._effects:
            return ValidationResult(valid=False, errors=["天气类型不存在"])

        return ValidationResult(valid=True)

    def compute(self, cmd, state, world) -> ExecuteResult:
        area_id = cmd.params["area_id"]
        new_weather = cmd.params["new_weather"]
        effect = world.weather_registry.get_effect(new_weather)

        return ExecuteResult(
            success=True,
            delta=StateDelta(changes=[
                StateChange(slice="weather", operation="set_weather",
                            path=area_id, value=new_weather),
                StateChange(slice="areas", operation="adjust_property",
                            path=f"{area_id}.visibility", value=effect.visibility),
            ]),
            narrative_hints=[
                f"天气变化：{area_id} 区域转为 {new_weather}",
                f"能见度降至 {effect.visibility:.0%}",
            ],
            rolls=[],
            time_cost=0,  # 天气变化不消耗玩家时间
        )
```

### Step 3b: PipelineHook — 天气影响旅行

```python
class WeatherTravelHook(PipelineHook):
    """引擎执行移动后，根据天气调整旅行时间。"""
    extension_point = "after_engine"
    priority = 35

    async def execute(self, context: PipelineContext) -> None:
        # 只关心移动动作
        if context.last_command.type != "move_area":
            return

        area_id = context.last_command.params["destination"]
        weather = context.state.weather_slice.get_weather(area_id)
        effect = context.world.weather_registry.get_effect(weather)

        if effect.travel_speed < 1.0:
            # 修改返回的 time_cost（乘以天气速度系数的倒数）
            original_cost = context.result.time_cost
            adjusted_cost = original_cost / effect.travel_speed
            context.result.time_cost = adjusted_cost
            context.result.narrative_hints.append(
                f"恶劣天气减缓了行军速度（{effect.travel_speed:.0%}）"
            )
```

### Step 3c: SettlementHook — 每格滚天气

```python
class WeatherSettlementHook(SettlementHook):
    """每格结算时检查天气变化。"""
    priority = 45  # P40-P49 随机事件区间
    name = "weather"

    async def execute(self, change_log, state, world, rules_engine, scene_bus) -> HookResult:
        commands = []
        sse_events = []

        player_area = state.player_slice.current_area
        climate = world.weather_registry.get_climate(player_area)
        current_weather = state.weather_slice.get_weather(player_area)

        # 根据转移概率表决定是否变天
        transitions = climate.transition_table.get(current_weather, {})
        new_weather = self._weighted_random(transitions)

        if new_weather != current_weather:
            # 产生 weather_change Command → 交给 ❷ 执行
            commands.append(Command(
                type="weather_change",
                source="engine",
                params={"area_id": player_area, "new_weather": new_weather},
            ))
            sse_events.append(SSEEvent(
                type="weather_change",
                data={"area": player_area, "weather": new_weather},
            ))
        else:
            # 天气不变，持续时间 +1
            state.weather_slice.increment_duration(player_area)

        return HookResult(commands=commands, sse_events=sse_events)

    def _weighted_random(self, transitions: dict[str, float]) -> str:
        """按概率权重随机选择。"""
        import random
        items = list(transitions.items())
        weights = [w for _, w in items]
        return random.choices([k for k, _ in items], weights=weights, k=1)[0]
```

**注册到 TickCoordinator**：

### Step 3d: ❺ AgentTool — 感知天气

GM/NPC/队友都可能需要"看看天气"来辅助叙述。

```python
class CheckWeatherTool(AgentTool):
    name = "check_weather"
    description = "查看当前位置的天气状况和影响。"
    parameters = {}  # 无参数，自动读当前位置
    allowed_roles = ["gm", "npc", "teammate"]

    async def execute(self, params: dict, context: AgentContext) -> ToolResult:
        area_id = context.state.player_slice.current_area
        weather = context.state.weather_slice.get_weather(area_id)
        effect = context.world.weather_registry.get_effect(weather)
        duration = context.state.weather_slice.duration.get(area_id, 0)

        return ToolResult(
            success=True,
            data={
                "weather": weather,
                "visibility": effect.visibility,
                "duration_slots": duration,
                "tags": effect.tags,
                "description": self._describe(weather, duration),
            },
            # 纯读取，不产生 Command
            command=None,
        )

    def _describe(self, weather: str, duration: int) -> str:
        descriptions = {
            "clear": "晴空万里",
            "cloudy": "乌云密布",
            "rain": f"{'淅沥小雨' if duration < 3 else '连绵阴雨'}",
            "storm": "暴风骤雨，电闪雷鸣",
            "snow": f"{'飘着细雪' if duration < 3 else '大雪纷飞'}",
            "fog": f"{'薄雾弥漫' if duration < 3 else '浓雾笼罩，难以视物'}",
        }
        return descriptions.get(weather, weather)
```

```
✅ Step 3b: WeatherTravelHook 加入 PipelineOrchestrator

联动更新：

□ ContextAssembler → L2 区域层加入天气描述
     → assembler 需要读 weather_slice.get_weather(area) 并加入上下文

□ 前端 SSE → 新增 weather_change 事件类型
     → 前端收到后切换氛围粒子效果（rain → 雨粒子，fog → 雾效果）
□ 表现层 → 天气 tag 映射到 ambiance preset（见 ❻ 表现层设计 §3.3）
```

## 五、联动点 Checklist

**每个新子系统上线前，逐条检查：**

### 数据层联动

| # | 检查项 | 说明 |

## 六、反模式清单

### ❌ 反模式 1：绕过 ❷ 直接写 ❸

```python
# ❌ 错误
def on_weather_change(state, new_weather):
    state.weather_slice.current[area] = new_weather    # 直接写！
    state.area_slice.areas[area].danger_level += 0.1   # 直接写！

# ✅ 正确
def on_weather_change(rules_engine, state, world, area, new_weather):
    cmd = Command(type="weather_change", params={"area_id": area, "new_weather": new_weather})
    result = rules_engine.execute(cmd, state, world)
    state.apply(result.delta)  # 通过 delta 统一应用
```

**为什么**：直接写跳过了验证、跳过了 narrative_hints 生成、跳过了 delta 追踪。GM 不知道发生了什么，AI Osiris 看不到变化记录。

### ❌ 反模式 2：在 ❶ Registry 中存可变数据

```python
# ❌ 错误
class WeatherRegistry:
    def update_climate(self, area_id, new_pattern):
        self._climate_zones[area_id] = new_pattern  # ❶ 应该是只读的！

# ✅ 正确
# 可变数据放在 ❸ WeatherSlice 中
# ❶ WeatherRegistry 只存不变的气候模式模板
```

**为什么**：❶ 是所有会话共享的世界级单例。如果一个会话改了 ❶，所有会话都受影响。

### ❌ 反模式 3：SettlementHook 直接调用其他 Hook

```python
# ❌ 错误
class WeatherSettlementHook(SettlementHook):
    async def execute(self, ...):
        # 天气变了 → 直接调用遭遇 Hook 重新检定
        encounter_hook = self._find_hook("encounter")
        await encounter_hook.execute(...)  # Hook 之间耦合！

# ✅ 正确
# 天气 Hook 只负责产生 weather_change Command
# 遭遇 Hook 在更晚的优先级（P40 > P45）自然会读到新的天气状态
# 优先级链保证了执行顺序，Hook 之间通过 ❸ 状态通信
```

**为什么**：Hook 之间应该通过 ❸ 状态间接通信（状态是唯一通信介质），而不是直接调用。优先级链保证了"先写后读"的顺序。

### ❌ 反模式 4：Agent 工具中嵌入业务逻辑

```python
# ❌ 错误
class MountTool(AgentTool):
    async def execute(self, params, context):
        mount = context.state.mount_slice
        if mount.stamina < 3:
            return ToolResult(success=False, error="坐骑太累了")
        mount.stamina -= 1        # 直接写状态！
        mount.is_mounted = True   # 业务逻辑在工具里！

# ✅ 正确
class MountTool(AgentTool):
    async def execute(self, params, context):
        cmd = Command(type="mount", source=f"npc:{context.character_id}", params={})
        result = context.rules_engine.execute(cmd, context.state, context.world)
        # 验证、stamina 检查、状态变更全在 ❷ Handler 中
        return ToolResult(success=result.success, command=cmd, data=result)
```

**为什么**：工具是 Command 构造器，不是业务逻辑容器。所有规则判断和状态计算必须在 ❷ 中。

### ❌ 反模式 5：在 Hook 中做 LLM 调用（P30 除外）

```python
# ❌ 错误
class WeatherSettlementHook(SettlementHook):
    priority = 45
    async def execute(self, ...):
        # 让 LLM 描述天气变化
        description = await llm.generate("描述天气从晴转雨...")  # Hook 中调 LLM！

# ✅ 正确
# Hook 只产生 narrative_hints 和 Command
# LLM 叙述由 P80 GmNarrationHook 统一处理
# narrative_hints 写入 SceneBus，GM Agent 在 P80 读取并叙述
```

**为什么**：SettlementHook 链是确定性的顺序执行。非 AI 相关的 Hook 中插入 LLM 调用会导致延迟不可控、失败处理复杂。LLM 叙述统一由 P80 处理。

### ❌ 反模式 6：新 Slice 不处理旧会话兼容

```python
# ❌ 错误
class WeatherSlice(StateSlice):
    def restore(self, data: dict):
        self.current = data["current"]  # 旧会话没有 "current" → KeyError!

# ✅ 正确
class WeatherSlice(StateSlice):
    def restore(self, data: dict):
        self.current = data.get("current", {})  # 旧会话缺失时用默认值
        self.duration = data.get("duration", {})
```

**为什么**：线上已有会话不会有新 Slice 的持久化数据。恢复时必须优雅降级到默认值。
