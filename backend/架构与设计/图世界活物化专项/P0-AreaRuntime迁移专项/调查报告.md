## 一、背景

`area_runtime.py`（~547 行）在 commit `c3d25ef` ("update-for-rebuild") 中从源码删除，但 `.pyc` 缓存仍存在于 `app/runtime/__pycache__/area_runtime.cpython-313.pyc`，Python 运行时通过 bytecode 缓存加载。

**现状**：SessionRuntime / EventMachine / ContextAssembler / IntentExecutor 仍依赖 AreaRuntime 的类/方法，全靠 .pyc 兜底。

**目标**：彻底消除对 `area_runtime.py` 的依赖，使代码库不依赖 .pyc 缓存也能正常运行。

## 六、关键发现

1. **AreaRuntime 的核心价值只剩上下文生成**：`get_area_context()` 和 `get_location_context()` 是 ContextAssembler 仍在调用的唯二方法。其余功能（事件状态机 → BehaviorEngine，导航状态 → IntentExecutor）已完成迁移。

2. **`_summarize_completion_conditions` 是纯函数**：不依赖任何实例状态，接收 raw dict/ConditionGroup，输出中文摘要字符串。可直接提取为独立模块。

3. **`record_action` 写入的数据无消费方**：`current_visit_log` 仅在 `unload()` 时写入 `VisitSummary.actions_taken`，而 VisitSummary 写入 Firestore 后无任何代码读取它。可安全删除。

4. **area state 已有两套**：WorldGraph 节点 `.state` 存了 `visit_count`（IntentExecutor 维护），AreaRuntime 的 AreaState 也存了同样字段。两者可能不一致。迁移后统一为 WorldGraph 单一源。

5. **`self.current_area` 是个大状态袋子**：SessionRuntime 持有 `current_area: Optional[AreaRuntime]` 作为整个区域的运行时容器。迁移后这个字段可以删除，所有需要的数据从 WorldGraph + WorldInstance 按需查询。
