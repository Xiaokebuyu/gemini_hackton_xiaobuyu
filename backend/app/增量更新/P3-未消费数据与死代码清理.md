## 一、审计方法论

对全部 10 个 ContentRegistry、11 个 StateSlice、data/ 目录、handlers/hooks/tools/adapters 进行穷举式调查：
- 每个 dataclass 字段逐一追踪消费链路
- 每个 public method 逐一搜索调用者
- 每个数据文件逐一确认加载路径
- 交叉比对架构设计文档的预期用途

审计结论分三类：
1. **真死** — 可安全删除/归档
2. **未消费但设计预期** — 需要实现消费端（属于功能 gap，不是"清理"）
3. **低活跃但正确** — 留置，后续子系统深化时自然激活

## 六、综合分析：断裂的数据管线

调查发现的不是零散的"死代码"，而是 **系统性的数据管线断裂** — schema 定义完整但消费逻辑缺失。按断裂严重程度排序：

### 6.1 Buff/Debuff 管线（修正：断裂点在创建层）

> **2026-03-05 修正**：读取端（get_effect_modifiers 等）已有消费者。真正断裂的是效果创建层——模板行为字段未传播到运行时 dict + 数据未填充。

```
StatusEffectTemplate.disadvantage_on    ──→  (数据未填充)
StatusEffectTemplate.modifiers          ──→  (数据未填充)
        ↓
    build_spell_effect_instance()       ──→  (不传播这些字段)
    _build_effect_payload()             ──→  (不传播这些字段)
        ↓
    ActiveEffect dict                   ──→  字段缺失
        ↓
    get_effect_modifiers()              ←── CombatHandler:1058 已调用（但读到空值）
    get_disadvantage_checks()           ←── SkillCheckHandler:159 已调用（但读到空值）
```

**影响**：效果被"贴上"但行为字段为空，读取端永远返回空值。详见 P3-1-BuffDebuff管线闭合.md。

### 6.2 怪物战斗 AI 管线（修正：基础 AI 已实现）

> **2026-03-05 修正**：ai_personality/flee_threshold/resistances/immunities/vulnerabilities 已消费。怪物已有差异化行为。

```
MonsterTemplate.flee_chance      ──→  (未消费，逃跑是确定性的)
MonsterTemplate.spells           ──→  (未消费，需要怪物施法系统)
MonsterTemplate.tactics_notes    ──→  (未消费，LLM 领域)
MonsterTemplate.attacks[1:]      ──→  (未消费，仅使用第一个攻击)
```

**影响**：怪物有基础 AI（攻击/逃跑），但逃跑非概率化、不会选择多攻击、不会施法。详见 P3-2-怪物AI深化.md。

### 6.3 遭遇生成管线（修正：代码已完整，缺数据）

> **2026-03-05 修正**：EncounterHook + EncounterHandler + BasicEncounterDetector 已完整实现（D-O15）。encounter_table 已被消费。默认使用 NullEncounterDetector 是有意的控制性占位。

```

AreaTemplate.hostile_pool        ──→  (未消费)

        ↓
    EncounterHook 当前使用简化逻辑生成遭遇
```

**影响**：遭遇生成不考虑地形、时段、区域特色怪物池。
