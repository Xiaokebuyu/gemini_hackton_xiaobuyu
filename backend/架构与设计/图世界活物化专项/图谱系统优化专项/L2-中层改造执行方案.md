## 一、定位与范围

本文档是"接口服务层"改造的可执行方案。L3 完成后，底层已具备：
- WorldGraph 包含记忆节点类型 + 索引 + 查询方法
- SpreadingActivation 直接在 WorldGraph 上运行
- MemoryGraphizer 写入目标已从 GraphStore 切到 WorldGraph
- RecallOrchestrator 已简化为 WorldGraph 直接激活
- MemoryGraph 已删除

**L2 的工作是**：把中层的服务初始化、依赖注入、遗留代码、双轨路径全部对齐到新底层。

**不做什么**：
1. 不改变 ContextWindow 内部逻辑（图谱化触发阈值、消息选择策略不变）
2. 不改变 SessionRuntime 的 restore/persist 主流程结构（只清理内部冗余路径）

**权限职责声明**（对齐三层设计"中层负责权限"原则）：
- 记忆读写的**可见性过滤**在中层（SessionRuntime 门面方法）执行 — L1 新增的 `session.recall()` / `session.record_memory()` 包含角色权限校验
- 工具调用资格（哪个 role 能调用哪些 immersive tool）仍由上层 RoleRegistry 控制
- L2 阶段完成 graph_store 移除和 AgenticContext 改造；记忆门面的最终形态（含权限校验）在 L1 落地

        if cached:
            self.game_state = cached
            return

**建议**：先确认 `StateManager.get_state()` 是否已包含 Firestore 读取。如果是，则 SessionStore 回退确实冗余。如果不是，保留但添加 TODO 注释。
