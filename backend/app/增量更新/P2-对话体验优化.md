## 一、当前 LLM 对话实现全景

### 1.1 NPC 对话链路总览

```
玩家发消息 → POST .../interact/stream
    │
    ├─ AgentOrchestrationService.run_npc_interaction()
    │     │
    │     ├─ InstanceManager.get_or_create(npc_id) → ContextWindow
    │     │
    │     └─ NpcInteractionCoordinator.execute_interaction()  ← 6 步管线
    │           │
    │           ├─ Step 1: Setup
    │           │   ├─ consume_directive() ← 消费 NarrativePlanner 下发的指令
    │           │   ├─ build_npc_full_context() ← 一次性构建 system_prompt + 7 层上下文
    │           │   └─ player message → SceneBus
    │           │
    │           ├─ Step 2: NPC Agent
    │           │   └─ executor.run_agentic(role="npc", ...)
    │           │       ├─ system_prompt = _build_npc_prompt_text()
    │           │       ├─ context_layers → _serialize_context_layers() → L0/L2/L3/L5
    │           │       ├─ conversation_history = ContextWindow → _window_to_history()
    │           │       └─ tools = RoleToolRegistry.get_tools_for("npc", traits=npc_tags)
    │           │
    │           ├─ Step 3: GM Observation (默认 pass_turn)
    │           ├─ Step 4: Teammate Reactions (概率门控)
    │           ├─ Step 5: Dialogue Options (LLM 优先 + 静态 fallback)
    │           └─ Step 6: Return NpcInteractionResult
    │
    └─ SSE 推送: npc_speech → gm_narration → teammate_speech → dialogue_options
```

### 1.2 System Prompt 构建详情

`_build_npc_prompt_text()` (context_builder.py:832-923) 当前生成的 prompt 结构：

```
You are {name}, an NPC in a dark-fantasy CRPG world.

## Your character
{personality}
Traits: {tags}
[## Your dialogue style — dialogue_style]

## Current relationship with the player
- Relationship stage: {stage}
- Approval: {approval} / Trust: {trust} / Fear: {fear} / Romance: {romance}

## Your memories of the player
{impressions from RelationSlice}

[## Relevant world knowledge — L6 memory hits, cap=5]
[## [重要行为指令] — active_directive from NarrativePlanner]

## Tool usage rules
- speak / emote / update_feeling / remember / refuse / offer_quest / offer_trade / reveal_secret
- "You MUST respond when spoken to — do not use pass_turn."

## Language
Respond in the same language as the player's message.
```

### 1.3 CharacterTemplate 字段消费分析

| 字段 | 已消费 | 消费位置 | 设计要求 |
|------|--------|---------|---------|
| `name` | ✅ | system_prompt `You are {name}` | — |
| `personality` | ✅ | system_prompt `## Your character` | — |
| `dialogue_style` | ✅ | system_prompt `## Your dialogue style` | — |
| `speech_pattern` | ❌ **未消费** | — | 设计文档未单独要求，但数据中有丰富内容（如"请地母神赐予慈悲、那个...我明白了"） |
| `appearance` | ❌ **未消费** | 仅图片生成使用 | NPC 不知道自己长什么样不影响对话，但可用于 emote 描写参考 |
| `backstory` | ❌ **未消费** | — | 角色背景是对话质量的核心！NPC 需要知道自己的经历才能 in-character |
| `secrets` | ❌ **未消费** | — | 设计文档 §七.5 要求 trust 门槛解锁后注入私聊上下文 |
| `tags` | ✅ | system_prompt `Traits: {tags}` | — |
| `character_class` / `class_id` | ❌ **未消费** | — | 角色职业影响说话方式和知识范围 |
| `faction` / `faction_id` | ❌ **未消费** | — | 阵营归属影响立场和态度 |
| `base_disposition` | ✅ (间接) | 通过 RelationSlice 的初始值 | — |
| `schedule` | ❌ 对话中不需要 | 日程系统使用 | — |
| `stats` | ❌ 对话中不需要 | 战斗系统使用 | — |
| `skills` | ❌ 对话中不需要 | 战斗系统使用 | — |

**关键缺失**：`speech_pattern`、`backstory`、`secrets`、`character_class`、`faction` 这 5 个字段直接影响角色扮演质量，当前 prompt 完全未消费。

### 1.5 对话选项生成分析

**当前实现** (npc_interaction.py Step 5):

```python
# LLM 路径：GM 的 suggest_options 工具调用
if gm_result and tr.metadata.get("tool") == "suggest_options":
    _lm_options = tr.metadata.get("options")

# 静态 fallback
_build_static_dialogue_options() → ["继续交谈", "告别", 商店/任务按需]
```

**设计要求** (叙事层设计规范 §五):
- Agent 生成选项意图（含检定类型：persuasion/athletics/perception）
- ❷ 填充 DC + 成功率
- 玩家看到 `[说服 DC14] 让守卫通融` 格式

**Gap**:
- GM 的 suggest_options 输出格式支持 `check` 字段，但 ❷ 的 DC 填充未实现
- 静态 fallback 过于简单，没有上下文感知
- suggest_options 的触发频率取决于 GM prompt 中的指令（当前："Use `suggest_options` when the situation calls for a skill check"）

## 四、待优化项（按优先级排序）

### ✅ P2-A: NPC System Prompt 丰富化 (已完成)

**问题**：NPC 缺少 `backstory`、`speech_pattern`、`character_class`、`faction`、`secrets` 等关键字段，导致角色扮演浅薄。

**实现方案**：修改 `_build_npc_prompt_text()` (context_builder.py:832)

需要新增的 prompt 段：

```
## Your background
{backstory}

## Your speech pattern
{speech_pattern}（示例口癖和说话习惯，帮助保持角色一致性）

## Your identity
- Class: {character_class}
- Faction: {faction}
```

**secrets 注入**（按 trust 门槛过滤后注入）：

```
## Things you know but haven't told the player
- {secret_1}（当 trust 足够高且对话气氛合适时可自然提及）
```

**同步修改 Teammate prompt** (`_build_teammate_prompt_text()`)：补充相同字段。

**工作量**：~40 行修改，影响文件 1 个。

### ✅ P2-B: 关系阶段行为指引 (已完成)

**问题**：prompt 中有 stage/trust/romance 数值但缺乏「数值 → 行为」的映射指引，LLM 不知道该怎么调整语气。

**实现方案**：在 system prompt 中根据 stage 注入对应的行为指引段落：

```python
STAGE_BEHAVIOR_GUIDES = {
    "stranger": "你不认识这个人。保持礼貌但有距离感。",
    "acquaintance": "你认得这个人。可以随意一些但不深入个人话题。",
    "friend": "你把对方当朋友。可以放松、分享想法、偶尔开玩笑。",
    "close_friend": "你深信对方。可以坦诚、脆弱、不再逞强。",
    "soul_mate": "你和对方有无保留的信任。",
    # 负面
    "cold": "你对这个人没什么好感。敷衍、简短。",
    "hostile": "你不喜欢这个人。讽刺、拒绝深入交谈。",
    "enemy": "你视这个人为敌。威胁、警告。",
}
```

**trust 行为指引**（根据数值区间注入）：

```python
def _trust_behavior_hint(trust: int) -> str:
    if trust < -30: return "你对此人高度戒备，不会分享任何个人信息。"
    if trust < 0: return "你对此人有些提防，只聊表面话题。"
    if trust < 30: return "你对此人态度中性，可以聊日常但不涉及私事。"
    if trust < 60: return "你信任此人，可以分享一些想法和经历。"
    return "你非常信任此人，可以吐露心声甚至秘密。"
```

**romance 行为指引**（类似映射）。

**工作量**：~60 行新代码，影响文件 1 个。

### ✅ P2-C: L0 Lore 信息完整化 (已完成)

**问题**：`_serialize_context_layers()` 对 L0 lore 只提取 name 不提取 description，NPC 知道世界里有个势力叫"地母神教会"但不知道它是干什么的。

**实现方案**：修改 `_serialize_context_layers()` (executor.py:288-308)

```python
# Before: lines.append(f"  - {name}")
# After:
desc = getattr(item, "description", None) or (item.get("description") if isinstance(item, dict) else None)
line = f"  - {name}: {desc}" if desc else f"  - {name}"
lines.append(line)
```

cap 从 5 调低到 3（加了 description 后 token 增多）。

**工作量**：~10 行修改。

### ✅ P2-D: 时间感知注入 (已完成)

**问题**：NPC 不知道当前是白天还是夜晚。一个酒馆老板在凌晨三点跟你打招呼的方式应该和下午不同。

**实现方案**：在 `_build_l4_npc()` 或 `_serialize_context_layers()` 中注入 TimeSlice 的 slot 信息。

```python
# 在 L4 或 system prompt 中添加
time_snapshot = self._state.time.snapshot()
period = time_snapshot.get("slot", "")  # "dawn"/"day"/"dusk"/"night"
day = time_snapshot.get("day", 1)
# → "Current time: Day 3, dusk"
```

**工作量**：~15 行。

### ✅ P2-E: Teammate 场景修正 (已完成)

**问题**：`_should_teammate_respond()` 只有基础 `response_tendency`，缺少设计文档要求的场景修正（COMBAT_END +0.3, CRISIS +0.4, TRIVIAL -0.2）和频率抑制。

**实现方案**：扩展 `_should_teammate_respond()` 读取 SceneBus entries 的 tags 做修正。

**工作量**：~30 行。

### ⚠️ P2-F: 对话选项 DC 填充 (未做，延后)

**问题**：suggest_options 生成的含检定选项（如 `check: {skill: "persuasion"}`）没有经过 ❷ 填充 DC。

**依赖**：需要 RulesEngine 支持「给定 skill + 场景参数 → 计算 DC」的查询接口。当前 ❷ 只有 execute 模式，没有纯查询模式。

**实现方案**：
1. RulesEngine 新增 `estimate_dc(skill, context)` 查询方法
2. npc_interaction Step 5 对含 check 的选项调用 DC 计算
3. 前端展示 `[说服 DC14]` 格式

**工作量**：较大，可后置。

### ⚠️ P2-G: 角色硬隔离 (未做，延后)

**现状**：AgentContext 携带完整 world + RoleStateProxy（软约束）。设计要求 Agent 工具访问应受角色级限制。

**实际影响**：当前软约束实际够用，NPC 工具只会访问 scene/relations/player 等已允许的 slice。

**可后置**。
