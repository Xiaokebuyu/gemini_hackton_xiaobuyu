# 里程碑剧本驱动与 Clue 简化 — 设计思路

记录日期：2026-03-16
状态：设计思路阶段，未进入实施

---

## 设计基调

- **题材**：边境小镇历练成长（日常向，不以战斗为核心事件）
- **氛围**：温馨日常为主基调，穿插成长与羁绊
- **NPC 交互**：所有 NPC 都可以深入交流，所有女性角色均可攻略
- **叙事结构**：事件是骨架，日常是血肉——事件和日常交织在同一个剧本中，不分离
- **任务驱动一切**：任务是玩家行动的唯一明确指引。日常/恋爱内容在完成任务的过程中自然发生，不作为独立节拍。任务把玩家带到正确的地点和人面前，NPC 行为指导让对话有温度
- **剧本节拍**：每幕以任务为中心驱动（例：create_quest 帮牧牛妹修围栏 → 玩家前往牧场 → 边干活边聊天 → 发现线索 → 回城汇报）
- **时间稀缺制造选择**：同一时间段多个 NPC 邀约只能选一个（傍晚限定任务竞争），选择本身推进关系线
- **关系解锁世界内容**：NPC 关系达到阈值时解锁新地点/内容（铁匠混熟→私人工坊、牧牛妹亲近→秘密花田、老板娘交心→地窖传闻）
- **行为回响**：帮了某人 → 其他 NPC 有反应（guild_girl 提到牧场的事、老板娘打趣昨晚加班），剧本中显式设计回响链

### 世界体验增强

以下机制均可在现有系统上实现，不需要新子系统。

**优先实现（1-3）：**

1. **天气系统**：Planner 通过 set_flag("weather", "rain/sunny/cloudy/snow") 设置天气 → GM 叙述引用 → NPC 对话自然提及 → 天气影响任务契机（雨天 → 牧牛妹担心牛棚 → 任务）。零新代码，纯 flag + prompt。

2. **玩家的家**：公会宿舍或旅馆长租房，作为日常锚点。早上出发（GM 描写晨光）、晚上回家休息、NPC 可能来访（cow_girl 送便当、guild_girl 送文件）。用 fill_room 创建，Planner 剧本中把"家"作为固定场景。

3. **NPC 间可见互动**：玩家进入场景时看到 NPC 在做自己的事（矮人和蜥蜴争论乳酪、guild_girl 安慰失败的冒险者）。通过 area_events / SceneBus 展示，Planner 按剧本安排"背景小剧场"。

**后续扩展（4-5）：**

4. **小镇口碑**：reputation_level flag，NPC 称呼和态度随口碑变化（"新来的" → 称呼名字 → 主动打招呼 → 给折扣）。Planner 按口碑等级调整 NPC 指导。

5. **季节/时间流逝感**：按 day 范围标注季节氛围（初秋→收获季→入冬预兆），GM 叙述 + NPC 话题跟随。

### 检定效果梯度系统

**核心理念：检定不决定"能不能"，而是调节"好不好"。** 玩家总能完成任务，检定只影响完成的品质。

效果等级（基于 margin = total - DC）：
- `excellent`（margin ≥ +5）：额外奖励（更多物品、更高好感、额外信息）
- `good`（margin ≥ 0）：标准奖励
- `poor`（margin ≥ -5）：减少奖励，但不惩罚
- `bad`（margin < -5）：最小收益 + 轻微不利（叙事性的，如手被刺伤）

GM 根据等级叙述过程，NPC 根据等级调整反应。bad 结果也可能触发正面关系事件（NPC 关心受伤的玩家）。

### 好感度系统重设计

**核心理念：NPC 有明确喜好标准，好感变化有据可依。**

**角色喜好维度**（内容层手写，不可 LLM 生成）：
- `values`：核心价值观（如 责任感/温暖/信仰/自由）
- `likes`：喜欢的玩家行为（如 认真完成委托/关心他人/喜欢动物）
- `dislikes`：反感的玩家行为（如 鲁莽/说谎/看不起乡下）
- `romance_triggers`：恋爱加分行为（如 下班后的关心/一起看夕阳/夸她做的饭）
- `turn_offs`：恋爱减分行为（如 在公会大吵大闹/嫌牧场脏）

**好感变化有界限**（NPC prompt 注入）：
- 单次交互 delta 上限：approval [-3,+3], trust [-2,+2], romance [-1,+2]
- NPC 根据 values/likes/dislikes 评估玩家行为决定 delta

**阶段跃迁 = 数值 + 关键事件双重门槛**：
- stranger → acquaintance：approval ≥ 10
- acquaintance → friend：approval ≥ 25 + trust ≥ 15 + 完成过一个和该 NPC 相关的任务
- friend → close_friend：trust ≥ 50 + 经历过一次 Planner 编排的"关键事件"
- close_friend → intimate：trust ≥ 70 + romance ≥ 40 + 完成该 NPC 的个人故事线

### 队伍 = 临时同行

队伍系统作为"邀请 NPC 同行"的工具，而非永久冒险小队：
- 玩家对话中邀请 → NPC 根据关系 + 当前状态决定是否加入
- 关系不够 → 拒绝；关系够 + 有空 → 加入
- 同行中：NPC 对场景反应（teammate_response）、多人闲聊、共同完成任务 → 关系加深
- 任务完成 → NPC 自动离队，Planner 通过 modify_location 放回原位
- **关系门槛决定谁愿意同行** — 自然地让"和谁出门"成为关系进度的体现

### HP 在日常中的意义

轻微 HP 变化让角色感觉"有身体"：
- 日常事件扣 HP（采药被刺 -2、淋雨 -3）— 叙事性，不危险
- 吃食物回 HP（给食物物品机械意义）
- 休息回满（已有）
- HP 让食物和休息有存在感，而非纯粹推进时间的按钮

### 角色成长

- **等级上限**：当前先开放 5 级
- **属性点分配**：初始点数偏少（抠搜），防止升级数值膨胀
- **升级奖励**：每次升级给属性点，玩家自选分配到哪个属性（STR/DEX/CON/INT/WIS/CHA）
- **成长意义**：更高属性 → 更好的日常检定结果（梯度系统下 margin 更大 → 更好的收益等级）
- **NPC 见证成长**：升级不只是数字。Planner 按等级在剧本中安排庆祝节拍：
  - Lv2：guild_girl 说"你进步很快"
  - Lv3：公会举办小型升阶仪式
  - Lv5：铁匠终于愿意给你看他的私藏

### 场景呈现

- **GM 动态场景描写**：玩家进入地点时，GM 不只列出"谁在这里"，而是读取 NPC 当前状态（blackboard.mood/attitude/goals）+ 玩家状态 + 时间段，生成带氛围的场景描写
  - 例：早上进公会 → "晨光透过窗户洒在柜台上，guild_girl 正低头整理一摞文件，眉间微蹙——似乎今天的委托比往常多。"
  - 例：傍晚进酒馆 → "酒馆里已经坐满了回城的冒险者，tavern_keeper 一边擦杯子一边和常客聊天，看到你进门点了点头。"
- **NPC 实时状态融入**：不是"NPC 在这里"而是"NPC 正在做什么 + 什么心情"
- **时间段差异**：同一地点不同时间呈现不同氛围
- **场景记忆**：GM 区分首次/回访。第一次去酒馆详细介绍环境；之后："推开熟悉的木门，走向老位置"+ 只描写今天的不同。通过 flags["visited_xxx"] 区分
- **情绪染色**：GM 读取最近的关系变化/事件，染色场景描写。美好互动后："脚步似乎比来时轻快了一些"；不好的事后："镇广场和平时一样热闹，但你有点心不在焉"

### 开场序列

- **角色创建**：保持当前系统不变（选职业/分配属性）
- **来镇理由选择**：让玩家选一个"为什么来边境小镇"（寻求冒险/逃离过去/追随某人/寻找亲人），影响 NPC 初始反应 + 给 Planner 剧本素材
- **剧本生成等待**：前端显示"正在准备中，请稍等"
- **流程**：角色创建 + 来镇理由 → LLM 生成第一份剧本 → 存入 NarrativePlanSlice → 执行第一幕首批节拍 → 玩家进入游戏

### 玩家交互增强

- **送礼机制**：不做新按钮。物品加 `giftable` tag + 描述提示，GM 适时提示可送礼，NPC 通过新增 `ReceiveGiftTool` 从玩家 inventory 取物品 + 好感变化
- **GM 叙述风格**：每个 settlement 都出氛围描写，从冒险转为日常生活风格（晨光、饭香、市集声、夜晚宁静）。Prompt 层改动
- **物品中文化**：items.json 全部英文需要中文化 + 补充日常物品（食物/礼物/日用品）
- **物品变关系信物**：某些物品带 sentimental metadata（`{from: "cow_girl", event: "修围栏那天"}`），之后拿给 NPC 看会触发特殊反应
- **合作制作物品**：和 NPC 一起做事产出独特物品（老板娘特制炖菜、铁匠定制小饰品），买不到只能通过任务获得，适合送礼

### 社交与经济增强

**优先实现：**

5. **NPC 之间的关系网**（数据补充）：在 character 数据中补充 NPC 相互关系描述（guild_girl 担心 goblin_slayer、cow_girl 是他青梅竹马、tavern_keeper 知道所有人八卦）。这些关系网是日常叙事的燃料，影响 Planner 剧本编写和 NPC 对话内容。

6. **角色模板深度**（数据补充）：当前 personality 50-100 字不够支撑长期日常互动。补充：口头禅、爱好、厌恶、日常习惯、童年故事素材、秘密（配合已有的 RevealSecretTool，关系达标后解锁）。

7. **玩家日志**（自动汇编）：从 area_events + quest_history + story_facts 自动生成"冒险日志"，让玩家回顾关键事件、对话、发现。长线日常剧情中的体验保障。

8. **关键记忆钉住**：blackboard.observations cap=10 会挤掉重要记忆。新增 `pinned_memories` 字段（不参与轮换），存放关键互动（第一次一起看日落、第一次私聊等）。

**优先实现（续）：**

9. **NPC 主动送礼**：NPC 关系到一定程度会主动给玩家东西（cow_girl 放一篮鸡蛋在门口、guild_girl 留整理好的资料、tavern_keeper 请一杯）。Planner 按关系阶段在剧本中安排，通过 direct_npc + assign_service(price=0) 或 grant_item 实现。

10. **NPC 礼物偏好**：角色数据加 `gift_preferences`（loves/likes/neutral/dislikes 分类），物品加 `gift_category` tag。送对了好感翻倍，送错了反而减分。让送礼变成需要了解 NPC 的小博弈。

11. **NPC 情绪波动**：NPC 有和玩家无关的情绪变化（下雨天 guild_girl 低落、行商来了 tavern_keeper 高兴、NPC 生日心情好）。Planner 通过 blackboard.mood 设置，玩家察觉后关心 → 关系加深。

12. **恋爱竞争感**：利用已有的角色关系网（goblin_slayer ↔ guild_girl / cow_girl）制造动态张力。玩家和某个 NPC 走近时其他相关 NPC 有反应。通过 Planner 剧本的 ripple 机制实现。

**后续扩展：**

- **共食社交**：在酒馆共同消费（买两份饭一起吃），花钱 → 好感 + 共同记忆。本质是特殊 service（price=饭钱，effect=双人好感）
- **帮工赚钱**：酒馆帮忙端盘、铁匠帮忙打铁。Planner 生成日常小任务，少量金币 + 关系建设
- **NPC 购物行为可见**：玩家在市集看到 cow_girl 买缎带，制造悬念。W3（NPC 可见互动）的延伸

## 核心理念

**Planner 是导演，里程碑是一部隐藏剧本，玩家和 NPC 是不知道剧本但能演绎剧情的演员。**

当前系统的问题：里程碑只是一个"完成条件清单"，Planner 像一个任务分发机器。缺少的是**故事性**——一个有起承转合、有悬念和节奏的完整叙事弧。

## 一、里程碑剧本系统

### 1.1 剧本是什么

每个里程碑激活时，LLM 一次性生成一份**完整的故事剧本**（约 8000 字），包含：

- **初期**：事件发生，线索浮现，玩家被卷入
- **中期**：调查深入，真相逐步展开，出现转折和抉择
- **末期**：矛盾激化，最终对决/解决，故事收束

剧本像一部线性游戏的剧情脚本，但不是让玩家直接阅读，而是由 Planner 将其**拆解为任务、线索、NPC 对话、地点布置**逐步呈现给玩家。

### 1.2 剧本对谁可见

| 角色 | 能否看到剧本 |
|------|------------|
| Planner | 完整可见 — 每轮决策时参考剧本 |
| GM 叙述者 | 不可见 — 只看到 Planner 给它的当前场景指示 |
| NPC | 不可见 — 只通过 directive/blackboard 获得行为指引 |
| 队友 | 不可见 — 和玩家一样是"演员" |
| 玩家 | 不可见 — 只通过任务、线索、对话体验剧情 |

### 1.3 Planner 如何使用剧本

Planner 每轮运行时：

1. 读取当前剧本 + 当前进度标记（"现在在第几幕"）
2. 观察玩家最近的行为（去了哪里、和谁聊了、完成了什么）
3. 参考剧本决定"下一步应该让玩家体验什么"
4. 输出 directives：
   - 发布/更新任务（引导玩家行动）
   - 布置地点和线索（创造探索内容）
   - 指挥 NPC（让 NPC 自然地透露信息、推动剧情）
   - 更新进度标记

关键：Planner 不是机械地执行剧本，而是**根据玩家实际行为灵活调整节奏**。玩家跑偏了就通过 NPC 提醒引导回来，玩家推进很快就跳过铺垫直接进入高潮。

### 1.4 剧本的生命周期

```
里程碑切换 → 生成剧本（LLM 一次性，~8000字）
  → 存入 NarrativePlanSlice（随 state 持久化）
  → Planner 每轮参考剧本决策
  → 玩家逐步体验剧情
  → 剧本走完 → 里程碑完成
  → 切换到下一个里程碑 → 生成新剧本
  → 旧剧本归档（可保留摘要供后续引用）
```

### 1.5 剧本应包含的内容

剧本不只是"故事文本"，还应包含 Planner 可以直接操作的结构化信息：

- **场景列表**：这个故事涉及哪些地点（已有的 + 需要新建的）
- **关键 NPC**：哪些 NPC 在故事中扮演什么角色、各阶段应有什么表现
- **线索链**：玩家需要发现的线索序列，每个线索指向什么
- **任务分解**：故事自然拆成哪些子任务、每个任务的完成条件
- **转折点**：哪些节点需要根据玩家选择分叉（有限分叉，不是无限开放）
- **氛围指示**：每个阶段的情绪基调（紧张、轻松、压抑、高昂）

这样 Planner 每轮不需要"创造性地想下一步做什么"，而是"对照剧本，根据当前进度选择执行哪一段"。

## 二、Clue 简化

### 2.1 当前问题

当前 clue 是一个复杂的"小游戏"：
- 强制 2~4 个选项（options），每个选项可带独立 skill check
- 每个选项有独立的 outcomes 树（always/on_pass/on_fail 三分支）
- LLM 很难正确生成这个复杂结构 → 大量 clue 被系统校验拒绝
- 即使通过校验，默认 outcomes 为空 → 玩家调查后什么都不发生

### 2.2 新模型：场景调查点

Clue 回归经典 CRPG 的场景调查点：

```
玩家看到"可疑的药草丛" → 点击调查 →
  1. 基础效果（必定触发）：获得 3 株普通药草
  2. [可选] 技能检定（自然知识 DC12）→ 成功：额外获得 1 株稀有药草
  3. 信息注入：调查内容进入队伍上下文 → 队友/NPC 自然讨论
```

### 2.3 Clue 的核心结构

简化后的 clue 只有三个层次：

**必定效果（base_effects）**
- 玩家点击调查就会获得的东西
- 如：获得物品、设置 flag、解锁地点、推进任务
- 这是 clue 作为"任务完成条件发放器"的核心

**检定效果（check_effects）**
- 可选。附带一个 skill check
- 成功时获得额外收益（更多物品、额外信息、更好的结果）
- 失败不会阻止基础效果，只是错过额外收益

**叙事信息（narrative）**
- clue 携带的故事信息（描述文本、发现的线索内容）
- 调查后自动注入当前场景上下文
- 同 room 的队友/NPC 会在后续对话中引用这些信息
- 这是 clue 服务于"剧本叙事"的核心

### 2.4 Clue 的使用场景

**作为任务条件发放器：**
- 接了"收集药草"任务 → Planner 在野外布置"药草丛" clue
- 玩家调查 → 获得药草（base_effects: grant_item）
- 任务 objective 的 condition 用 `item_obtained` 检测

**作为剧情推进器：**
- 剧本需要玩家发现"哥布林的踪迹" → Planner 在森林小径放置 clue
- 玩家调查 → set_flag("goblin_tracks_found") + 解锁新地点
- 信息注入上下文 → 队友讨论"这些足迹很新，它们就在附近"
- Planner 下轮看到 flag → 推进到剧本下一幕

**作为探索奖励：**
- 玩家进入新区域 → Planner 布置几个 clue 增加探索感
- 调查 → 获得少量金币/经验/物品 + 世界知识
- 检定成功 → 额外奖励

### 2.5 与里程碑剧本的配合

```
剧本第一幕："北门守卫报告夜间有可疑活动"
  ↓
Planner 执行：
  - direct_npc: 让守卫找玩家谈话，透露线索
  - create_quest: "调查北门外的可疑活动"
  - fill_location: 在北门外放置 clue（可疑脚印）
      base_effects: set_flag("found_goblin_tracks")
      narrative: "泥地上的爪印三趾分叉，间距说明是小型类人生物——哥布林。"
  ↓
玩家调查脚印 → flag 设置 → 队友讨论 → Planner 看到进度
  ↓
剧本第二幕："追踪发现哥布林营地入口"
  ↓
Planner 执行：
  - fill_area: 创建"密林深处"子地点（locked=true）
  - fill_location: 在当前位置放置新 clue（折断的树枝）
      base_effects: unlock_sub_location("dense_forest")
      check: {skill: "survival", dc: 14}
      check_effects: grant_item("goblin_map_fragment")
      narrative: "顺着痕迹能找到它们的巢穴方向。"
  ↓
...逐步推进直到剧本末期的最终对决
```

## 三、子地点生成服务于叙事

### 3.1 当前能力

Planner 已有完整的子地点生成能力：
- `fill_area`：创建可进入的新子区域（可 locked）
- `fill_room`：在已有 sub_location 中新增房间
- `fill_location`：在已有位置放置 interactable（含 clue）
- `plant_encounter`：种植战斗遭遇
- `discover_room`：解锁隐藏房间

### 3.2 服务于剧本的用法

一个里程碑剧本可能需要 Planner 创建一个**包含多个 room 的完整地下城**：

```
剧本："哥布林巢穴"（里程碑 ms_goblin_nest）

Planner 逐步布置：
  第一幕：fill_area("goblin_cave_entrance", locked=true) — 洞穴入口
  第二幕：
    - fill_room("goblin_cave_entrance", "guard_post") — 守卫哨
    - plant_encounter(guard_post, ["goblin", "goblin"]) — 门卫遭遇
    - fill_location(guard_post, clue:"粗糙的地图") — 发现内部地图
  第三幕：
    - fill_room("goblin_cave_entrance", "prison") — 牢房
    - fill_location(prison, clue:"被关押的旅人") — 救人 + 获得情报
    - fill_room("goblin_cave_entrance", "throne_room") — Boss 房
    - plant_encounter(throne_room, ["hobgoblin_chief"]) — 最终战
```

每一步不是一次性全部创建，而是**随剧本推进逐步展开**——玩家打完守卫才发现内部地图，看了地图才知道有牢房和王座室。

### 3.3 关键原则

- **按需生成，不一次铺开**：剧本虽然预先写好，但地点/clue/遭遇随玩家进度逐步布置
- **保持悬念**：玩家不知道后面还有什么，每次探索都有新发现
- **复用已有地点**：不是每个剧本都建新城，优先在已有地点中添加内容
- **容量控制**：现有的容量限制（sub_area 15 个上限、overlay 4 个上限）确保不会过度堆积

## 五、与当前系统的关系

### 保留

- 23 种 directive 全链路（已完善，不需要改）
- 任务完成追踪三层机制（QuestObjectiveTrackingHook + TaskMonitorHook + 确定性预处理）
- 子地点生成能力（fill_area / fill_room / fill_location / plant_encounter）
- NPC directive 系统（direct_npc + blackboard + pending_topic）
- 11 种任务完成条件类型

### 改造

- **Clue**：从"复杂选项树"简化为"基础效果 + 可选检定 + 叙事信息"
- **milestone_outline**：从简单 steps 列表升级为完整剧本存储
- **Planner prompt**：从"每轮自由决策"改为"参照剧本、按进度执行"
- **剧本生成**：新增里程碑激活时的 LLM 剧本生成流程

### 新增

- 剧本生成器（里程碑激活 → LLM 生成 ~8000 字剧本）
- 剧本进度追踪（Planner 读写"当前在第几幕"）
- Clue 叙事信息注入（调查后内容进入队伍上下文）
